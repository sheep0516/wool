# 项目一-企业知识库问答系统

本节给出企业知识库问答的最小可交付版本：范围、链路、关键决策、评估与成本。目标是用一个项目把第4章的链路与第8章的评估跑通。

## 1.1 范围定义

不要一开始做“全公司知识库”。选定一个部门、一类制度，文档量控制在 20 至 50 篇。

| 项目要素 | 建议 |
|---|---|
| 覆盖范围 | 一个部门的制度与操作手册 |
| 文档量 | 20 至 50 篇，含表格与附件 |
| 用户 | 该部门员工，20 至 50 人 |
| 问题类型 | 规定查询、流程说明、材料要求 |
| 明确不做 | 跨部门综合判断、需要实时数据的查询 |

范围收窄不是降低难度，而是让评估可控。文档量过大时，问题会同时来自解析、分块、检索与权限，无法定位。

## 1.2 链路设计

```
文档上传
  ↓
解析（含 OCR）→ 清洗 → 分块（按章节，保留标题路径）
  ↓
元数据标注（部门、密级、生效时间、版本）
  ↓
向量化 → 入库
  ↓
用户提问 → 查询改写 → 混合检索（向量 + 关键词）
  ↓
权限过滤 → 重排 → 选取 3 至 5 条 → 注入
  ↓
生成（强制引用，无依据则拒答）
  ↓
引用校验 → 输出
```

每一段的输入输出应有约定。例如检索节点输出片段列表与得分，生成节点输入固定字段而不是自由文本。

## 1.3 关键决策

| 决策点 | 选项 | 建议与理由 |
|---|---|---|
| 分块方式 | 固定长度 / 按章节 | 制度类按章节或条款切分，保留标题路径 |
| 检索方式 | 纯向量 / 混合 | 混合检索，编号与条款号依赖关键词 |
| 是否重排 | 有 / 无 | 先做无重排版本，评估后再加，用数据验证收益 |
| 权限粒度 | 文档级 / 段落级 | 起步用文档级，敏感条款再做段落级 |
| 拒答策略 | 允许模型自主回答 / 强制拒答 | 强制拒答，检索为空或低分时不生成 |
| 引用粒度 | 文档 / 段落 / 条款 | 条款级，制度类文档必须精确到条 |

一个必须提前定的判断：是否允许模型在检索为空时使用自身知识。知识库问答场景应明确不允许，否则会掩盖知识缺口，让评估失真。

## 1.4 评估方案

| 项目 | 要求 |
|---|---|
| 评估集规模 | 100 条起步，覆盖常见问法、边界问法、应拒答问题、版本冲突问题 |
| 检索指标 | 命中率（正确片段是否出现在前若干条）、平均排名 |
| 生成指标 | 忠实度、完整性、引用准确率 |
| 拒答指标 | 应拒答样本的拒答率、正常样本的误拒率 |
| 阈值示例 | 检索命中率不低于 80%，引用准确率不低于 90%，误拒率不高于 10% |
| 复测时机 | 每次分块、检索、提示词变更前 |

阈值应按业务风险调整，这里给的是可用的起点，不是标准答案。

## 1.5 成本测算

先算单次问答成本，再乘以日均请求量。

| 变量 | 取值方式 |
|---|---|
| 系统提示词 | 固定长度，实测 Token |
| 历史 | 建议限制在两到三轮 |
| 检索片段 | 条数 × 平均片段长度 |
| 输出 | 实测平均长度 |
| 日均请求 | 按用户数与人均次数估算 |

成本控制的三个优先动作：限制检索条数、压缩片段长度、对高频问题做缓存。知识库问答的问题重复率通常较高，缓存收益明显。

## 1.6 上线与兜底

| 失败 | 处理 |
|---|---|
| 检索为空 | 说明未找到，给出相近条目或转人工 |
| 得分低于阈值 | 给候选条款并提示核实 |
| 引用不匹配 | 重新生成一次，仍失败则标注不确定 |
| 权限不足 | 明确说明无权限，不展示片段内容 |
| 版本冲突 | 并列展示并标注生效时间 |

上线采用小范围试用，先给部门内十人使用两周，观察误拒率与转人工量，再扩大。

## 1.7 交付物清单

| 交付物 | 内容 |
|---|---|
| PRD | 范围、能力边界、权限设计、验收标准 |
| 知识库方案 | 文档清单、分块策略、元数据字段、更新流程 |
| 评估报告 | 评估集构成、各项指标、失败样本分析 |
| 成本测算表 | 单次成本、月度预算、优化措施 |
| 复盘记录 | 关键决策、遇到的问题、改进方向 |

## 1.8 常见失败

| 失败 | 原因 | 改进 |
|---|---|---|
| 离线指标好，线上差评多 | 评估集问题太规整 | 用真实提问补充样本 |
| 回答总是“未找到” | 分块切断或检索过严 | 检查分块与过滤条件 |
| 答案正确但引用错 | 未强制逐段引用 | 提示层强制编号，输出层校验 |
| 越权泄露 | 权限只做在展示层 | 检索后按片段元数据过滤 |
| 制度更新后答旧版 | 未按生效时间过滤 | 元数据加版本与生效时间 |

## 1.9 自检清单

1. 文档解析后的文本是否抽查过，表格是否完整。
2. 分块是否保留标题路径，条款号是否可定位。
3. 权限过滤是否发生在注入之前。
4. 评估集是否包含应拒答与版本冲突样本。
5. 单次成本与月度预算是否已测算。
6. 每条失败是否有明确去向。

## 1.10 小结

- 项目范围应收窄到一个部门、一类制度、20 至 50 篇文档，便于定位问题。
- 链路的关键在解析、分块、混合检索、权限过滤与强制引用五处。
- 评估需同时看检索与生成，并单独统计误拒率。
- 成本控制优先做检索条数限制、片段压缩与高频缓存。
- 交付物应包含 PRD、知识库方案、评估报告、成本测算与复盘。
