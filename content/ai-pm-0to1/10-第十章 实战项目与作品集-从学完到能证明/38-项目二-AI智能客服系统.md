# 项目二-AI 智能客服系统

本项目的目标不是让机器人陪聊，而是把服务流程走完。评估重点在意图识别、转人工与质检。

## 2.1 范围定义

| 项目要素 | 建议 |
|---|---|
| 覆盖场景 | 售前咨询、订单查询、退换货、投诉受理 |
| 意图数量 | 8 至 12 类，含兜底类 |
| 渠道 | 单一渠道起步，避免多渠道同时改造 |
| 明确不做 | 复杂纠纷裁决、赔付审批、跨系统权限操作 |

## 2.2 意图体系

意图体系决定系统的上限。四条设计规则：

1. 互斥且完备，必须包含“其他”与“无法判断”。
2. 区分“咨询”与“办理”：咨询只需要答案，办理需要参数与系统操作。
3. 投诉类单独成类，直接进入人工队列。
4. 标注边界样例，尤其是相邻意图的区分。

| 意图 | 处理方式 | 是否需要参数 |
|---|---|---|
| 售前咨询 | 知识库问答 | 否 |
| 订单查询 | 工具调用 | 订单号或手机号 |
| 退换货办理 | 流程加工具 | 订单号、原因、凭证 |
| 投诉 | 转人工 | 否 |
| 其他 | 兜底，询问或转人工 | 视情况 |

## 2.3 服务流程

```
用户输入
  ↓
意图识别（低置信则给出候选或转人工）
  ↓
参数收集（一次只问一个缺失项）
  ↓
权限校验（是否本人订单）
  ↓
系统查询（订单、物流、退款）
  ↓
规则判定（是否符合退换条件）
  ↓
答复生成（事实附来源，承诺需校验）
  ↓
质检抽样 / 转人工
```

关键设计：答复中的承诺类内容（退款时效、补偿方案）必须来自规则或人工，不能由模型自由生成。

## 2.4 转人工条件

转人工条件应写死，由程序判断：

1. 用户明确要求。
2. 连续两轮未解决或意图仍无法判断。
3. 投诉、纠纷、赔付类。
4. 涉及权限外操作或敏感信息。
5. 情绪指标超过阈值。

转接时必须携带上下文：用户身份、意图、已收集参数、已查询结果、未解决原因。缺少这些信息，用户需要重复描述，体验比纯人工更差。

## 2.5 质检方案

| 质检项 | 内容 | 方式 |
|---|---|---|
| 事实准确性 | 答复与政策、系统数据是否一致 | 抽样人工核对 |
| 承诺合规性 | 是否给出超权限承诺 | 规则加人工 |
| 转接合理性 | 是否该转未转或误转 | 抽样与指标监控 |
| 话术规范 | 是否存在不当表达 | 规则检测加抽样 |
| 隐私保护 | 是否泄露他人信息 | 规则检测 |

质检比例不必很高，但必须固定频率并覆盖新出现的意图与新版本。质检发现的失败样本应补入评估集。

## 2.6 指标设计

| 类别 | 指标 |
|---|---|
| 效率 | 首次响应时长、平均处理时长、并发承载 |
| 解决 | 一次解决率、返工率、工单关闭率 |
| 转接 | 转人工率、误转率、漏转率、转接信息完整度 |
| 体验 | 满意度、差评率、投诉率 |
| 合规 | 承诺违规率、隐私泄露事件数 |

需要避免的三个口径错误：

1. 用“未转人工”当解决率。
2. 只统计会话内指标，不跟踪工单最终状态。
3. 满意度只在会话结束时询问，忽略后续回访。

## 2.7 评估与成本

| 项目 | 做法 |
|---|---|
| 评估集 | 按意图分层，每类若干条，含边界与对抗样本 |
| 核心指标 | 意图识别准确率、参数抽取准确率、答复忠实度、误转率 |
| 成本 | 单会话 Token、平均轮次、工具调用次数 |
| 优化 | 简单意图用小模型、参数收集减少轮次、高频答复缓存 |

成本放大的主要来源是轮次与工具调用，而不是生成本身。控制轮次比压缩提示词更有效。

## 2.8 交付物清单

| 交付物 | 内容 |
|---|---|
| PRD | 意图清单、流程、转人工规则、验收标准 |
| 意图与参数规范 | 每个意图的定义、边界样例、所需参数 |
| 评估报告 | 分层指标、误转分析、失败样本 |
| 质检方案 | 检查项、抽样比例、处理流程 |
| 指标看板设计 | 五类指标的字段与口径 |
| 成本测算 | 单会话成本与优化措施 |

## 2.9 常见失败

| 失败 | 原因 | 改进 |
|---|---|---|
| 用户重复描述 | 转接未携带上下文 | 转接时传完整状态 |
| 错误承诺 | 承诺类内容由模型生成 | 改为规则或人工确认 |
| 硬扛不转 | 考核口径以转人工率为主 | 改为解决率与满意度考核 |
| 意图边界混淆 | 标签粒度不一致 | 重设标签并补边界样例 |
| 成本超预算 | 轮次过多、工具重复调用 | 限制轮次与调用次数 |

## 2.10 自检清单

1. 意图体系是否互斥完备，是否有兜底类。
2. 转人工条件是否写死并可被程序判断。
3. 转接是否携带完整上下文。
4. 承诺类内容是否全部经过规则校验。
5. 解决率口径是否基于工单最终状态。
6. 质检是否覆盖新意图与新版本。

## 2.11 小结

- 智能客服的目标是走完服务流程，意图体系与转人工规则决定上限。
- 转人工条件必须写死，转接必须携带完整上下文。
- 承诺类内容不能由模型自由生成，需规则或人工确认。
- 指标要区分效率、解决、转接、体验与合规，解决率不能用未转人工替代。
- 成本主要来自轮次与工具调用，控制轮次比压缩提示词更有效。
