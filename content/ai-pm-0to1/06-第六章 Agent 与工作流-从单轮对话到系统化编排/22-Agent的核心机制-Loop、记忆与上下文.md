# Agent 的核心机制-Loop、记忆与上下文

本节说明 Agent 与工作流的本质区别、循环结构、记忆分层，以及上下文膨胀的处理方式。

## 2.1 Agent 与工作流的区别

区别不在于是否用工具，而在于谁决定下一步。

| 维度 | 工作流 | Agent |
|---|---|---|
| 路径由谁决定 | 开发者预先编排 | 模型在运行时决定 |
| 步骤数量 | 固定 | 动态，取决于情况 |
| 可预测性 | 高 | 低 |
| 调试难度 | 中 | 高 |
| 适用场景 | 步骤明确、规则稳定 | 步骤不确定、需要探索 |

工作流是“把已知步骤写死”，Agent 是“给模型工具与目标，让它自己走”。前者可靠，后者灵活，两者常混合使用：外层是工作流，某个节点内部用 Agent 探索。

## 2.2 Agent Loop

Agent 的基本结构是一个循环：

```
目标 + 可用工具
  ↓
思考：当前状态、下一步做什么
  ↓
选择一个动作（调用工具 / 输出结果 / 请求澄清）
  ↓
执行动作，得到观测结果
  ↓
判断是否达成目标
  ├── 已达成 → 输出
  └── 未达成 → 回到思考
```

循环必须有终止条件，否则模型会在没有进展时继续调用。常见的四类终止条件：

1. 目标达成，模型输出最终结果。
2. 达到最大步数或最大调用次数。
3. 超过时间或成本预算。
4. 连续失败或重复动作，触发中止。

产品侧的做法是把这四条写在执行层，由程序判断，而不是交给模型自觉遵守。

## 2.3 记忆的三个层次

| 层次 | 内容 | 存储方式 | 生命周期 | 主要风险 |
|---|---|---|---|---|
| 短期上下文 | 当前对话的轮次、工具结果 | 请求内的消息列表 | 单次会话 | 超长后注意力衰减 |
| 任务状态 | 已确认的事实、待办、决策 | 结构化对象，程序维护 | 单次任务 | 字段遗漏、状态不同步 |
| 长期记忆 | 用户偏好、历史行为、历史结论 | 数据库或向量库 | 跨会话 | 记错、过期、隐私 |

三层的取舍原则：

第一，事实放任务状态，不放对话历史。订单号、地址、金额这类关键事实应由程序抽取后写入结构化字段，每轮注入。放在历史文本里会随轮次增多而被稀释或挤出。

第二，长期记忆只存稳定偏好，不存易变事实。用户的语气偏好可以记住，订单状态不该记。

第三，长期记忆需要可删除与可查看。涉及个人数据时，用户应能查看、纠正、删除，这也是合规要求。

第四，记忆写入要有触发条件。不是每轮对话都写，而是当出现明确偏好表达或任务结论时写入，否则记忆会积累大量噪声。

## 2.4 上下文膨胀

Agent 的上下文会快速膨胀，来源有四处：对话历史、检索片段、工具返回结果、推理与计划文本。

后果是四重的：成本随 Token 线性上升；首字延迟增加；注意力被分散，关键信息被埋没；最终触发窗口上限，导致截断丢信息。

常用压缩策略：

| 策略 | 做法 | 代价 |
|---|---|---|
| 滑动窗口 | 只保留最近若干轮 | 早期约束可能丢失 |
| 摘要 | 把历史压缩成结构化摘要 | 摘要可能丢细节，且需额外调用 |
| 结构化状态 | 关键事实抽成字段，每轮注入 | 需要定义字段与抽取逻辑 |
| 结果裁剪 | 工具返回只保留必要字段 | 可能丢失模型需要的上下文 |
| 分层记忆 | 近期完整保留，远期转摘要或向量化 | 实现复杂 |
| 按需检索 | 不携带历史，需要时再检索 | 增加一次检索延迟 |

实践中通常组合使用：结构化状态保关键事实，滑动窗口保留近期对话，工具结果裁剪到必要字段，远期内容压缩为摘要。

## 2.5 记忆的失败模式

| 失败 | 表现 | 应对 |
|---|---|---|
| 记错 | 把 A 订单的信息套用到 B 订单 | 关键事实由程序写入，不由模型誊写 |
| 污染 | 模型生成的推测被当作事实存入记忆 | 只存用户明确表达或系统查询结果 |
| 过期 | 旧地址、旧偏好继续生效 | 记忆带时间戳与有效期，定期复核 |
| 隐私泄露 | 一个会话的记忆被另一场景读取 | 按场景隔离记忆，按权限读取 |

## 2.6 常见误解

一、Agent 就是会调工具的聊天机器人。不成立。关键在于模型自主决定下一步，路径不固定。

二、多轮对话本身就是记忆。不成立。历史文本会衰减，关键事实需要结构化状态。

三、记忆越多越懂用户。不成立。无关记忆会干扰判断，并带来隐私与过期风险。

四、上下文窗口够大就不需要压缩。不成立。成本、延迟与注意力衰减仍然存在。

五、Agent 循环可以一直跑到成功为止。不成立。必须设步数、时间、成本上限。

## 2.7 判断练习

1. 一个订票 Agent 在第 8 轮后把目的地记成了上一个会话的城市。指出问题层与改法。
2. 客服 Agent 每轮都把完整物流报文注入上下文，单次请求 Token 持续增长。给出两种压缩方式。
3. 一个 Agent 连续调用同一查询工具 9 次，结果都一样。指出缺失的机制。
4. 产品希望“记住用户喜欢的回答风格”。应存入哪一层记忆，需注意什么。

参考答案：

1. 长期记忆被跨会话复用且无场景隔离，或任务状态未按会话重置。应把当前任务关键事实写入结构化状态，长期记忆按用户与场景隔离并带时间戳。
2. 工具结果裁剪为必要字段并附摘要；对历史轮次做滑动窗口或摘要压缩。
3. 缺少重复动作检测与最大步数限制，也缺少“无新信息则中止”的终止条件。
4. 存入长期记忆。需明确写入触发条件、提供查看与删除入口，并避免把一次性的临时偏好永久化。

## 2.8 小结

- Agent 与工作流的区别在于路径由谁决定：开发者编排还是模型运行时决定。
- Agent Loop 由思考、行动、观测、判断构成，必须由程序设定步数、时间、成本与失败终止条件。
- 记忆分三层：短期上下文、任务状态、长期记忆；关键事实应放结构化状态。
- 上下文膨胀带来成本、延迟、注意力与上限四重后果，需组合使用裁剪、摘要、结构化状态等策略。
- 记忆的主要风险是记错、污染、过期与隐私泄露，写入需有触发条件与隔离规则。
