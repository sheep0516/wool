# AI 产品的商业模式与定价逻辑

本节说明三种常见计费方式的差异、混合定价的思路，以及 ROI 的测算方法。核心判断：AI 产品的定价必须建立在边际成本之上。

## 1.1 成本结构决定定价方式

传统软件的边际成本接近零，定价主要看价值与竞品。AI 产品每次请求都有推理成本，因此定价必须同时满足两个条件：单用户收入高于其推理成本；定价方式能让用户预估用量。

| 结构 | 传统 SaaS | AI 产品 |
|---|---|---|
| 边际成本 | 接近零 | 随请求量增长 |
| 定价锚点 | 席位与功能价值 | 用量、席位与结果价值 |
| 规模风险 | 低 | 重度用户可能导致亏损 |
| 可预估性 | 高 | 中，取决于计费粒度 |

## 1.2 三种计费方式

| 方式 | 计量 | 适用对象 | 优点 | 风险 |
|---|---|---|---|---|
| 按 Token | 输入输出用量 | 开发者、API 客户 | 成本与收入直接对应 | 用户难以预估，可能抑制使用 |
| 按席位 | 账号数量 | 企业客户、内部工具 | 简单、易预算、销售友好 | 重度用户亏损，轻度用户补贴重度 |
| 按价值或结果 | 完成任务数、节省工时、达成结果 | 效果可量化的场景 | 与客户收益挂钩，易接受 | 计量与归因困难，收入不稳定 |

按 Token 计费最贴近成本，但客户往往无法理解“一次问答多少 Token”。实践中常做包装：给出“额度包”或“每千次问答”的换算，让客户可预估。

按席位计费适合使用频率稳定、用户行为差异不大的内部工具。风险在于重度使用者可能把单席位成本推高数倍，需要通过用量上限或分级套餐控制。

按价值计费的难点在计量。例如“每解决一个工单收费”，需要先定义什么叫“解决”，这与第7章的解决率指标直接相关。计量口径不清会导致结算争议。

## 1.3 混合定价

多数商业产品采用混合模式：

1. 基础订阅按席位，包含一定用量额度。
2. 超出额度按用量计费。
3. 高价值功能单独定价，例如高级模型、批量任务、专属知识库。

混合定价的作用是把可预估性与成本覆盖结合起来：客户能预算基础费用，厂商能覆盖重度使用。

| 组合 | 适用 |
|---|---|
| 席位加额度 | 企业协作类工具 |
| 订阅加超额 | 面向专业个人的工具 |
| 免费额度加按量 | 面向开发者的平台 |
| 结果分成 | 效果可直接换算为收益的场景 |

## 1.4 ROI 测算

ROI 需要分别算两笔账：客户侧与厂商侧。

客户侧的算式：

```
年收益 = 节省工时 × 人力成本 + 减少的错误损失 + 增量收入
客户 ROI = 年收益 ÷ 年支出
```

厂商侧的算式：

```
单客户毛利 = 客单价 - 推理成本 - 服务与运维成本
```

两个例子说明口径：

- 客服场景：AI 处理的比例 × 单工单人工成本 = 节省工时折算。若 AI 只做初筛，需要扣掉人工复核的时间。
- 写作场景：单篇节省时间 × 篇数。若质量需要返工，返工时间必须扣除。

三类收益难以量化，但会影响决策：

| 收益 | 说明 | 量化方式 |
|---|---|---|
| 响应速度 | 从小时级到分钟级 | 折算为业务机会或满意度 |
| 决策质量 | 更全面的信息与对比 | 用错误率或返工率间接衡量 |
| 体验一致 | 服务标准化、不受情绪影响 | 用满意度或投诉率间接衡量 |

ROI 不成立时的四条路径：

1. 缩小场景，只做高频高价值的部分。
2. 调整定位，从替代人改为辅助人，降低推理量与风险。
3. 优化成本结构，路由到小模型、加缓存、压缩上下文。
4. 调整价格，但要确认客户仍能获得正收益，否则规模不可持续。

## 1.5 常见定价错误

一、按竞品价格定价而不算自身成本。竞品可能用更小的模型或不同的成本结构。

二、只算平均用量，忽略重度用户。少数用户可能消耗大部分成本。

三、把推理成本当作一次性投入。它是持续的边际成本，会随规模线性增长。

四、免费额度设得过高。早期用户结构往往偏向重度使用者，免费额度会直接转化为亏损。

五、价值计费缺少计量口径。结算时争议不断，最终退化为按用量计费。

## 1.6 判断练习

为下列产品选择主要计费方式，并说明理由。

1. 面向中小企业的合同审查助手，每月处理几十份合同。
2. 面向开发者的文档问答 API。
3. 面向个人的写作助手，日常高频使用。
4. 面向大型客服中心，按解决的工单计费。

参考答案：

1. 按席位或按份数。使用频率可预估，按份数更贴近成本；若客户希望固定预算，可用席位加额度。
2. 按 Token 或按调用次数。开发者能理解用量，成本与收入直接对应。
3. 订阅加用量上限。个人用户难以理解 Token，订阅更易接受；用上限控制重度消耗。
4. 按结果计费。需先定义“解决”的口径（例如工单关闭且七日内无返工），并约定复核机制。

## 1.7 小结

- AI 产品的边际成本随请求增长，定价必须同时覆盖成本并让客户可预估。
- 三种计费方式分别是按 Token、按席位、按价值，各自适配不同客户与场景。
- 混合定价把可预估性与成本覆盖结合，是商业产品的常见选择。
- ROI 需分别算客户侧收益与厂商侧毛利，难以量化的收益用间接指标衡量。
- ROI 不成立时，应缩场景、改定位、优化成本或调整价格。
