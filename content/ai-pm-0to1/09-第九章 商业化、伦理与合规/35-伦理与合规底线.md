# 伦理与合规底线

本节说明三类底线问题、常见法规的检查清单，以及产品侧的落地方式。法规会更新，本节只提供检查框架，具体条款应以最新官方文本为准。

## 3.1 三类底线问题

| 类别 | 核心问题 | 典型后果 |
|---|---|---|
| 数据隐私 | 收集是否必要、使用是否有据、是否泄露 | 监管处罚、用户流失、信任崩塌 |
| 偏见与公平 | 输出是否对不同群体存在系统性差异 | 歧视投诉、品牌损害、法律风险 |
| 生成内容安全 | 是否生成违法有害、侵权或虚假内容 | 下架、处罚、内容责任 |

三者的共同点是：出问题往往不是模型“坏了”，而是产品侧缺少约束机制。

## 3.2 数据隐私

产品侧需要回答六个问题：

1. 收集什么。只收集完成任务所必需的数据，避免“先存下来以后可能有用”。
2. 为什么收集。每类数据有明确用途，不能挪用其他目的。
3. 是否告知。用户是否知道数据将被如何使用，是否可拒绝。
4. 谁能看到。内部访问是否有权限控制与审计。
5. 保存多久。设定保留期限，到期删除。
6. 是否出域。跨境传输、第三方服务调用是否合规。

三个容易出问题的环节：

第一，日志。为了排查而记录全文输入输出，其中可能包含身份证号、地址、联系方式。应在入库前脱敏。

第二，长期记忆。为了“更懂用户”而长期保存对话与偏好，实际构成了持续的个人信息处理，需要说明用途与删除方式。

第三，训练数据。用户输入是否被用于模型训练，必须在协议中写清，并提供退出机制。默认把用户数据用于训练，是高风险的常见做法。

## 3.3 偏见与公平

偏见的来源有四处：

| 来源 | 说明 |
|---|---|
| 训练数据 | 语料中的历史偏见被模型学到 |
| 提示词 | 角色设定与示例带有倾向 |
| 检索资料 | 知识库中的过时或歧视性表述 |
| 评估集 | 样本分布不均，导致偏差未被发现 |

偏见的典型表现是群体差异：同样的资质，对不同性别、地域、年龄给出不同评价；或输出刻板印象。

缓解手段：

1. 分组评估。评估集按群体标签分组，比较各组的通过率差异，而不是只看总体。
2. 资料审查。知识库中的表述定期检查，清理歧视性内容。
3. 提示约束。明确禁止基于敏感属性给出判断，并要求说明依据。
4. 人工复核。涉及对人的评价、准入、排序的决策，保留人工环节。

需要明确一个边界：模型不能作为涉及个人权益的最终决策者。可以做初筛、可以做信息整理，最终决定必须由人或规则作出。

## 3.4 生成内容安全

| 风险 | 例子 | 处理 |
|---|---|---|
| 违法有害 | 暴力、诈骗、违禁品制作 | 输入输出双向过滤，命中拦截 |
| 侵权 | 复现受版权保护的文本或形象 | 限制素材来源，提供合规模板 |
| 虚假信息 | 编造新闻、伪造引文 | 强制引用，事实类内容需校验 |
| 深度伪造 | 换脸、声音克隆 | 显著标识，限制特定用途 |

内容标识是近年监管的重点方向：AI 生成内容需要以可感知的方式标注，部分场景还要求元数据标识。产品侧应把标识设计进输出流程，而不是事后补加。

## 3.5 合规检查清单

不逐条解读法规，给出可执行的检查项：

| 检查项 | 要确认的内容 |
|---|---|
| 合法性基础 | 处理个人信息是否有同意、合同必要或其他法定依据 |
| 告知 | 是否说明收集范围、用途、保存期限、用户权利 |
| 最小必要 | 是否只收集完成任务所需的数据 |
| 留存与删除 | 是否有保留期限与删除机制，用户能否注销并删除 |
| 访问控制 | 内部访问是否有权限与审计 |
| 数据出境 | 是否涉及跨境传输，是否完成相应合规程序 |
| 内容标识 | 生成内容是否有可感知标识 |
| 投诉与申诉 | 是否有反馈渠道与处理时限 |
| 安全评估 | 上线前是否完成必要的内容安全与算法相关评估 |
| 未成年人保护 | 是否涉及未成年用户，是否有额外限制 |

涉及的法规框架大致包括：

- 中国：个人信息保护相关法律、数据安全相关法律、生成式人工智能服务管理相关规定、深度合成与生成内容标识相关规定、算法推荐相关规定。
- 欧盟：通用数据保护条例（GDPR）、人工智能法案（AI Act，按风险分级设定义务）。

两个使用提醒：一是法规持续更新，检查清单应每季度复核一次；二是不同市场的义务差异较大，跨境产品需要按市场分别评估，不能一套方案通用。

## 3.6 产品侧的落地方式

把合规要求转化为产品机制，而不是文档条款：

| 要求 | 产品机制 |
|---|---|
| 告知与同意 | 首次使用时的分层说明，关键授权单独确认 |
| 最小必要 | 字段级收集，非必需字段设为选填 |
| 删除权 | 提供会话删除、记忆清除、账号注销入口 |
| 访问控制 | 按角色与租户隔离，敏感操作留痕 |
| 内容标识 | 输出页固定标识，导出文件带说明 |
| 投诉渠道 | 产品内入口，承诺处理时限 |

关键点在于：合规不能只写在隐私政策里，必须体现在界面上、接口上和日志里。

## 3.7 常见误解

一、合规只是法务的事。不成立。数据最小化、删除入口、内容标识都需要产品设计承载。

二、开源模型本地部署就没有合规问题。不成立。数据仍可能涉及个人信息，内容仍需安全审核。

三、只要不收集个人信息就没有风险。不成立。生成内容安全、偏见与标识义务同样适用。

四、模型偏见过段时间会随版本更新消失。不成立。偏见需要在评估与流程层面持续治理。

五、生成内容加了“AI 生成”水印就满足要求。通常不够。标识需可感知、可追溯，具体形式依监管要求。

## 3.8 判断练习

1. 产品为了提升效果，把用户聊天记录默认用于训练。指出问题与改法。
2. 简历筛选助手对某类院校毕业生的通过率明显偏低。给出三步处理。
3. 生成的营销文案中出现了未经授权的品牌名称与标语。属于哪类风险，如何处理。
4. 团队认为本地部署开源模型即可规避合规审查。指出遗漏。

参考答案：

1. 缺少合法性基础与告知。应默认不用于训练，提供明确的单独同意与退出机制，并在协议中说明。
2. 先按院校分组核对评估集与真实通过率，确认差异是否系统性；再检查训练数据与提示词中的倾向；最后引入人工复核并调整评估标准，不允许模型直接决定淘汰。
3. 侵权风险。应限制素材来源，建立品牌白名单，输出前做版权与商标检查，并提供替换建议。
4. 本地部署只解决数据存储位置，未解决个人信息处理、内容安全、标识义务与偏见治理，这些仍需产品机制承载。

## 3.9 小结

- 三类底线问题是数据隐私、偏见与公平、生成内容安全，多数风险来自产品侧缺少约束机制。
- 数据隐私需回答收集、用途、告知、访问、期限、出境六个问题，日志、记忆与训练数据是高风险环节。
- 偏见治理靠分组评估、资料审查、提示约束与人工复核，模型不能作为涉及个人权益的最终决策者。
- 合规清单覆盖合法性基础、告知、最小必要、删除、访问控制、出境、标识、投诉与评估。
- 合规要求必须转化为界面与接口机制，不能只停留在政策文本。
