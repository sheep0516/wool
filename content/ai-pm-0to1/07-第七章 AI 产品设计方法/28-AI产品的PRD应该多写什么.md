# AI 产品的 PRD 应该多写什么

本节说明 AI 产品 PRD 相对传统 PRD 需要增加的章节与验收写法。核心判断：传统 PRD 描述功能，AI PRD 必须同时描述能力边界、验收标准与失败处理。

## 4.1 与传统 PRD 的差异

| 维度 | 传统 PRD | AI PRD |
|---|---|---|
| 功能描述 | 输入触发，输出确定 | 需说明能力范围与不确定部分 |
| 验收 | 通过或不通过 | 阈值、评估集、复测机制 |
| 异常 | 边界情况与报错 | 模型失败、拒答、幻觉、工具失败 |
| 成本 | 通常不涉及 | 单次与月度成本预算 |
| 数据 | 字段与来源 | 知识来源、更新、权限、留痕 |
| 迭代 | 版本功能清单 | 模型与 Prompt 版本、回归评估 |

一份 AI PRD 如果没有“评估方案”与“降级策略”两章，基本无法验收，也无法上线后运维。

## 4.2 六个增补章节

| 章节 | 必须写清的内容 |
|---|---|
| 能力边界 | 能做什么、明确不做什么、什么条件下拒答、已知失败类型 |
| 模型与 Prompt 策略 | 选型理由、关键参数、上下文如何组织、版本管理方式 |
| 评估方案 | 评估集构成与规模、指标定义、及格阈值、复测频率、责任人 |
| 降级与兜底 | 各类失败如何分流、用户看到什么、何时转人工 |
| 成本预算 | 单次请求成本、日均请求量、月度上限、超限策略 |
| 数据与权限 | 数据来源、更新机制、可见范围、留痕与审计要求 |

### 4.2.1 能力边界

不要写“支持智能问答”，要写成可判断的条目：

- 支持回答产品功能、价格、售后政策三类问题。
- 不支持法律意见、医疗建议、财务规划。
- 检索无结果时明确表示无法回答，不生成推测内容。
- 已知失败：多条件叠加的退货判定准确率偏低，此类问题引导至人工。

### 4.2.2 评估方案

评估方案是 AI PRD 的核心，它把“效果好”变成可验收的数字。至少包含：

1. 评估集来源：真实问题抽样、边界问题、应拒答问题、诱导性表述。
2. 规模：初期不少于若干百条，覆盖主要意图与边界。
3. 指标：检索命中率、答案忠实度、引用准确率、拒答正确率、任务完成率。
4. 阈值：每项指标的及格线与目标线。
5. 频率：每次 Prompt 或模型变更前必须回归。
6. 责任人：谁维护评估集，谁判定是否通过。

### 4.2.3 降级与兜底

按失败类型逐条写明走向，避免工程临时决策：

| 失败 | 产品行为 |
|---|---|
| 检索为空 | 说明未找到，给替代入口 |
| 低于置信阈值 | 给候选或建议核实 |
| 工具超时 | 重试一次，仍失败则提示稍后或转人工 |
| 内容风险 | 拦截并给出可解释的拒绝 |
| 连续未解决 | 主动提示转人工 |

### 4.2.4 成本预算

写明三个数字：单次请求的 Token 与费用估算、日均请求量、月度上限。再写明超限策略：降级到小模型、限制单用户额度、排队或提示。缺少这一节，上线后第一次账单就会成为事故。

### 4.2.5 数据与权限

写明数据从哪来、多久更新、谁能看到、是否留痕。涉及个人信息的，还要写保存期限与删除机制。

## 4.3 验收标准的写法

验收条目要满足三个条件：可测、有阈值、有样本。对比示例：

| 不可验收 | 可验收 |
|---|---|
| 回答准确、专业 | 在 300 条评估集上，事实性错误不超过 5%，引用准确率不低于 90% |
| 支持多轮对话 | 在五轮以内的任务中，意图识别准确率不低于 85%，无法识别时给出候选 |
| 响应要快 | 首字延迟不超过 1.5 秒，完整回答不超过 8 秒（P90） |
| 不能泄露数据 | 越权样本测试 100 条，全部拒绝；日志中不出现完整身份证号 |

## 4.4 风险边界

PRD 中应单列一节，写明三类内容：

1. 不可做的事。例如不提供医疗诊断、不承诺赔付金额、不执行未经确认的退款。
2. 必须人工复核的环节。例如合同条款最终判定、高风险客户的服务方案。
3. 合规要求。数据不出域、生成内容需标注、留痕保存期限。

这一节的作用是在需求评审阶段就把边界定下来，避免上线前被合规叫停。

## 4.5 常见 PRD 缺陷

| 缺陷 | 后果 |
|---|---|
| 只写功能，不写能力边界 | 上线后用户问到范围外的问题，产品无应对 |
| 没有评估方案 | 无法验收，迭代变成主观争论 |
| 只写正常流程，不写失败态 | 出错时表现混乱，用户流失 |
| 不写成本 | 规模化时费用失控 |
| 不写数据与权限 | 合规评审被卡，返工 |
| 验收写成形容词 | 无法判断是否达标 |

## 4.6 判断练习

给下列需求补上缺失的 PRD 章节。

1. “做一个企业内部制度问答助手，员工可以问报销、考勤、假期相关问题。”
2. “做一个商品文案生成工具，输入商品信息，输出三版文案。”
3. “做一个客服机器人，自动处理退换货咨询。”

参考答案：

1. 缺能力边界（不含法律与人事争议）、权限（按部门与职级可见制度）、评估方案（制度类问题忠实度阈值）、数据更新机制（制度修订后的生效流程）、拒答策略。
2. 缺成本预算（三版生成的单价与额度）、内容安全（违禁词与品牌合规）、版权（素材来源）、队列与失败重试、采纳率指标。
3. 缺意图清单与兜底意图、转人工触发条件、承诺类内容的规则校验、解决率与误转率的定义、工具失败降级、质检抽样方案。

## 4.7 小结

- AI PRD 与传统 PRD 的差异集中在验收、异常、成本与数据四方面。
- 六个增补章节是能力边界、模型与 Prompt 策略、评估方案、降级兜底、成本预算、数据权限。
- 验收条目必须可测、有阈值、有样本，形容词不能作为验收标准。
- 风险边界应单列，写明不可做的事、人工复核环节与合规要求。
- 缺少评估方案与降级策略的 PRD，无法验收也无法运维。
