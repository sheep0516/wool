# 主流模型格局与选型直觉

本节说明模型的能力与成本光谱、选型维度、模型路由的适用条件，以及多模态能力对产品的影响。


## 4.1 能力与成本光谱

模型大致可分为四类。具体型号与价格变动频繁，这里只描述相对关系，不给具体数字。

| 类别 | 特点 | 典型优势 | 典型代价 |
|---|---|---|---|
| 闭源旗舰 | 能力最强，多模态与工具调用完整 | 复杂推理、长文档、多步骤任务 | 单价最高，延迟较高，数据需出境或经第三方 |
| 轻量模型 | 参数小，响应快，价格低 | 高频简单任务、分类抽取、实时交互 | 复杂推理与长上下文能力弱 |
| 推理模型 | 生成前先进行较长思考 | 数学、逻辑、多约束规划 | 延迟显著上升，输出 Token 消耗大 |
| 开源模型 | 权重可获取，可本地或私有部署 | 数据不出域、可深度定制、成本可控 | 需要自建运维，能力通常低于同期旗舰 |

一个容易误判的点：能力强的模型不一定是最优选择。选型目标是单位任务成本下的达标效果，而不是排行榜第一。

## 4.2 选型维度

| 维度 | 需要回答的问题 |
|---|---|
| 任务类型 | 生成、抽取、分类、推理、多模态，哪一类是主任务 |
| 质量要求 | 达标标准是什么，允许的错误率是多少 |
| 延迟要求 | 用户能等多久，是否需要流式、是否可异步 |
| 成本预算 | 单次请求可接受成本与月度上限 |
| 数据合规 | 数据能否出域，是否涉及个人信息或行业监管 |
| 稳定性 | 供应商可用性、限流策略、版本变更频率 |
| 语言能力 | 中文、多语言、方言的实际表现 |
| 结构化输出 | JSON 模式、函数调用的可靠性 |
| 上下文需求 | 单次需要注入多少资料 |

其中数据合规通常是硬约束，会先排除一批候选，再在剩余范围内比较能力与成本。稳定性容易被忽略：供应商的模型版本升级可能改变输出行为，需要回归评估机制。

## 4.3 模型路由

模型路由指按任务难度、风险或用户等级，把请求分发给不同模型。常见策略：

1. 规则路由：按意图或业务线固定分配。
2. 分类器路由：先由轻量模型判断任务难度，再决定使用哪个模型。
3. 级联路由：先小模型作答，置信度不足或校验失败时升级到大模型。
4. 混合路由：简单步骤用小模型，关键步骤用大模型，同一流程内混用。

收益是成本显著下降、简单任务延迟降低。代价是系统复杂度上升，并引入一致性问题：同一产品内不同模型输出的风格与格式可能不一致，评估也需要分层。

不适合做路由的情况：请求量很小、任务类型单一、对一致性要求极高。此时节省的成本有限，复杂度却实打实增加。

## 4.4 多模态能力的含义

多模态指模型可处理文本以外的输入或输出。产品侧关注点各不相同。

视觉理解（图像输入）：常见于票据识别、截图问答、图表解读、质检。需要关注分辨率对准确率的影响、图片折算 Token 后的成本、以及小字与倾斜拍摄的失败率。图像理解出错时通常不会明确告知，因此关键字段仍要程序校验。

文生图：关注可控性（构图、文字、风格一致性）、版权与合规、以及生成失败的重试成本。产品上通常需要提供风格预设、尺寸参数与候选数量。

语音：分为识别（ASR）与合成（TTS）。识别关注口音、噪声、专业术语的准确率；合成关注延迟、打断处理与音色一致性。实时对话场景中，端到端延迟比单点质量更影响体验。

文生视频：时长、一致性、可控性仍是主要限制，适合短片段与素材辅助，不适合长叙事成片。

多模态不是“更高级”，而是不同的输入输出形态。成本结构、失败模式、评估方法都与纯文本不同，不能沿用文本产品的验收标准。

## 4.5 选型流程

一个可执行的顺序：

1. 明确任务与达标标准，先写评估集。
2. 用 3 至 5 个候选模型在同一评估集上跑同题测试。
3. 比较四组数据：达标率、单位成本、延迟、格式遵循率。
4. 合规与稳定性审查，排除不可用候选。
5. 在剩余候选中按单位任务成本排序，选择满足标准的最低成本方案。
6. 保留一个备选模型，用于故障切换与版本回归。

同题测试的关键是使用真实样本，而不是自己构造的简单例子。评测集要包含边界情况与失败案例，否则所有模型都会显得表现良好。

## 4.6 常见误解

一、用最强的模型最保险。不成立。成本与延迟可能使产品无法规模化，且强模型同样会幻觉。

二、便宜的小模型只适合测试环境。不成立。分类、抽取、改写等任务中，小模型在达到标准时是最优选择。

三、开源模型部署后就没有成本。不成立。GPU、运维、调优、升级都产生成本，规模小时单位成本往往更高。

四、多模态模型可以替代 OCR 加规则校验。不成立。关键字段仍需结构化校验，模型输出不能作为唯一依据。

五、模型升级后效果一定更好。不成立。版本变更可能改变格式遵循与拒答尺度，必须做回归评估。

## 4.7 判断练习

为下列场景选择模型类别，并说明理由。

1. 每天千万次的短文本情感分类。
2. 需要读取合同扫描件并抽取 20 个字段。
3. 医院内部的病历摘要，数据不得出院区。
4. 面向用户的实时语音对话助手。
5. 需要多步推理的复杂费用核算解释。

参考答案：

1. 轻量模型。任务简单、量大，成本与延迟是主要约束，达标即可。
2. 多模态模型加结构化校验。扫描件需要视觉理解，字段抽取结果必须程序校验，不能直接采信。
3. 开源模型本地部署。合规为硬约束，数据不得出域，优先满足隔离要求，再评估能力是否达标。
4. 轻量或专用语音方案，重点控制端到端延迟与打断处理，复杂推理可降级或异步。
5. 推理模型或旗舰模型，配合工具调用取数。计算与事实由工具完成，模型只负责解释与组织表达。

## 4.8 小结

- 模型分闭源旗舰、轻量、推理、开源四类，能力与成本不同，选型目标是单位任务成本下的达标效果。
- 选型维度包括任务类型、质量、延迟、成本、合规、稳定性、语言、结构化输出与上下文需求。
- 模型路由能降低成本与延迟，但会提高复杂度并带来一致性问题，请求量小或任务单一时不划算。
- 多模态是不同的输入输出形态，成本与失败模式与文本不同，关键字段仍需程序校验。
- 选型顺序是评估集先行、同题测试、合规审查、按成本排序选最低可行方案，并保留备选模型。
