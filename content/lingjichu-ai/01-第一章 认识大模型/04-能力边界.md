# 大模型擅长什么，必然错在哪

判断标准只有一条：任务是否依赖大量文本里反复出现的模式。是，模型通常做得不错；不是，比如精确计算、实时事实、严格长链推理，它必然出错，只是错得很流畅。按这条线把任务分开，比事后逐条检查更省力。

## 一、擅长的任务

这些任务的共同点是有海量范例、容错高、结果容易人工判断：

- 改写：换语气、换受众、压缩或扩写。
- 总结：长文提要点，抓主要论点。
- 归类：打标签、分主题、判断情感倾向。
- 生成候选：起标题、列方案、写测试用例草案。
- 解释概念：用类比把一个术语讲清楚。
- 格式转换：JSON 转表格、自然语言转 SQL 草稿。
- 代码草稿：脚手架、正则、样板代码。

注意「草稿」二字：产出的是起点，不是终稿。

## 二、不擅长的任务

| 任务类型 | 为什么不行 | 正确做法 |
| --- | --- | --- |
| 精确计算 | 按 `token` 生成，没有可靠的算术单元 | 让它写代码或调用计算器 |
| 实时信息 | 知识截止时间之后的事不知道 | 搜索、查接口 |
| 严格长链推理 | 中间步骤出错会一路累积 | 拆步骤，逐步验证 |
| 冷门事实检索 | 训练语料里没有就编 | 查权威来源 |
| 稳定复现 | 采样有随机性 | 降温度、固定参数、多次比对 |
| 真正执行操作 | 它只输出文本 | 走工具调用或人工执行 |

「严格长链推理」要说明边界：不是所有多步推理都不行，而是步骤越多、越依赖精确的中间结果，错误累积越明显。让它一步步写出来并逐步检查，能缓解，但不能消除。

判断顺序可以先看可验证性，再看任务难度：难但可验证的任务（写代码、做表格），往往比简单但无法验证的任务（评价一个人、预测趋势）更适合交给模型。

## 三、五类典型错误

| 错误类型 | 表现 | 例子 |
| --- | --- | --- |
| 幻觉 | 编造不存在的事实、文献、接口 | 引用一篇查不到的论文 |
| 算术错 | 大数运算、多步计算出错 | 137 × 48 算成 6576 |
| 时间错 | 把旧信息当现状 | 说某产品「最新版本」是两年前的 |
| 引用错 | 出处、页码、链接对不上 | 给的链接打不开或内容不符 |
| 过度顺从 | 顺着错误前提编解释 | 解释「为什么水在 0 度会沸腾」 |

幻觉最难发现，因为它在语气、结构、专业度上和正确内容没有区别。

## 四、表达流畅与内容正确是两件事

模型的训练目标是「下一个 `token` 像不像人写的」，不是「这句话是不是真的」。所以流畅度和正确性没有必然关系。一段逻辑通顺、用词专业、层次清楚的文字，完全可能建立在错误前提上。

实用推论：读输出时，把「写得真好」和「说得对」分开评估。前者几乎总是成立，后者需要单独验证。

## 五、判断该不该交给模型：三问

1. 结果错了，代价大不大？代价小、能快速发现，可以放心交；代价大，必须有人复核。
2. 有没有客观的验证方式？能跑测试、能对账、能查原文，就适合交给它出草稿；无法验证的，谨慎。
3. 任务是否依赖训练语料里稳定存在的模式？常见写作、常见代码、通用概念，是；内部数据、最新行情、精确数值，不是。

三问里有一个「否」，就要加人工环节。

## 六、人在回路

人在回路不是「最后看一眼」，而是把验证点设计进流程。让模型主动暴露不确定项，比你自己猜哪里可能错有效得多：

```text
请完成以下任务，并严格按给定格式输出：
1. 结论（不超过 3 句）
2. 依据（逐条列出，并标明来自我提供的资料，还是你的推断）
3. 不确定项（列出你没有把握的部分，不要省略）
4. 需要我核实的事实清单（逐条写出该怎么查）

不要为了显得完整而补充资料以外的内容。
```

要求它区分「资料」和「推断」，幻觉就更容易暴露。任何进入正式文档、代码库或对外沟通的内容，都要过这一步。复核成本要和错误代价匹配：写一封内部邮件，扫一眼就够；生成一段要上线的代码，必须跑测试。

## 速查

- 擅长：改写、总结、归类、生成候选、解释概念、格式转换、代码草稿。
- 不擅长：精确计算、实时信息、严格长链推理、冷门事实、稳定复现、真实执行。
- 五类典型错误：幻觉、算术错、时间错、引用错、过度顺从。
- 流畅不等于正确，两者要分开评估。
- 三问：错了代价多大、能否验证、是否依赖稳定模式。
- 有一个「否」就加人工复核。
- 让它区分「资料」与「推断」，幻觉更容易暴露。
- 产出是草稿，进入正式流程前必须验证。
