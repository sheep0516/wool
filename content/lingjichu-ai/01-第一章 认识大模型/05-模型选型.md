# 模型选型：规模、推理与多模态怎么选

选型的第一原则是：先用真实任务样本做小规模对比，再看榜单和参数。真正决定取舍的是三个维度——能力够不够、成本能不能接受、延迟是否影响使用。任何脱离任务的「最强模型」推荐都没有意义。

## 一、三个维度

| 维度 | 关注点 | 什么时候优先 |
| --- | --- | --- |
| 能力 | 任务通过率、输出稳定性 | 复杂推理、长文、代码 |
| 成本 | 每百万 `token` 单价、缓存折扣、输出溢价 | 高频、大批量 |
| 延迟 | 首字延迟、输出速度 | 交互式、实时场景 |

三者通常互相制约：更强的模型往往更贵更慢。选型就是在三角里找一个能接受的点，而不是三项都要最好。

## 二、通用模型与推理型模型

- 通用模型：响应快、便宜，适合改写、总结、分类、日常问答、格式转换。
- 推理型模型：回答前会做较长的内部推导，适合数学、复杂代码、多步规划、要求严格逻辑的任务。

推理型不是全面更强。它的思考过程本身消耗大量 `token`，简单任务上用它会又慢又贵，收益接近零。判断标准是任务是否需要「多步、可验证的中间推导」，而不是问题看起来难不难。另外，它展示的思考过程不等于正确依据，结果仍要验证。

## 三、闭源 API 与本地开源模型

| 对比项 | 闭源 API | 本地开源模型 |
| --- | --- | --- |
| 上手成本 | 低，注册即可用 | 高，要部署和调优 |
| 能力上限 | 通常更高 | 受模型规模和量化影响 |
| 数据隐私 | 数据要出内网 | 完全本地，可控 |
| 成本结构 | 按量付费 | 一次性硬件投入加运维 |
| 可控性 | 受服务方策略与限流影响 | 可改、可换、可离线 |
| 硬件门槛 | 基本没有 | 显存是硬约束 |

判断顺序：数据是否敏感 → 是否有离线或合规要求 → 用量是否大到值得自建 → 能力是否够用。个人学习和低敏任务用 API；涉及内部数据、离线环境、长期高频，再考虑本地部署。

## 四、多模态与长上下文：加钱买的是什么

多模态指处理图像、音频、视频。值不值得付费，看任务是否必须「看」或「听」：

- 必须：截图转文字、票据信息抽取、界面走查、图表读数、语音转写。
- 不必须：纯文本任务。先用 OCR 或转写工具预处理，再交给文本模型，通常更便宜也更稳。

一个常见错误是「买了多模态就不需要别的工具」。实际项目里，专用 OCR 在结构化文档上往往比通用视觉模型更准、更便宜。

上下文长度是另一个可加钱的维度。更长的窗口能一次读入整本书或整个代码库，但有三点代价：成本按 `token` 线性增长；长上下文中间的内容容易被忽略，放进去不等于会被用到；预填充时间随输入变长而增加。按当前主流工具，长上下文适合「一次性分析一份长文档」，不适合替代检索。需要反复查询大量资料时，先检索再喂入更划算。

## 五、可执行的选型流程

1. 定任务：写清楚输入、输出、验收标准，以及出错的代价。
2. 建样本集：从真实数据里挑 20–50 条，覆盖典型情况和边界情况。
3. 小规模对比：同一批样本跑 2–3 个候选模型，记录通过率、延迟、成本。
4. 算总账：按实际调用量估算月成本，把重试和人工复核算进去。
5. 再决定升级：只有当前模型在样本上明显不达标，才换更贵的。

评测环节可以先借模型自己初筛，把明显不满足要求的挑出来，再人工复核争议项：

```text
你是评测助手。下面有若干条样本，每条包含「输入」「期望要点」「模型输出」。
请逐条判断模型输出是否覆盖了期望要点，按表格输出：
| 编号 | 是否通过 | 缺失要点 | 严重程度 |
判分规则：措辞不同但意思覆盖算通过；出现期望要点以外的编造事实判为不通过；拿不准的标「待人工」。
```

## 六、常见误区

| 误区 | 问题 | 修正 |
| --- | --- | --- |
| 越大越好 | 小任务上收益低、成本高 | 按通过率选最小够用的 |
| 只买最贵 | 忽略用量与延迟，预算失控 | 按实际调用量算总成本 |
| 忽略延迟 | 交互场景体感差 | 单独测首字延迟 |
| 只看榜单 | 榜单任务与实际任务不一致 | 用自有样本评测 |
| 一上来就多模态 | 能力冗余、成本上升 | 先文本，确认不够再加 |
| 长上下文代替检索 | 贵，且中间信息容易丢 | 先检索，再喂入 |

## 速查

- 先定任务再选模型，不要按榜单选。
- 三维度：能力、成本、延迟，通常互相制约。
- 推理型适合多步推导，简单任务上又慢又贵。
- 数据敏感、离线、长期高频，才考虑本地部署。
- 多模态只在任务必须「看」或「听」时才值得。
- 长上下文贵且中间内容易丢，不能替代检索。
- 流程：定任务、建 20–50 条样本、对比 2–3 个模型、算总账、再升级。
- 按真实样本通过率选「最小够用」的模型。
