# 一次回答是怎样生成的

一次回答本质上是两类计算：先把整段上下文一次性读进去（预填充），然后一个 `token` 一个 `token` 地往外吐（解码）。总时长约等于首字延迟加上输出 `token` 数乘以每个 `token` 的耗时。有了这个公式，长输出为什么慢、无关上下文为什么拖后腿，都能直接解释。

## 一、请求链路

1. 分词：把你发的内容、系统提示、历史消息全部切成 `token`。
2. 拼装上下文：按固定模板把「系统提示 + 历史对话 + 本轮用户输入」拼成一个序列。
3. 预填充：对整个序列做一次前向计算，缓存中间结果。这一步计算量大，但可以并行。
4. 采样：在最后一个位置的概率分布上抽一个 `token`。
5. 逐词解码：把新 `token` 接到序列末尾，再前向算一次，抽下一个。每次只能出一个。
6. 流式返回：每生成若干 `token` 就推给前端，所以你看到的是逐字出现。

关键在第 5 步：它必须串行。第 n 个 `token` 要等第 n−1 个算完，这就是长输出慢的根本原因。

## 二、上下文窗口是什么

上下文窗口是模型一次能读入的最大 `token` 数，包含系统提示、全部历史、本轮输入，以及给输出预留的空间。它不是「记忆容量」，而是一次前向计算能处理的上限。

| 组成部分 | 典型占用 | 特点 |
| --- | --- | --- |
| 系统提示 | 几十到几百 `token` | 每轮都带，最稳定 |
| 历史对话 | 随轮次线性增长 | 最容易失控 |
| 本轮输入 | 不定 | 你直接控制 |
| 输出预留 | 不定 | 设太大就挤压输入空间 |

超出窗口会怎样：常见做法是截断最早的内容、做摘要压缩，或者直接报错。无论哪种，被挤掉的信息模型就是看不到，表现就是「它忘了前面说过的话」。

## 三、预填充与解码：为什么首字延迟重要

预填充阶段所有 `token` 并行计算，通常几百毫秒到几秒；解码阶段每个 `token` 一次串行计算，速度取决于模型规模和硬件。两类耗时的性质不同：

- 首字延迟（预填充加第一个 `token`）决定「等待感」。
- 解码速度决定「读完要多久」。

对人来说，首字延迟比总时长更影响体验：等 3 秒开始出字，比等 30 秒一次性蹦出一大段更好接受，所以工具普遍采用流式输出。反过来，如果写程序调接口，要知道总时长由输出长度主导，而不是由输入长度主导。

## 四、系统提示、历史、输入在上下文中的位置

常规顺序是：系统提示在最前，历史对话按时间排列，本轮用户输入在最后。模型对靠近开头和结尾的内容更敏感，中间部分容易被「稀释」。这是经验规律，不是硬保证，但足够用来排版你的提示词。

利用这一点，把关键约束放开头，并在结尾再提一次：

```text
【任务】把下面的会议记录整理成待办清单。
【硬性要求】每条待办必须含负责人和时间；找不到的写「待确认」，不要编造。
【输出格式】markdown 无序列表，按负责人分组。

（会议记录正文）
……
再次强调：信息缺失就写「待确认」，不要补充猜测。
```

把「不要编造」放在长文档末尾，常常会被忽略；放开头并重复，稳定性明显更好。

## 五、长输出为什么慢、成本高

- 慢：解码是串行的，输出 1000 个 `token` 就是 1000 次前向计算。
- 贵：按 `token` 计费，输入和输出都算，输出通常单价更高。
- 上下文随之变长：多轮对话每轮都要重传历史，输入 `token` 会累积上涨。

所以让模型「详细展开」是有代价的。需要长文档时，分批生成再拼接，通常比一次生成更可控，也更容易检查。

## 六、对使用者的可操作结论

| 做法 | 原因 |
| --- | --- |
| 重要信息放开头或结尾 | 中间内容容易被忽略 |
| 清掉无关上下文 | 省 `token`、降延迟、减少干扰 |
| 长任务分段 | 单段输出短，串行成本低，便于检查 |
| 明确输出格式与长度 | 避免自由发挥导致超长 |
| 需要稳定就降低随机性 | 采样随机性会让长输出越走越偏 |

长任务分段的写法可以直接照抄：

```text
这是任务的第 1 段，共 3 段。只处理第一部分，输出后停下，等我确认再继续。
【本段范围】第 1–4 章内容摘要，每章 3 条，不要引用后面章节。
```

## 速查

- 一次回答等于预填充一次加解码 N 次。
- 总时长约等于首字延迟加输出 `token` 数乘每 `token` 耗时。
- 预填充可并行，解码必须串行，所以长输出慢。
- 上下文窗口包含系统提示、历史、输入和输出预留。
- 超出窗口会被截断或压缩，表现为「忘记」。
- 首字延迟比总时长更影响体感，流式输出就是为此。
- 关键约束放开头并重复一遍；无关历史及时清理。
- 长任务分段生成，比一次索要一大段更稳。
