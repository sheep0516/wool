# 搭建个人 AI 工作流

个人 AI 工作流的本质，是把「每次重新想怎么问」变成「按固定流程跑」。三层结构：提示词库、固定流程、工具链。从一周内重复出现的劳动入手，先做 3 个模板加 1 条固定流程，跑顺了再扩。

## 一、三层结构

| 层 | 作用 | 形式 |
| --- | --- | --- |
| 提示词库 | 存可复用的问法 | Markdown 模板 |
| 固定流程 | 把多步串成标准动作 | 清单或脚本 |
| 工具链 | 让流程能读写文件、检索资料 | 本地脚本或平台功能 |

三层各管一段：模板保证问法稳定，流程保证步骤不漏，工具链保证能接触真实数据。只堆模板而不管流程，产出仍然零散；只搭工具而没有模板，每次输出风格都不一样。

三层不必一次建齐。先把模板攒起来，再补流程，最后才考虑写脚本；顺序反了，容易做出一堆没人用的工具。

## 二、从重复任务入手

先记录一周内重复出现的劳动：同一类改写、同一格式的总结、同一份周报、同一套代码审查。判断标准是重复三次以上、每次步骤相似。

不要从「看起来高级」的任务开始，从「烦但简单」的任务开始。这类任务收益明确、风险低，最容易验证流程是否真的省事。

记录用最简单的方式：每天在同一个文件里追加一行「做了什么、花了多久、下次能否复用」。一周后统计，重复项自然会浮现。

判断是否值得流程化，还看它是否容易出错：重复且易错的劳动，收益比单纯重复更高。

## 三、模板库怎么组织

命名用「场景-对象-版本」，例如 `周报-项目-v2`。变量用固定记号标出，例如 `{{材料}}`、`{{规范}}`，每次只替换这些部分。只存验证过的版本：跑过、输出稳定、你愿意复用的才入库。每份模板开头写清适用场景与已知缺陷。

版本号只在行为发生变化时递增，小修小补不算；否则版本很快失控，自己都分不清哪版能用。

```markdown
模板：代码审查-接口层-v2
适用：审查新增 API 的边界处理
变量：{{diff}} 代码差异，{{规范}} 团队规范摘要

请按以下顺序审查 {{diff}}：
1. 输入校验：空值、类型、越界
2. 错误处理：是否吞异常、是否泄露内部信息
3. 与 {{规范}} 不一致处，逐条引用原文
输出表格：问题 | 位置 | 严重度 | 建议
```

## 四、输入输出的规范

文件放哪：固定目录，例如 `inbox/` 放原始材料，`out/` 放产物。目录固定后，脚本和模板都不用改路径。

怎么命名：日期加主题，例如 `2026-11-23-周报.md`，不要出现「最终版 2」这类名字。

结论落盘：每次有价值的输出存成文件，第一行写结论，后面放正文。这样日后检索时先看到结论，不用重读全文。

产物命名带上来源与日期，例如 `2026-11-23-周报-from-inbox.md`，日后能顺藤摸瓜找到原始材料。

目录与命名规则定下后，写进模板顶部的注释里，避免每次重新决定，也方便脚本按固定路径读写。

## 五、每周复盘与隐私备份

复盘只问三件事：哪次没用上，删掉对应模板；哪次节省最多，把它固化成流程；哪次出错，在模板里补一条检查点。

复盘不要写成日记，只留可执行的三行：删哪个、固化哪个、加哪条检查。没有结论的复盘等于没做。

隐私方面，未清洗的原文不要直接送进外部接口，敏感资料本地处理或脱敏。备份方面，把模板与产出纳入版本管理或定期打包，别只留在聊天记录里，记录一关就找不回来。

## 六、最小起步与成熟度自评

最小方案是 3 个高频模板加 1 条固定流程。模板可选总结、改写、代码审查；流程可选每周周报。连续跑两周，再决定是否增加。

起步阶段不要追求工具链完备，能用现成产品完成模板替换就先跑起来；工具是为流程服务的，不是反过来。

| 阶段 | 特征 | 参考分 |
| --- | --- | --- |
| 随意提问 | 每次现想，结果不稳定 | 0 |
| 有模板 | 常用任务有固定问法 | 1 |
| 有流程 | 多步任务有清单与检查点 | 2 |
| 工具化 | 能读写文件、自动检索 | 3 |
| 可复盘 | 有记录、有评估、持续优化 | 4 |

不必追求一次到 4 分。能从 0 到 1，产出就已经稳定；能稳定在 2，说明流程真的在替你省事。
