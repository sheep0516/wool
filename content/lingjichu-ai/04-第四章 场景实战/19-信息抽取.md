# 信息抽取：把散乱文本变成表格

抽取质量的决定因素不在模型，而在 schema：字段、类型、取值规则先定死，模型只负责按规则填空。schema 含糊，模型就会自行发挥，最后你拿到一张字段混乱、无法统计的表。

## 一、先定 schema 再抽取

别一上来就贴文本让模型「帮我提取信息」。先回答三个问题：

- 这张表一行代表什么（一份简历、一张发票、一条评论）。
- 每行要有哪些字段，每个字段用来干什么。
- 哪些字段是枚举，枚举值有哪些。

把这三件事写成 schema，再喂给模型，抽取才有稳定输出。schema 同时也是验收标准：字段对不上，就是抽取出了问题。schema 最好先手写两三行样例数据，确认字段够用、不重复，再交给模型批量跑。

## 二、字段、类型与枚举的约定

| 约定项 | 规则 | 示例 |
| --- | --- | --- |
| 字段名 | 英文小写下划线，语义单一 | `start_date` |
| 类型 | 明确 string、number、date、array | `amount: number` |
| 枚举 | 取值穷举，禁止自由发挥 | `status: ["待审","通过","拒绝"]` |
| 格式 | 日期统一 ISO，金额保留两位 | `2025-03-01` |

缺失值统一用 `null`，不要用空字符串、`N/A`、`未知` 混着来。不确定的值单独用 `"uncertain"` 标注，并另设 `note` 字段说明原因。这样后续统计时，`null`、`uncertain` 和真实值三者可以分开处理，不会被混为一谈。字段命名避免同义反复，比如同时出现 `company` 和 `company_name`，会让模型在两个字段间摇摆。

## 三、长文本分批与去重

超长文本直接丢进去会被截断，或者模型开始遗漏后半段。做法是：

- 按条目切批：一条记录一批，或固定条数一批。
- 每批独立抽取，输出统一 JSON 数组。
- 合并后按唯一键去重，如发票号、简历邮箱、评论 ID。

没有唯一键时，用「文本哈希加关键字段」做去重键。去重放在合并阶段，不要指望模型自己发现重复。分批大小要兼顾两点：单批不超上下文，批数不失控。通常一批 5 到 20 条比较稳。

## 四、常见抽取对象的字段示例

| 对象 | 关键字段示例 |
| --- | --- |
| 简历 | 姓名、邮箱、电话、最高学历、技能列表、工作年限 |
| 发票 | 发票号、开票日期、金额、税额、购买方、销售方 |
| 用户评论 | 评分、情感倾向、提及产品、问题类型、原文片段 |
| 会议记录 | 结论、待办事项、负责人、截止时间、参会人 |

字段不必多，够用即可。每多一个自由文本字段，就多一处需要人工复核的地方。字段示例只是起点，实际按业务增删，删字段比加字段更安全。

## 五、JSON 抽取提示词

```text
你是信息抽取器。请从下面的文本中抽取记录，严格按给定 schema 输出 JSON，不要输出任何解释。

schema：
{
  "name": "string",
  "email": "string | null",
  "years": "number | null",
  "skills": "string[]",
  "status": ["待审", "通过", "拒绝"]
}

规则：
1. 只能使用原文中出现的信息，禁止推测或补全。
2. 原文没有的字段填 null；有歧义的填 "uncertain"，并在 note 里写明原因。
3. 日期统一 ISO 格式；数字不带单位。
4. 输出为 JSON 数组，每个元素包含 schema 全部字段，外加 note 字段。

文本：
【粘贴文本】
```

提示词里把 schema 和规则分开写，改规则时不用动 schema，复用更方便。如果一次跑不完，把 schema 和规则存成固定模板，每批只换文本，输出风格才一致。

## 六、结果校验与失败处理

抽取完必须校验，不能直接信：

- 条目数量守恒：输入多少条记录，输出应有多少条；对不上就查是否截断或漏抽。
- 格式校验：用 JSON 解析器跑一遍，类型不符直接报错。
- 抽样复核：随机抽 5% 到 10%，人工对照原文，算出准确率。

抽样复核不只看得出的值，还要看 `null` 是否真的缺失，模型有时会把有值的地方误判为空。

常见失败与处理：

| 失败现象 | 原因 | 处理 |
| --- | --- | --- |
| 字段缺失 | 原文确实没有 | 保留 null，勿补 |
| 模型自行补全 | 提示词未禁止推测 | 加「只能使用原文信息」 |
| 超长文本截断 | 超出上下文 | 分批抽取再合并 |
| 枚举值跑偏 | 未穷举取值 | 在 schema 里写死枚举 |

从原始文本到表格的流水线可以固定成五步：

```text
原始文本 → 清洗与分条 → 按 schema 分批抽取 → 合并去重 → 校验与抽样复核 → 导出表格
```

每一步都留痕：原始文本、每批的 JSON 输出、校验报告都存档，出问题才能回溯到具体哪一批、哪一条。导出前再跑一次全量格式校验，别把错误带进下游。

- [ ] 长文本已分批抽取，合并后按唯一键去重
- [ ] 输出条目数量与输入一致
- [ ] JSON 通过解析器校验，类型无误
