# 输出格式控制：表格、JSON 与结构化输出

控制输出格式的目的只有三个：能直接复制、能被人快速校验、能被程序解析。内容再对，格式散着，就等于还要手工整理一遍。

## 一、为什么值得花力气控制格式

- 可复制：固定小节和字段，可以直接贴进笔记、文档或工单。
- 可校验：字段齐不齐、类型对不对，一眼能看出来，程序也能查。
- 可处理：JSON 能被脚本直接读，省掉一次人工转录。

格式要求写在提示词结尾，紧挨着任务，别埋在长材料中间。格式约定还有一个隐性收益：它逼你在提问前想清楚自己要什么，很多含糊的需求在写格式这一步就被筛掉了。

## 二、三种轻量格式

| 格式 | 适合什么 | 不适合什么 |
| --- | --- | --- |
| Markdown 表格 | 多对象、同字段的对比和清单 | 嵌套结构、长文本 |
| 固定小节 | 有固定几个部分的说明、报告 | 字段不固定的抽取 |
| 清单 | 步骤、要点、检查项 | 需要按字段对齐的数据 |

选择原则：人读为主用表格和清单，机器读为主用 JSON。三种都要求「字段名固定、顺序固定、无多余说明」。

表格的列数控制在三到五列。列一多，模型容易把长句塞进单元格，表格反而比段落更难读。固定小节则要写明小节名称和顺序，否则每次标题都不一样，没法逐版比对。清单也要限制每条的长度，每条压到一行以内，否则清单会退化成段落。

## 三、JSON 模式与 schema 约束

- 部分模型和接口支持 JSON 模式，开启后输出保证是合法 JSON，但不保证字段符合你的预期。
- schema 描述结构：有哪些字段、什么类型、允许哪些取值、缺值怎么表示。它比「请输出 JSON」具体得多。
- 常见做法是两者叠加：先要求只输出 JSON，再在提示词里给出字段定义，接口层如果有 JSON 模式就一起开。

JSON 模式解决的是「语法合法」，schema 解决的是「语义可用」。只开 JSON 模式而不写字段定义，常会得到合法但字段名各不相同的对象，后续脚本一样跑不通。

## 四、schema 怎么写

要点：字段名用英文小写加下划线；类型写清楚；枚举值列全；空值约定统一。

```text
从下面的招聘信息中抽取字段，只输出 JSON，不要任何解释文字。
字段定义：
- title: string，职位名称
- company: string，公司名称，未提及填 null
- city: string，工作城市，未提及填 null
- min_years: number，要求的最低工作年限，未提及填 null
- skills: string[]，技能关键词，最多 5 个
- level: string，取值只能是 "junior"、"mid"、"senior" 之一，无法判断填 null
输出一个 JSON 对象，不要数组，不要代码块标记。
招聘信息：
〔粘贴文本〕
```

几条经验：枚举值不要留给模型自由发挥；数组要写清上限；空值统一用 `null`，不要一会儿空字符串一会儿「无」；明确「不要代码块标记」，否则常会带回 `json` 围栏。字段说明里别写「等」「相关信息」这类词，模型会自行扩展字段，校验时全对不上。

## 五、多余解释与解析失败

模型常会在 JSON 前后加一句「以下是抽取结果：」。处理顺序：

1. 先要求只输出 JSON，并在末尾再强调一次。
2. 给一条完整示例，展示从输入到 JSON 的样子。
3. 仍然多余时，在程序里兜底：截取第一个 `{` 到最后一个 `}` 之间的内容再解析。

解析失败的标准流程：把报错信息贴回去，连同原文和要求，让它只修复格式、不改内容，最多重试一到两次。两次还不行，就把材料拆成更短的单条输入，通常是一次抽太多字段导致结构崩掉。重试时原文必须一起带上，只贴报错，模型没有材料可改。

## 六、完整示例与校验代码

下面是抽取加校验的最小可用组合。先给提示词：

```text
从下面的文本中抽取人名、公司和职位，只输出 JSON。
字段：
- name: string，人名
- company: string，未提及填 null
- role: string，未提及填 null
规则：一人一个对象，输出数组；不要解释，不要代码块标记。
文本：
〔粘贴文本〕
```

再用一段脚本校验：

```python
import json

required = {"name": str, "company": (str, type(None)), "role": (str, type(None))}

raw = '{"name": "张三", "company": "某公司", "role": null}'

def parse(text: str):
    start, end = text.find("{"), text.rfind("}")
    if start == -1 or end == -1:
        start, end = text.find("["), text.rfind("]")
    if start == -1 or end == -1:
        raise ValueError("没有找到 JSON")
    data = json.loads(text[start:end + 1])
    items = data if isinstance(data, list) else [data]
    for item in items:
        for key, typ in required.items():
            if key not in item:
                raise ValueError(f"缺少字段：{key}")
            if not isinstance(item[key], typ):
                raise ValueError(f"字段类型不对：{key}")
    return items

print(parse(raw))
```

这段代码做三件事：从可能带杂质的文本里截出 JSON；统一成列表；逐项检查字段名和类型。真实使用时把最后的 `print` 换成写入文件或入库即可。

如果更习惯 JavaScript，思路一样：`indexOf` 和 `lastIndexOf` 截取，`JSON.parse` 解析，再遍历键检查类型。

## 速查

- 控格式为三件事：可复制、可校验、可处理。
- 人读用表格和清单，机器读用 JSON。
- schema 写清字段名、类型、枚举、空值。
- 空值统一 `null`，明确不要代码块标记。
- 有杂文字先要求，再给示例，最后程序截取。
- 解析失败贴回报错重试，最多两次。
- 抽太多字段容易崩，拆成单条重试。
