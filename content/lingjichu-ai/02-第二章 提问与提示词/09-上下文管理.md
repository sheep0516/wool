# 上下文管理：多轮对话、长文档与记忆

一次对话里模型能「看到」的内容有上限，这个上限叫上下文窗口。超过之后，早先的内容会被截断或压缩，表现就是「它忘了我前面说过的话」。管理上下文，本质是管理有限位置里放什么。

## 一、上下文窗口与 token

- 模型按 token 计量，token 是文本切出来的片段。中文大致一个字到两个 token，英文一个词约一个多 token。
- 窗口是一次对话里输入加输出的总容量。窗口越大，能一次放进去的材料越多，但不等于放进去就一定被用好。
- 计量的现实影响：贴一整本书和贴三页摘要，成本差几十倍，效果未必更好。
- 输出也占窗口。让它写长文，留给后续对话的空间会变少，长输出会挤掉前面的材料。

不必记具体数字，记住两点就够：窗口有上限；长度和效果不是线性关系。

## 二、长上下文里的信息衰减

材料一长，模型对信息的利用并不均匀。经验上：

- 开头和结尾的内容更容易被抓住，尤其是你放在最后的明确指令。
- 中间的大段材料容易被「读过但没用上」，细节尤其如此。
- 越靠后追加的指令，越可能覆盖前面的要求。

所以重要的约束不要埋在长材料中间，任务要求和格式说明放在材料之后再说一遍。

| 位置 | 被利用的概率 | 建议放什么 |
| --- | --- | --- |
| 开头 | 较高 | 角色、总任务、材料说明 |
| 中间 | 较低 | 大段原始材料，尽量精简 |
| 结尾 | 较高 | 具体指令、格式要求、验收标准 |

## 三、三种应对策略

- 滚动摘要：每聊几轮，让它把已达成的结论压缩成几条，新会话只带这份摘要。适合持续多轮的写作和讨论。
- 分段处理：长文档拆成节，一次只处理一节，最后合并。适合总结、抽取、逐段改写。
- 重开会话：任务变了就新开，把必要结论复制过去。最省事，也最容易被忽略。

三种策略也可以叠加：长文档先分段，同一段内多轮打磨时用滚动摘要，任务做完整体重开。

滚动摘要可以直接用这段：

```text
把目前为止我们达成的结论压缩成 5 条，每条一句话，只保留决定和数字，去掉过程讨论。
```

## 四、长文档的处理流程

1. 先要目录和结构：让它列出章节和每节主题，确认它读到的结构和你理解的一致。
2. 定位相关章节：只挑和问题有关的节，不要整篇反复贴。
3. 分段提问：每节单独问，问完让它用两三句复述结论，确认没跑偏。
4. 最后汇总：把各节结论贴进一个新会话，让它整合，避免在超长上下文里直接汇总。

第一步可以这样写：

```text
先不要总结。列出这份文档的章节标题和每节的主题，一句话一节。
```

这个流程的关键是「先定位再精读」。整篇丢进去问「总结一下」，得到的往往是各节都提一句的平均答案。

分段的粒度按小节走，不要细到一段一问，也不要粗到半本书一问。每段处理完留下两三句结论，汇总时只带结论，不带原文。

## 五、会话卫生与「记忆」的边界

- 一个任务一个会话。写作、查资料、改代码混在一起，上下文互相污染，模型会把上一个任务的语气带过来。
- 结论及时落盘。每轮得到可用的结论，就复制到自己的文档里。会话是工作台，不是存储。
- 「记忆」类功能不等于可靠存储。它记住的是摘要或片段，可能记错、记漏，也可能在新会话里失效。重要的事实、偏好、约束，每次该带的还是要带。
- 新会话开头花一句话复述任务和目标，比指望它自己记起来更可靠。

## 六、按场景选策略

| 场景 | 建议策略 |
| --- | --- |
| 一次性的小问题 | 直接问，不用管理 |
| 多轮写作、反复打磨 | 滚动摘要，每几轮压缩一次结论 |
| 长文档总结或抽取 | 先目录后分段，最后在新会话汇总 |
| 代码调试、连续排错 | 一个 bug 一个会话，修完把结论记下来 |
| 任务已经换方向 | 重开会话，只带必要结论 |
| 需要长期沿用的偏好 | 写进自己的模板，不依赖记忆功能 |

选择的标准很简单：这次对话还要不要接着用前面的内容。要，就控制长度；不要，就重开。

## 速查

- 上下文窗口有上限，输入输出共用。
- 长材料中间最容易被忽略，指令放结尾再说一遍。
- 三种策略：滚动摘要、分段处理、重开会话。
- 长文档先要目录，再分段问，最后新会话汇总。
- 一个任务一个会话，结论及时落盘。
- 记忆功能是摘要，不是可靠存储。
- 判断标准：这次还要不要用前面的内容。
