# 提示词的四个要素：任务、背景、约束、格式

一段提示词只要把任务、背景、约束、格式四件事说清，输出质量就稳定在一个可用的水平。四者缺一，失败方式是可预测的：缺任务会答偏，缺背景会答空，缺约束会答散，缺格式会答乱。

## 一、四个要素各管什么

- 任务：要模型做的具体动作。「写」「改」「总结」「对比」「抽取」「检查」。动词要单一。
- 背景：这件事的上下文。给谁用、什么场景、已有材料是什么、之前试过什么。
- 约束：不许做什么、必须满足什么。长度、禁用词、结构、事实来源。
- 格式：输出长什么样。字段、顺序、分隔方式。

四者分别管方向、信息、边界、形状。方向错了后面全错，形状不对则内容再好也用不上。

## 二、缺一个要素会怎样

| 缺失要素 | 典型表现 | 例子 |
| --- | --- | --- |
| 任务 | 答非所问，写成分析或建议 | 只说「看看这段代码」，它开始讲设计理念而不是找 bug |
| 背景 | 空泛、正确但无用 | 没说明读者，写出的解释既不够浅也不够深 |
| 约束 | 又长又散，什么都提一点 | 只要求「总结一下」，得到 800 字还没到重点 |
| 格式 | 内容对但没法直接用 | 要表格，给回三段散文，还得手动整理 |

这张表可以当排错清单用：输出不对时，先看缺的是哪一格。

## 三、约束要可观察、可验证

「简洁一点」「专业一些」「不要太啰嗦」这类约束无法验证，模型和你对「简洁」的标准不一样。可验证的约束是能用眼睛数出来的：

- 数字：不超过 300 字；分 3 条；每条一行；最多 2 个例子。
- 禁用词：不出现「赋能」「闭环」「助力」；不用感叹号。
- 结构：每条以动词开头；先结论后理由；不出现问句。
- 来源：只使用我提供的材料；材料里没有的写「未提及」。

约束不必多，三到五条足够，但要条条能检查。写十条模糊的约束，不如写三条能打勾的。

## 四、格式要具体到字段和顺序

「用表格」还不够，要说清几列、每列叫什么、按什么顺序。

```text
输出一张 Markdown 表格，三列，顺序固定为：问题、原因、修改建议。
每个问题占一行，原因不超过 30 字，修改建议给出可直接替换的写法。
表格之外不要写任何解释。
```

格式说清楚的好处是双重的：模型不用猜，你拿到就能用，也方便后面复制到文档或程序里。格式只写到「表格」「清单」这个层级，等于没写。

## 五、第五个要素：示例

示例的作用是把「约束」里说不清的部分演示出来，尤其是语气、颗粒度和判断标准。一条好的示例，胜过五句形容词。

```text
按下面的风格改写，示例：
原句：这个功能主要是为了提升用户体验。
改写：把提交按钮从页面底部移到表单右侧，用户少滚动一次。
只保留可核对的事实，去掉「提升」「主要」这类模糊修饰。
```

示例有两点要注意：一是要短，二是要和任务同类型。给一个无关领域的例子，模型学到的只是格式，学不到判断。

## 六、从模糊需求到四要素齐全

原句：「帮我写个周报。」

| 要素 | 改写后 |
| --- | --- |
| 任务 | 写一段本周工作周报 |
| 背景 | 我是后端实习生，本周做了接口联调和日志排查，读者是带我的导师 |
| 约束 | 200 字以内；只写完成的事和遇到的问题；不写计划；不用「持续推进」这类空话 |
| 格式 | 两个小节「已完成」「待解决」，每节用 `-` 列 2 到 3 条 |

```text
写一段本周工作周报。我是后端实习生，本周做了接口联调和日志排查，读者是我的导师。
要求：200 字以内，只写已完成的事和遇到的问题，不写计划，不用「持续推进」这类空话。
格式：两个小节「已完成」「待解决」，每节用 - 列 2 到 3 条。
```

关于长度：提示词不是越长越好，关键是单位长度里的信息量。删掉「请你作为一名资深专家」「这对我非常重要」这类不改变输出的句子，留下能影响结果的数字、边界和示例。

三种常见反模式：

- 礼貌废话：请、麻烦、非常感谢堆在前面，对输出没有任何影响，只是占位置。
- 形容词堆砌：专业、深度、高质量、有洞察，没有一条能验证，模型只能自由发挥。
- 多个任务混在一起：「先总结再翻译再列成表格」，容易只做其中一件，拆成两轮更稳。

## 速查

- 四要素：任务、背景、约束、格式。
- 缺任务答偏，缺背景答空，缺约束答散，缺格式答乱。
- 约束要能数出来、能打勾，三到五条足够。
- 格式写到列名和顺序。
- 示例用来演示语气和颗粒度，短且同类型。
- 删礼貌废话和无效形容词，保留数字与边界。
- 多个任务拆成多轮。
