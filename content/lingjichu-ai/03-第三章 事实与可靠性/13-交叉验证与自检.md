# 让模型自检与交叉验证

自检的价值在于暴露不确定，而不是获得保证。让模型检查自己的输出，能发现逻辑矛盾、遗漏和表述问题，但无法凭空产生它没有的事实。把它当作筛子，不当作证据。

## 一、自检不是让模型说「我确定」

模型对自己的回答没有独立的验证通道。它读到的是自己刚生成的文本，判断依据仍是同一套参数。因此，问「你确定吗」通常只会得到一个更笃定的版本，或者一个没有依据的改口。

有效的自检要改变任务：从「判断对错」改成「列出风险」。让模型做它擅长的事，例如分类、列举、对照清单、寻找反例，而不是让它为自己的事实背书。

## 二、四类自检提示词

- 列不确定点：要求标出回答中最没把握的部分，并说明缺什么信息。
- 给反例：要求举出与结论相反的情形，检验结论是否被过度推广。
- 按清单打分：给出明确维度，让它逐项评估，避免笼统的「很好」。
- 标出需外部验证的句子：把事实性内容单独摘出，交给人工核查。

可以合并成一段模板：

```text
请审查你上面的回答，不要重写，只输出以下四项：
1. 不确定清单：列出 3 至 5 个你最没把握的判断，说明原因。
2. 反例：给出至少 2 个能让结论不成立的情形。
3. 评分：按「结构完整、逻辑一致、事实可查、边界清楚」各 1 至 5 分打分，并说明扣分点。
4. 待验证句：逐句摘出所有需要外部来源才能确认的内容。
```

## 三、多次采样看分歧

同一个问题问三遍，比较答案的差异。做法可以是新开会话、改写问法，或在支持时调高随机性。三次都一致的内容相对稳定，出现分歧的地方就是风险点。

| 分歧类型 | 表现 | 含义 |
| --- | --- | --- |
| 事实细节不同 | 数字、日期、人名不一致 | 高幻觉风险，必须查来源 |
| 表述不同但事实一致 | 顺序、措辞变化 | 通常可接受 |
| 一方拒答、一方作答 | 一处说不知道，一处给具体值 | 具体值可疑 |
| 结构差异大 | 分类方式、步骤数量不同 | 说明任务定义不清 |

分歧不是判决，而是排序：先查分歧最大的部分，往往能用最少时间排除最多错误。

## 四、换角色审稿与拆子问题

换一个身份重读，能激活不同的检查角度。

- 审稿人：只找错误和漏洞，逐段挑刺，不负责润色。
- 反方：假设结论是错的，寻找支持相反结论的证据和逻辑。
- 目标读者：判断是否看得懂、会不会被误导、缺哪些前提。

把一个笼统问题拆成可独立检验的子问题，也能提高可靠性。例如「这个方案可行吗」可以拆成成本、依赖、风险、替代方案四个子问题，分别核对事实与假设。子问题越具体，越容易发现哪一环是空的。

## 五、模型互审的局限

让另一个模型审稿，看起来像交叉验证，实际上有三个问题。

- 同源偏差：主流模型的训练数据高度重叠，会共享同一批错误和盲区。
- 互相附和：模型倾向同意上下文中已有的判断，尤其当原文语气笃定时。
- 无法产生新证据：互审只能比较表述和逻辑，不能确认真实世界的数字与事件。

所以互审适合检查结构、逻辑、遗漏和表达，不适合替代外部来源。两个模型都说对的内容，仍然可能一起错。哪些任务适合自检，差别也很明显。

| 适合自检 | 不适合自检 |
| --- | --- |
| 结构完整性、逻辑一致性 | 最新事实、实时数据 |
| 遗漏项、边界条件列举 | 专有数据、内部指标 |
| 表达清晰度、术语统一 | 法律、医疗、财务结论 |
| 代码的静态问题、命名一致 | 需要实测的性能数字 |

## 六、10 分钟自检流程

1. 圈出所有事实性断言，按影响排序，只保留前 3 至 5 条重点核查。
2. 用自检模板让模型列不确定点、反例和待验证句。
3. 同一关键问题换问法再问一次，记录与首次回答的分歧。
4. 对分歧点和待验证句，检索一手来源确认。
5. 换审稿人角色通读一遍，检查逻辑跳步和被忽略的前提。
6. 把确认结果写回正文，删除或弱化无法证实的部分。

这套流程不能保证内容正确，但能把「看起来对」和「查过是对的」分开。

## 检查清单

- [ ] 自检是否要求列风险，而不是要求保证
- [ ] 是否标出了不确定点和待验证句
- [ ] 是否让模型给出了反例
- [ ] 关键问题是否换了问法再问一次
- [ ] 分歧点是否优先核查
- [ ] 是否用审稿人或反方视角通读过
- [ ] 互审结论是否仍用外部来源确认
- [ ] 无法证实的部分是否已处理
