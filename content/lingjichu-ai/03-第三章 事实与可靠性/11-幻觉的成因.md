# 幻觉：为什么它会一本正经地编

大模型的幻觉不是偶发的程序缺陷，而是生成方式的必然副产品：它按概率续写最像答案的文本，并不查询事实。语言越流畅、细节越具体，越不代表内容为真。使用时的默认规则是：任何具体事实都先当作假设。

## 一、幻觉是什么，不是什么

幻觉指模型生成了语言通顺、格式规范，但事实错误或没有可核实来源的内容。它通常不是乱码，也不是一眼可见的胡扯，而是把错误藏在最像正确答案的位置。

它与普通错误有区别。普通错误包括理解偏差、算错数、答非所问，用户容易察觉，也能通过追问纠正。幻觉的特征是形式完整、细节具体、语气笃定：编造的人名配有头衔，编造的论文配有期刊和年份，编造的 API 配有参数说明。错误越像真的，越难被发现。

判断标准只有一条：这句话能否被独立来源证实。模型自己的保证不算证据。

## 二、生成机制为什么会编

理解成因，才能判断哪里该防。

- 按概率续写。模型逐词预测下一个最可能的词。它的目标是「像正确答案」，不是「是正确答案」。当真实信息缺失时，最像答案的文本仍然会被生成出来。
- 没有内建事实数据库。参数里存的是训练语料的统计规律，不是可检索的记录。模型无法可靠区分「我记得」与「我编得像」。
- 训练数据有缺口。冷门人物、最新事件、地区性规定、长尾细节覆盖不足，空缺处会被相似的模式填补。
- 对齐训练带来顺从倾向。人类反馈训练奖励「有用、配合」的回答，模型因此更愿意给出用户期待的答案，而不是承认不知道。
- 上下文诱导。如果问题预设了错误前提，例如「某公司 2023 年上市后股价如何」，模型往往顺着前提继续编，而不是指出前提有误。

## 三、高发场景

不同任务的风险差别很大。以下场景应默认提高警惕。

| 场景 | 典型表现 | 风险 | 处理方式 |
| --- | --- | --- | --- |
| 人名与履历 | 补齐头衔、学历、任职时间 | 高 | 查本人主页或机构官网 |
| 数字与统计 | 精确到小数点的比例、市场规模 | 极高 | 找原始报告核对口径 |
| 文献与法条 | 标题、作者、期刊、条款编号齐全 | 极高 | 检索原文，核对编号 |
| API 用法 | 函数名、参数混搭不同版本 | 中高 | 查对应版本官方文档 |
| 时间与地点 | 事件年份、地点、先后顺序 | 中 | 两个以上来源交叉比对 |
| 冷门知识 | 小众工具、地方政策、行业惯例 | 高 | 默认不可靠，必须查证 |

规律是：越具体、越冷门、越新、越需要精确编号的内容，幻觉率越高。反过来，常识性解释、思路梳理、文本改写通常较稳。

## 四、可识别的信号

幻觉不能靠「感觉不对」识别，要靠结构特征。

- 细节异常具体：精确到小数点后两位、完整的页码、完整的 DOI，却不给来源。
- 来源含糊：使用「根据某研究」「业内普遍认为」「数据显示」这类无法追溯的表述。
- 前后矛盾：同一段里数字对不上，时间线打架，人物关系冲突。
- 被质疑后改口，但依然自信：不给理由，直接换一个说法，语气不变。
- 只回答「是什么」，不回答「怎么知道」。追问来源时，回答变得更模糊或更具体，两者都危险。
- 引用格式过于整齐：真实文献的引用常有细节差异，编造的引用反而格式完美。

## 五、语气自信与可靠性无关

模型的自信来自语言模式，不来自事实核查。生成过程中，它计算的是下一个词的概率，不是这句话为真的概率。流畅、笃定、条理清晰，只说明这段文本符合训练语料中的表达习惯。

因此，「它说得很有把握」不能作为采信理由。同一个模型可以在常识问题上非常可靠，在引用编号上稳定出错，两者互不影响。

使用者应默认遵守的规则：

- 把具体名词当作待核实项：人名、机构、数字、日期、引用、链接、条款编号。
- 要求模型标注来源，并自己打开来源确认，不把「它给了链接」当作已核实。
- 需要精确事实时，先检索再提问，或让模型只基于你提供的材料回答。
- 交付前逐条核对关键断言，宁可删掉一句，也不留下无法证实的细节。

需要模型自查时，可以用下面的提示词先暴露风险：

```text
请逐句检查你上面的回答，只做三件事：
1. 列出所有具体事实断言（人名、数字、日期、引用、条款、API 名称）。
2. 对每一条标注：有可靠来源 / 仅凭记忆 / 无法确认。
3. 把「仅凭记忆」和「无法确认」的条目单独列出，并说明需要查什么来源才能确认。
不要重写答案，不要为不确定的内容补充细节。
```

## 检查清单

- [ ] 我是否把每句具体事实都当成待核实项
- [ ] 人名、机构、头衔是否查过一手来源
- [ ] 数字是否核对了口径、单位和时间范围
- [ ] 文献与条款是否检索到原文
- [ ] API 用法是否对照了对应版本文档
- [ ] 我是否因为语气自信而放松了核查
- [ ] 无法证实的细节是否已删除或改为定性表述
- [ ] 交付前是否留下了核查记录
