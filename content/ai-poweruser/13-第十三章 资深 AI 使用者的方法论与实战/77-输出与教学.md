# 输出与教学

本节说明如何通过写案例、做复盘和教学，把经验固化并检验自己的理解。

## 4.1 输出的作用

输出不只是分享，更是检验：

1. 能不能把做法讲清楚，说明是否真正理解。
2. 能不能说出失败情况，说明是否知道边界。
3. 能不能让别人复现，说明步骤是否完整。
4. 能不能解释为什么这样做，说明是否有判断依据。

写不出来，通常不是文笔问题，而是理解有缺口。

## 4.2 案例写法

一个可复用的案例包含：

```
背景：什么场景，为什么要做
任务：具体目标与成功标准
工具：用了哪些模型、平台、插件
做法：提示词或工作流的关键步骤
结果：实际产出与效果，尽量量化
失败：出过什么问题，如何发现
改进：改了什么，下次怎么做
成本：时间、费用、人工复核
```

重点是失败与改进。只写成功过程的案例，对他人帮助有限。

## 4.3 复盘写法

复盘比案例短，聚焦一次具体执行：

| 项目 | 内容 |
|---|---|
| 目标 | 这次想完成什么 |
| 实际 | 实际发生了什么 |
| 差距 | 哪里符合预期，哪里不符合 |
| 原因 | 数据、提示词、工具、流程还是判断 |
| 改进 | 下次具体改什么 |
| 验证 | 如何确认改进有效 |

复盘应在一个任务结束后尽快写，隔太久细节会丢失。

## 4.4 教学方式

教别人时，顺序与自学不同：

1. 先讲边界。能做什么、不能做什么、什么时候不要用。
2. 再讲一个真实案例，完整演示输入到输出。
3. 讲一个失败案例，说明如何发现与处理。
4. 让对方动手做一遍，不要只看演示。
5. 给出检查表，让对方能自查。
6. 收集对方遇到的问题，作为下一版材料的输入。

只讲技巧不讲边界，学习者会在不适合的场景强行使用，出错后放弃。

## 4.5 输出的频率

不需要写长文。可以采用：

- 每周：一条复盘，记录一次成功或失败。
- 每月：一个完整案例，包含背景、做法、结果、失败与改进。
- 每季度：整理一次案例库，删除过时内容，补充新案例。

持续的小输出比偶尔的长文更有效。

## 4.6 常见问题

1. 只写成功，不写失败，读者无法判断边界。
2. 只贴提示词，不写输入要求与前置条件。
3. 结果没有量化，无法判断是否真的有效。
4. 教程只有演示，没有练习与检查表。
5. 内容过时，模型或工具已经变化。
6. 为了分享而分享，没有经过自己的实际验证。

## 4.7 小结

- 输出的作用是检验理解、暴露边界、让别人可复现、说明判断依据。
- 案例包含背景、任务、工具、做法、结果、失败、改进和成本。
- 复盘聚焦目标、实际、差距、原因、改进和验证。
- 教学先讲边界，再讲案例与失败，让学习者动手，并提供检查表。
- 输出频率可以是每周复盘、每月案例、每季度整理。
- 常见问题是只写成功、缺输入要求、结果未量化、内容过时和未经实测。
