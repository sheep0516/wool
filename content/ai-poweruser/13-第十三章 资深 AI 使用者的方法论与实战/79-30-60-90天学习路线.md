# 30-60-90 天学习路线

本节把前面的章节压缩成三个阶段，每个阶段都有明确的产出。

## 6.1 总体安排

| 阶段 | 时间 | 目标 | 产出 |
|---|---|---|---|
| 第一阶段 | 第 1 到 30 天 | 建立认知与基础工具 | Prompt 库、事实核查清单 |
| 第二阶段 | 第 31 到 60 天 | 建立知识与流程能力 | 个人知识库、一个工作流 |
| 第三阶段 | 第 61 到 90 天 | 搭建与复盘 | 两个 Agent、一个自动化项目、案例复盘 |

判断标准不是"看完了多少章"，而是"有没有可运行的产出"。

## 6.2 第一个 30 天

对应章节：第1章、第2章、第3章、第4章。

周安排：

| 周 | 内容 | 产出 |
|---|---|---|
| 第1周 | 概念层级、模型分类、能力边界 | 一页概念笔记 |
| 第2周 | 幻觉与事实校验 | 一份核查清单 |
| 第3周 | Prompt 四要素、结构化模板 | 5 个常用模板 |
| 第4周 | Few-shot、输出格式、Prompt 库 | 分类整理的个人 Prompt 库 |

验收：

- 能说清 AI、机器学习、生成式 AI、大模型的包含关系。
- 能判断一个任务适合用什么档位的模型。
- 有一份可执行的事实核查清单。
- Prompt 库至少有 10 个模板，每个附适用场景与失败案例。

## 6.3 第二个 30 天

对应章节：第5章、第6章、第7章、第8章。

周安排：

| 周 | 内容 | 产出 |
|---|---|---|
| 第5周 | 上下文管理、长文档处理 | 一套分段与索引方法 |
| 第6周 | RAG 与个人知识库 | 20 到 50 份文档的知识库 |
| 第7周 | 工具调用与 MCP | 一个接入搜索或文件工具的助手 |
| 第8周 | 工作流基础与一个场景 | 一条可运行的工作流 |

验收：

- 知识库能用 20 条测试问题通过基本评估。
- 无答案问题不编造，引用可核对。
- 工具调用失败时有明确提示，不编造结果。
- 工作流有日志、失败处理和一个人工确认点。

## 6.4 第三个 30 天

对应章节：第10章、第11章、第12章、第13章。

周安排：

| 周 | 内容 | 产出 |
|---|---|---|
| 第9周 | 需求定义、四组件、单 Agent | 第一个 Agent |
| 第10周 | 测试、发布、迭代 | 测试集与版本记录 |
| 第11周 | 第二个 Agent 或自动化项目 | 第二个 Agent 或一条自动化流程 |
| 第12周 | 评估、成本、安全、复盘 | 案例复盘与作品集片段 |

验收：

- 两个 Agent 能跑通完整任务，不只是演示。
- 有 20 条测试问题与回归记录。
- 高风险操作有确认环节，敏感数据有处理方案。
- 至少一份完整案例，包含失败点与改进。

## 6.5 时间投入

每天 30 到 60 分钟，周末可集中做项目。三个阶段合计约 45 到 90 小时。

如果时间不足，优先保证产出，而不是按章节顺序读完：

1. 先做 Prompt 库与核查清单。
2. 再做知识库与一个工作流。
3. 最后做 Agent 与复盘。

## 6.6 常见问题

1. 只读不练，三个月后没有可运行的产出。
2. 同时开始多个项目，每个都停在演示阶段。
3. 追求工具数量，没有一条流程真正跑通。
4. 跳过测试与复盘，上线后问题反复出现。
5. 用高风险场景做第一个项目，出错后放弃。
6. 没有记录，无法判断是否真的进步。

## 6.7 小结

- 第一阶段建立认知与基础工具，产出 Prompt 库与核查清单。
- 第二阶段建立知识库与工作流，产出可评估的知识库和一条流程。
- 第三阶段搭建两个 Agent 与一个自动化项目，并完成案例复盘。
- 每天 30 到 60 分钟，总计约 45 到 90 小时。
- 时间不足时优先保证产出，而不是按章节顺序读完。
- 判断标准是可运行的产出与复盘记录，而不是阅读进度。
