# 个人 AI 工作流盘点

本节说明如何找出值得改造的任务，并按收益与可行性排序。

## 1.1 盘点方法

连续记录一周的工作，按以下字段整理：

| 字段 | 说明 |
|---|---|
| 任务 | 具体动作，不用"办公"这类模糊描述 |
| 频率 | 每天、每周、每月几次 |
| 单次耗时 | 分钟或小时 |
| 重复性 | 步骤是否每次相同 |
| 输入 | 材料从哪来，格式是否稳定 |
| 输出 | 交付给谁，格式要求 |
| 错误代价 | 出错后是否可修复 |

记录时不要只写"用了 AI 的任务"，也要写"还没用 AI 但很耗时的任务"。后者往往收益更大。

## 1.2 常见的十类任务

| 类别 | 例子 |
|---|---|
| 信息收集 | 找资料、追新闻、整理竞品 |
| 阅读与总结 | 长文档、报告、课程 |
| 写作 | 邮件、方案、文案、周报 |
| 改写与校对 | 润色、改语气、查错 |
| 会议 | 记录、纪要、待办 |
| 数据整理 | 表格清洗、格式转换、汇总 |
| 分类与归档 | 文件归类、工单分流 |
| 查询与答疑 | 制度、产品、流程问题 |
| 汇报 | 周报、月报、数据解读 |
| 重复操作 | 跨系统录入、通知、提醒 |

多数人的高频任务集中在前六类。

## 1.3 收益与可行性评分

对每个任务按两个维度打分，1 到 5 分：

收益：

- 时间节省。每周能省多少小时。
- 质量提升。是否减少错误、提升一致性。
- 覆盖人数。只影响自己，还是也影响同事。

可行性：

- 数据是否可用。输入是否稳定、是否敏感。
- 工具是否具备。现有工具能否完成。
- 风险是否可控。错误是否可修复、是否需要人工确认。
- 维护是否可持续。是否需要长期投入。

收益与可行性相乘，得到优先级分数。

## 1.4 四象限

| 象限 | 特征 | 处理 |
|---|---|---|
| 高收益、高可行 | 高频、输入稳定、风险低 | 优先改造 |
| 高收益、低可行 | 价值大，但数据敏感或工具不足 | 先解决前提条件 |
| 低收益、高可行 | 容易做，但节省有限 | 有空再做 |
| 低收益、低可行 | 价值小、成本高 | 不做 |

第一个改造对象应落在"高收益、高可行"象限，且步骤少、错误可修复。

## 1.5 选择第一个任务

优先选择满足以下条件的任务：

1. 每周至少发生三次。
2. 步骤固定，输入格式稳定。
3. 出错后能快速发现并修正。
4. 三到五步可以跑通闭环。
5. 不需要访问敏感数据。

例如"每周把会议记录整理成待办"，比"自动处理客户合同"更适合作为起点。

## 1.6 定期复盘

每月重新盘点一次：

1. 已完成改造的任务，实际节省了多少时间。
2. 哪些任务仍然手工完成，原因是什么。
3. 是否有新出现的高频任务。
4. 原有任务的优先级是否变化。

盘点的作用是让改造顺序跟着实际工作变化，而不是一次定死。

## 1.7 小结

- 盘点要记录频率、耗时、重复性、输入输出和错误代价。
- 常见高频任务是信息收集、阅读总结、写作、改写、会议、数据整理。
- 按收益与可行性各打 1 到 5 分，相乘得到优先级。
- 高收益高可行的任务优先改造，低收益低可行的不做。
- 第一个任务应高频、步骤固定、错误可修复、不涉及敏感数据。
- 每月重新盘点，根据实际节省与工作变化调整顺序。
