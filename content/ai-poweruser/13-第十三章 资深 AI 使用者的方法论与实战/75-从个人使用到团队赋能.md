# 从个人使用到团队赋能

本节说明把个人经验转成团队可用的方法，包括 SOP、模板、共享知识库和培训方式。

## 2.1 个人与团队的差别

个人使用时，规则可以留在自己脑子里；团队使用时，必须写下来。差别集中在四点：

| 维度 | 个人 | 团队 |
|---|---|---|
| 标准 | 自己知道就行 | 需要统一，可检查 |
| 权限 | 自己决定 | 需要分级与审批 |
| 维护 | 自己负责 | 需要明确责任人 |
| 培训 | 边用边学 | 需要材料与练习 |

直接把个人提示词发给同事，通常无法复现效果，因为缺少上下文、输入要求和失败处理。

## 2.2 写 SOP

一份可用的 SOP 包含：

```
目的：解决什么问题
适用范围：哪些任务适用，哪些不适用
前置条件：需要哪些权限、资料、工具
步骤：按顺序写清每一步做什么
输入输出：每步需要什么，产出什么
检查点：每步如何确认完成
失败处理：常见失败及应对
责任人：谁维护、谁审核
版本：当前版本与修改记录
```

SOP 不是越详细越好。步骤要能让没做过的人照着执行，同时保留判断空间。

## 2.3 做模板

需要沉淀的模板有三类：

1. 提示词模板。包含角色、任务、上下文、输出格式、失败处理。
2. 工作流模板。包含触发、步骤、分支、人工确认、日志。
3. 检查表。包含交付前必须核对的项。

模板要附一个真实示例和至少一个失败案例。只有成功示例的模板，使用者遇到边界情况时不知道怎么办。

## 2.4 共享知识库

团队知识库与个人知识库的差别：

1. 权限分级。按部门、项目、密级划分。
2. 更新责任。每类资料有明确维护人。
3. 版本管理。旧版本标注废止，不参与默认检索。
4. 命名统一。按日期、类型、主题、版本命名。
5. 审核流程。对外资料需要审核后入库。
6. 使用说明。写清适用范围与引用方式。

知识库没有维护人，通常会在几个月内失效。

## 2.5 培训方式

有效的培训不是演示成功案例，而是讲清边界。

建议结构：

1. 这个工具能做什么，不能做什么。
2. 一个真实案例，从输入到输出完整演示。
3. 一个失败案例，说明哪里会出错、如何发现。
4. 让学习者自己动手做一遍。
5. 给出检查表，让他们能自查。
6. 留下反馈渠道，收集他们遇到的问题。

只讲技巧不讲边界，会让使用者在不适合的场景强行使用，出错后不再信任工具。

## 2.6 推广节奏

1. 种子用户。先找三到五个愿意尝试的同事。
2. 小范围验证。用真实任务跑一到两周。
3. 收集问题。记录失败案例与使用障碍。
4. 修订 SOP 与模板。
5. 扩大范围。按部门或项目逐步推广。
6. 建立支持渠道。有人负责答疑与维护。

一次全量推广，问题会集中爆发且无人处理。

## 2.7 常见问题

1. 只发提示词，不给输入要求与失败处理。
2. SOP 写得过于抽象，新人无法执行。
3. 知识库没有维护人，逐渐过期。
4. 培训只演示成功案例，学员遇到失败就放弃。
5. 权限过宽，敏感资料对全员可见。
6. 没有反馈渠道，问题无法回流。
7. 推广过快，支持能力跟不上。

## 2.8 小结

- 个人经验转团队使用，需要统一标准、分级权限、明确责任和培训材料。
- SOP 包含目的、范围、前置条件、步骤、输入输出、检查点、失败处理和责任人。
- 模板分提示词、工作流和检查表三类，每类附真实示例与失败案例。
- 共享知识库要有权限分级、更新责任、版本管理、统一命名、审核流程和使用说明。
- 培训要讲边界与失败案例，并让学习者动手。
- 推广按种子用户、小范围验证、修订、扩大的顺序进行。
