# 建立个人 Prompt 库

本节说明如何把零散的提示词整理成可复用、可迭代的个人库。

## 7.1 为什么要建库

每次从零写 Prompt，会遇到三个问题：

1. 重复劳动。同类任务反复写相似的结构。
2. 无法比较。没有固定模板，输出差异无法判断是模型问题还是提示词问题。
3. 经验流失。某次效果好的写法没有记录，下次想不起来。

个人 Prompt 库的作用是把有效写法固定下来，并把失败案例积累成改进依据。

## 7.2 分类方式

按使用场景分类，比按模型或工具分类更稳定：

| 类别 | 典型场景 |
|---|---|
| 学习 | 概念讲解、资料总结、题目练习、错题分析 |
| 写作 | 文章初稿、改写润色、提纲、标题 |
| 办公 | 邮件、会议纪要、周报、方案 |
| 分析 | 数据解读、竞品对比、方案评审、风险清单 |
| 生活 | 行程规划、购物对比、信息查询、决策辅助 |

每一类下面再按具体任务细分。分类不宜过细，否则检索成本高于复用收益。

## 7.3 每个模板记录什么

| 字段 | 内容 |
|---|---|
| 名称 | 能一眼看出用途，例如"会议纪要转待办" |
| 适用场景 | 什么情况下用，解决什么问题 |
| 不适用场景 | 什么情况下不要用 |
| 输入要求 | 需要提供哪些材料、格式、篇幅 |
| Prompt 正文 | 完整模板，用方括号标注占位符 |
| 输出样例 | 一次真实输出，便于对比 |
| 失败案例 | 出过什么问题，原因是什么 |
| 版本 | 第几版，改了什么 |
| 使用模型 | 在哪个模型上测试过 |
| 参数设置 | 温度、输出格式等 |
| 效果记录 | 通过率、常见问题 |

字段不必全部填写，但"适用场景""Prompt 正文""失败案例"三项建议保留。

## 7.4 单个模板的写法

一个模板文件可以按以下结构组织：

```
# 模板名称

## 适用场景
……

## 输入要求
……

## Prompt
（完整模板）

## 输出样例
（一次真实输出）

## 失败案例
- 问题：
- 原因：
- 修改：

## 版本记录
- v1：初始版本
- v2：增加不确定标注规则
```

关键是把"失败案例"和"版本记录"写下来。只保存成功模板，无法知道它的边界在哪里。

## 7.5 目录与命名

建议的目录结构：

```
Prompt 库/
├── 学习/
├── 写作/
├── 办公/
├── 分析/
└── 生活/
```

文件命名用"任务 + 用途"，例如"会议纪要转待办.md"、"长文三段总结.md"。避免"提示词1""测试2"这类无法检索的名称。

如果使用笔记软件，可以用标签补充场景、模型、状态，但目录分类仍然是基础。

## 7.6 维护机制

1. 每周复盘。把本周用过且有效的 Prompt 收进库，把失败的记入失败案例。
2. 版本记录。修改模板时保留旧版本，注明修改原因。
3. 定期清理。半年未使用、且没有复用价值的模板可以归档。
4. 换模型后重测。同一模板在不同模型上的表现不同，需要更新效果记录。
5. 脱敏。库中的示例要去掉真实姓名、电话、金额、客户信息。

## 7.7 常见问题

1. 只收藏不整理。存了大量 Prompt，但没有分类和说明，实际使用时找不到。
2. 只存成功案例。没有失败记录，无法判断模板的适用边界。
3. 模板过长。把多个任务塞进一个模板，复用时需要大量删改。
4. 缺少输入要求。换一份材料就失效，因为不知道模板依赖哪些前提。
5. 不记录模型。换模型后效果下降，却不知道原因。

## 7.8 小结

- Prompt 库的价值是减少重复劳动、支持对比、积累经验。
- 按学习、写作、办公、分析、生活分类，比按工具分类更稳定。
- 每个模板至少记录适用场景、Prompt 正文和失败案例。
- 模板文件应包含输入要求、输出样例、失败原因和版本记录。
- 维护靠定期复盘、版本管理和换模型重测。
- 只收藏不整理、只存成功案例，是建库最常见的失效方式。
