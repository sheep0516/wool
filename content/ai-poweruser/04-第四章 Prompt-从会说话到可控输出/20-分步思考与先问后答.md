# 分步思考与先问后答

本节说明复杂任务为什么要拆开执行，以及"先澄清、再列提纲、分块完成、最后合并"的具体做法。

## 4.1 为什么复杂任务不宜一次完成

一次性让模型完成复杂任务，常见问题：

1. 遗漏。长输出中容易漏掉要求中的某一项。
2. 结构混乱。多个目标混在一起，层次不清。
3. 错误累积。前面的错误结论被后面继续引用。
4. 难以校验。输出是一大段文字，无法逐项检查。
5. 修改成本高。改一处往往需要重写整段。

分步执行的目的，是把一个不可校验的大任务，拆成若干可校验的小任务。

## 4.2 先问后答

当需求本身不清楚时，不要让模型直接执行，先让它提问。

写法：

```
在开始之前，请先列出完成这个任务还需要确认的信息，最多 5 条，按重要性排序。
不要开始写正文。
```

模型会给出需要澄清的点，例如受众、篇幅、用途、必须包含的内容、禁止内容。用户回答后，再进入执行。

适用场景：

- 任务目标模糊，例如"帮我写个方案"。
- 材料不完整，缺少关键背景。
- 输出用途不明确。

不适用场景：

- 任务已经足够明确，再提问只是拖延。
- 需要快速得到初稿，用于讨论方向。

提问清单本身也可以模板化，例如固定询问"读者是谁、用于什么场合、篇幅上限、必须包含、禁止出现"。

## 4.3 提纲、分块、合并

复杂写作或分析任务，通常分三步：

### 第一步：列提纲

```
先不要写正文。根据以下要求，给出文章提纲：
- 目标读者
- 每一部分的核心论点
- 每部分需要的材料或数据
- 预计篇幅
```

提纲确认后再继续，可以避免整篇写完才发现结构不对。

### 第二步：分块执行

```
按提纲第 2 部分写正文，约 400 字。
只使用我提供的材料，不要引用其他部分的内容。
```

分块执行的好处是每块都能单独检查，出错时只需重写该块。

### 第三步：合并与统一

```
把以下各部分合并成一篇完整文章。
检查并修正：
1. 术语是否统一
2. 前后结论是否矛盾
3. 是否有重复内容
4. 过渡是否自然
5. 总字数是否符合要求
输出合并稿，并列出修改点。
```

合并阶段最容易出现前后矛盾、术语不一致和重复，需要专门检查。

## 4.4 分步不等于展示思维链

"分步思考"有两种含义：

- 任务分步：把工作拆成多个可验收的步骤，由人控制流程。
- 模型内部推理：让模型在回答前生成长推理过程。

第二种对推理模型并非必需，部分模型已内置推理，额外要求"逐步思考"可能只增加 token 消耗。第一种才是日常工作中更可靠的做法。

## 4.5 检查点设计

每一步都应设定可验收的检查点：

| 步骤 | 检查点 |
|---|---|
| 澄清 | 是否覆盖了受众、用途、篇幅、禁忌 |
| 提纲 | 结构是否完整，论点是否对应目标 |
| 单块 | 是否只用了指定材料，字数是否达标 |
| 合并 | 术语、结论、格式是否统一 |

检查点不通过时，回到该步骤修改，不要带着问题进入下一步。

## 4.6 常见问题

1. 过度拆分。步骤太细，每步都要重复上下文，成本高且容易丢失信息。
2. 信息丢失。分块执行时，后一块不知道前一块的结论，导致重复或矛盾。
3. 上下文超限。多轮分步累积过多内容，早期材料被挤出窗口。
4. 缺少统一标准。各块由不同提示词生成，风格不一致。
5. 把分步当成万能。简单任务分步只会增加往返次数。

处理方式：在每一步的开头附上必要的前置结论摘要，而不是全文；合并阶段统一做一致性与风格检查。

## 4.7 小结

- 复杂任务一次完成容易遗漏、混乱、难以校验，分步是为了产生可检查的中间产物。
- 需求不清时先让模型提问，提问清单可以模板化。
- 写作与分析常用"提纲—分块—合并"三步。
- 任务分步与模型内部思维链是两件事，前者更可控。
- 每步设置检查点，问题不带入下一步。
- 分步要适度，并注意上下文传递与风格统一。
