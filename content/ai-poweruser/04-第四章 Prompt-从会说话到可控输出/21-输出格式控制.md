# 输出格式控制

本节说明如何让模型稳定输出可解析、可校验、可直接进入下一步的格式。

## 5.1 为什么需要控制格式

生成式模型的默认行为是"写一段通顺的文字"，而不是"输出一个结构化对象"。不加约束时，常见结果包括：格式每次不同、附带多余解释、字段缺失、单位不统一。

控制格式有三个目的：

1. 可校验。字段和类型固定后，可以用程序检查。
2. 可衔接。输出能直接进入表格、数据库、工作流或下游模型。
3. 可比较。同一结构下，多次输出才能逐项对比。

## 5.2 常见格式与适用场景

| 格式 | 适用 | 风险 |
|---|---|---|
| 表格 | 多条目、多属性对比 | 列数过多时可读性下降，单元格内换行易错 |
| JSON | 程序消费、字段固定 | 模型可能附带说明文字，导致解析失败 |
| 清单 | 步骤、检查项、要点 | 层级过深时结构不清 |
| 评分卡 | 多维评估、打分 | 分值标准不明确时结果不可比 |
| 对比矩阵 | 多方案、多维度比较 | 维度定义不一致时结论失真 |

选择格式的原则：给人看用表格或清单，给程序用 JSON，做决策用评分卡或对比矩阵。

## 5.3 表格与对比矩阵

表格要写清列名、顺序和单元格规则：

```
输出为 Markdown 表格，列依次为：方案、优点、缺点、适用条件、风险。
每格不超过 40 字；不确定的内容写"待确认"；不要合并单元格。
```

对比矩阵要先定义维度，再定义评分口径：

```
维度固定为：成本、实施难度、可维护性、风险。
每个维度按 1 到 5 分打分，并给出一句理由。
分数标准：1 最差，3 中等，5 最好。
```

没有评分口径时，模型给出的分数没有可比性。

## 5.4 JSON 与字段定义

JSON 的关键不是"要求输出 JSON"，而是定义每个字段的含义、类型和空值规则。

```
输出严格 JSON，不要包含解释文字，不要使用 Markdown 代码块标记。
字段定义：
- title：字符串，材料标题，找不到填 null
- date：字符串，格式 YYYY-MM-DD，找不到填 null
- amount：数字，单位元，保留两位小数
- category：枚举值，只能是["合同","发票","报告","其他"]之一
- confidence：数字，0 到 1，表示抽取把握
```

常见问题及处理：

| 问题 | 处理 |
|---|---|
| 输出前后带说明文字 | 明确"只输出 JSON"，并在解析前截取第一个 { 到最后一个 } |
| 字段缺失 | 在提示词中列出必填字段，解析后检查 |
| 类型错误 | 解析时做类型转换与校验，失败则重试 |
| 枚举越界 | 解析时校验取值范围，越界按"其他"处理或重试 |
| 数字带单位 | 字段定义中写明单位，解析时去除非数字字符 |

## 5.5 清单与评分卡

清单适合步骤和检查项，写法要点：

- 每条一个动作，不要合并多个要求。
- 标明顺序或优先级。
- 给出完成标准。

评分卡适合评估，写法要点：

- 维度固定，不要临时增加。
- 每个维度给出分值含义。
- 要求同时给出理由，避免只有分数没有依据。
- 说明总分如何计算，是加权还是简单相加。

## 5.6 格式约束检查

写格式要求时逐项检查：

- 结构是否明确：表格、JSON、清单、评分卡
- 字段是否定义：名称、类型、单位、格式、空值规则
- 是否允许附加文字：说明、注释、解释
- 长度是否有限制：字数、条数、单元格长度
- 排序是否指定：按时间、按分数、按优先级
- 是否给出示例：一个正确的输出样例

## 5.7 程序校验

格式控制的最后一步是校验，而不是相信模型会遵守。

校验内容包括：

1. 语法：JSON 能否解析，表格列数是否一致。
2. 字段：必填项是否齐全，类型是否正确。
3. 取值：枚举是否在允许集合内，数字是否在合理区间。
4. 引用：提到的文件、链接是否存在。
5. 一致性：同一字段在不同条目中的单位是否统一。

校验失败时的处理：重试并附带错误信息，或降级为人工处理。不要让格式错误的输出直接进入下游。

## 5.8 常见失败情况

1. 模型在 JSON 外包裹解释文字，导致解析失败。
2. 字段名漂移，同一含义在不同输出中使用不同名称。
3. 单位缺失或混用，例如金额有的按元有的按万元。
4. 表格单元格内换行，破坏 Markdown 结构。
5. 评分卡只有分数没有理由，无法判断依据。
6. 输出长度超出下游限制，被截断后结构损坏。

## 5.9 小结

- 控制格式的目的是可校验、可衔接、可比较。
- 按用途选择格式：人看用表格或清单，程序用 JSON，决策用评分卡或矩阵。
- JSON 的关键是字段定义，而不是只写"输出 JSON"。
- 评分卡必须给出分值标准与理由。
- 格式要求要配合程序校验，不能假设模型一定遵守。
- 常见失败集中在附加文字、字段漂移、单位混用和结构损坏。
