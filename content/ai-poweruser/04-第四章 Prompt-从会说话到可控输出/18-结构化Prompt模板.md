# 结构化 Prompt 模板

本节给出一个通用骨架和六类高频任务的模板，用于减少每次从零写 Prompt 的成本。

## 2.1 通用骨架

```
背景：这份材料是什么，给谁看，用于什么场合。
目标：要产出什么，成功的标准是什么。
约束：不能做什么，必须保留什么，篇幅与语气限制。
输入：材料正文，或材料的位置与范围。
输出格式：结构、字段、长度、语言。
```

可选的补充部分：

- 示例：给出 1 到 3 个输入输出样例。
- 验收标准：列出检查项，让模型自检。
- 不确定处理：材料没有时如何标注。

骨架的作用是保证四要素不缺项。实际使用时按任务裁剪，不必每次都写满。

## 2.2 总结类

```
背景：这是一份[材料类型]，用于[用途]，读者是[受众]。
目标：提炼核心信息，便于快速决策。
约束：只使用材料中的信息；不添加材料外的结论；保留关键数字与时间。
输入：[粘贴材料]
输出格式：
1. 一句话结论
2. 5 条以内要点，每条不超过 30 字
3. 需要进一步确认的问题（如有）
不确定处理：材料未提及的内容写"未提及"，不要推测。
```

常见错误：不指定受众，导致详略失当；不限制条数，输出变成全文复述。

## 2.3 改写类

```
背景：这段文字用于[场合]，读者是[受众]。
目标：在保持原意的前提下，调整为[风格/长度/语气]。
约束：
- 必须保留的事实：[列出]
- 不得改变的数字与结论
- 不添加原文没有的信息
输入：[粘贴原文]
输出格式：改写稿 + 修改说明（列出主要改动及原因）
```

改写最容易出现的问题是把限定条件删掉，或把不确定表述改成确定表述。约束部分要明确写出"保留限定词"。

## 2.4 分析类

```
背景：[问题背景]
目标：回答[具体问题]，并给出依据。
约束：
- 区分事实、推断与观点
- 每个结论给出依据
- 信息不足时说明缺少什么
输入：[数据或材料]
输出格式：
1. 结论
2. 依据（对应材料位置）
3. 反例或风险
4. 仍需确认的信息
```

分析类任务的关键是把"结论"和"依据"分开，避免整段都是判断而没有支撑。

## 2.5 抽取类

```
背景：从[文档类型]中抽取结构化字段，用于[用途]。
目标：按指定字段输出，不漏不误。
约束：只抽取原文中出现的内容；找不到填 null；不推断。
字段定义：
- 字段名：类型，说明，示例
输入：[粘贴文本或上传文件]
输出格式：JSON，字段如下……
```

字段定义要写清类型、单位、格式和空值规则。没有定义的字段，模型会自行解释。

## 2.6 评审类

```
背景：这是一份[文档类型]，即将[用途]。
目标：找出问题，按严重程度排序。
约束：只评审，不重写；每条问题必须引用原文；区分事实错误、逻辑问题、表达问题。
输入：[粘贴文档]
输出格式：
| 序号 | 位置 | 问题类型 | 原文 | 问题说明 | 建议 |
严重程度：高/中/低
```

评审类要明确"只评审不重写"，否则模型会直接给出一版新稿，掩盖原稿的问题。

## 2.7 教学类

```
背景：学习者已具备[基础]，目标是掌握[概念/技能]。
目标：讲清概念、机制、边界与常见错误。
约束：不使用未解释的术语；每个抽象概念配一个具体例子；指出常见误解。
输入：[主题]
输出格式：
1. 定义
2. 机制或步骤
3. 例子
4. 边界与失败情况
5. 3 道自测题（附答案）
```

教学类最容易犯的错误是只给定义和类比，不讲边界，导致学习者误以为概念适用范围无限。

## 2.8 模板使用说明

1. 方括号内是占位符，使用前替换为具体内容。
2. 模板是骨架，不是固定文本。任务简单时删掉不必要部分。
3. 模板越长，越要检查指令之间是否冲突。
4. 把常用模板存入个人 Prompt 库，记录使用效果与失败案例。
5. 换模型后重新测试，不同模型对同一模板的遵循程度不同。

## 2.9 小结

- 通用骨架由背景、目标、约束、输入、输出格式组成。
- 六类高频模板：总结、改写、分析、抽取、评审、教学。
- 每类模板的核心是把任务标准写成可检验的条件。
- 模板要按任务裁剪，不是越长越好。
- 模板应配合失败案例记录，才能持续改进。
