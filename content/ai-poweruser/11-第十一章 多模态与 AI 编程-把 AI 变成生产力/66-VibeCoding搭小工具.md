# Vibe Coding 搭小工具

本节说明如何用自然语言让 AI 写小脚本、小网页和小自动化，以及普通人应如何验收。

## 4.1 什么是 Vibe Coding

Vibe Coding 指用自然语言描述需求，由 AI 生成代码，运行后根据结果继续对话修改。使用者不需要系统学习编程，但需要能判断结果是否正确。

适合的任务：

- 批量重命名、格式转换、文件整理
- 简单数据清洗与统计
- 小网页、小工具、表单
- 定时抓取、消息提醒
- 调用 API 的小脚本

不适合的任务：

- 涉及支付、权限、生产环境的系统
- 需要长期维护的复杂项目
- 处理不可恢复数据的操作
- 对安全性要求高的服务

## 4.2 基本流程

```
描述需求 → 生成最小版本 → 运行 → 报错反馈 → 修正 → 逐步扩展
```

要点：

1. 先做最小可用版本。只实现一个功能，跑通后再加。
2. 每次只改一处。一次提多个修改，出错后无法定位。
3. 提供运行环境。说明操作系统、版本、已安装的依赖。
4. 报错时贴完整信息。错误类型、堆栈、输入数据都要给出。
5. 保存可运行版本。每次跑通后备份，改坏时能回退。

## 4.3 验收清单

普通人不需要读懂每一行代码，但必须验收以下五项：

| 项目 | 检查内容 |
|---|---|
| 输入 | 空值、超长、格式错误、特殊字符时是否报错或跳过 |
| 输出 | 结果是否正确，格式是否符合预期，是否覆盖原文件 |
| 异常 | 网络失败、文件不存在、权限不足时是否有提示 |
| 权限 | 访问了哪些目录、网络、账号，是否超出必要范围 |
| 可维护 | 是否有注释、配置是否集中、能否再次运行 |

验收方法：

1. 用真实数据跑一遍，不只跑示例。
2. 故意给错误输入，看是否安全失败。
3. 检查输出文件是否覆盖了原始数据。
4. 查看代码中是否有硬编码的路径、密钥、账号。
5. 隔一天再运行一次，确认环境没有变化。

## 4.4 安全要求

1. 不运行来源不明的代码。AI 生成的代码可能包含删除、上传、外联操作。
2. 密钥不写入代码。使用环境变量或配置文件，且不提交到公开仓库。
3. 最小权限。脚本只访问必要目录，不申请管理员权限。
4. 先备份再运行。涉及修改或删除时，先复制原始数据。
5. 限制网络访问。不需要联网的脚本，不要引入网络请求。
6. 检查依赖。第三方库的来源、版本、许可证要确认。

## 4.5 常见失败

1. 只看代码不看运行结果，代码能生成但跑不通。
2. 没有测试边界输入，遇到空文件或异常格式直接崩溃。
3. 输出覆盖了原始数据，无法恢复。
4. 硬编码密钥或路径，换一台机器就不能用。
5. 一次要求太多功能，代码结构混乱，无法维护。
6. 依赖版本不匹配，昨天能跑今天报错。
7. 脚本执行了未预期的删除或上传操作。

## 4.6 适合普通人的边界

可以做：

- 一次性小脚本，用完即弃。
- 本地文件处理，有备份。
- 只读操作，或输出到新文件。
- 简单网页，无登录、无支付。

不要做：

- 直接操作生产数据库。
- 处理他人数据而没有授权。
- 自动化付款、发布、删除。
- 把含密钥的代码上传到公开平台。

## 4.7 小结

- Vibe Coding 是用自然语言生成代码并迭代，适合小脚本、小工具和轻量自动化。
- 流程是先做最小版本、运行、报错反馈、逐步扩展。
- 验收看输入、输出、异常、权限和可维护性五项。
- 安全要求是不运行不明代码、密钥不入代码、最小权限、先备份、限制网络。
- 常见失败是只看代码不运行、无边界测试、覆盖原始数据、硬编码密钥和一次要求过多。
