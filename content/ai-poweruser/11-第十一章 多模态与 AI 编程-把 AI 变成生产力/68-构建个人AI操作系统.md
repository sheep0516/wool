# 构建个人 AI 操作系统

本节把前面的工具与方法整合成四个系统：输入、处理、输出、自动化。

## 6.1 四个系统

| 系统 | 作用 | 关键要求 |
|---|---|---|
| 输入 | 收集资料、统一入口 | 不遗漏、可检索、有来源 |
| 处理 | 总结、分析、生成 | 有模板、可校验、留版本 |
| 输出 | 写作、汇报、发布 | 格式可交付、事实可核对 |
| 自动化 | 提醒、归档、复盘 | 可监控、失败可接管 |

四个系统不是四套软件，而是一组固定流程。工具可以替换，流程应保持稳定。

## 6.2 输入系统

目标是让资料有一个统一入口，避免散落在聊天记录、收藏夹和下载文件夹。

做法：

1. 统一收集方式。网页剪藏、文件上传、邮件转发都进入同一位置。
2. 统一命名。日期、类型、主题、版本。
3. 记录来源。链接、作者、发布时间。
4. 初步分类。按项目或主题放入对应目录。
5. 定期清理。删除重复与无关内容。

输入系统的常见问题是"只收集不处理"，资料越存越多，实际使用时找不到。

## 6.3 处理系统

处理包括总结、分析、生成三类任务。

1. 总结。长文分段、要点提取、保留页码。
2. 分析。对比、归类、找矛盾、列风险。
3. 生成。按模板产出初稿、方案、清单。

要求：

- 每类任务有固定模板，减少每次重新描述。
- 输出有版本记录，改了什么、为什么改。
- 关键结论标注来源与不确定等级。
- 失败案例单独记录，作为改进依据。

## 6.4 输出系统

输出面向他人，要求格式可交付、事实可核对。

1. 写作。结构、篇幅、语气按受众调整。
2. 汇报。结论前置，数据有来源，图表服务观点。
3. 发布。确认渠道规则、敏感信息、授权与标识。

输出前的检查：

- 事实与数字有来源
- 引用可打开
- 格式符合渠道要求
- 无未脱敏的个人信息
- 无未经确认的承诺

## 6.5 自动化系统

自动化处理重复动作：

| 动作 | 做法 |
|---|---|
| 提醒 | 到期前推送，包含事项与链接 |
| 归档 | 按规则移动到归档目录，保留元数据 |
| 复盘 | 定期汇总完成项、失败项、待办 |
| 备份 | 定期复制关键资料，验证可恢复 |

自动化的前提是流程已经稳定。流程还在变化时，先手动执行，确认步骤固定后再自动化。

## 6.6 数据流

```
输入 → 处理 → 输出 → 归档 → 复盘
```

每个环节都应留下记录：

1. 输入：来源、日期、原始文件。
2. 处理：使用的模板、模型、版本。
3. 输出：交付版本、修改记录。
4. 归档：存放位置、保留期限。
5. 复盘：问题、原因、改进。

这条数据流的价值在于：任何一份产出都能追溯到来源和处理过程。

## 6.7 最小可用版本

不需要一次建全四个系统。起步阶段可以只做：

1. 一个统一收集入口。
2. 三类固定模板：总结、分析、写作。
3. 一个输出检查清单。
4. 一个每周复盘提醒。

先用一个月，确认哪些环节真正高频，再逐步增加自动化。

## 6.8 常见问题

1. 工具堆叠。每个环节用不同工具，数据无法流转。
2. 没有统一入口。资料散落在多个平台，检索困难。
3. 只收集不处理。收藏夹膨胀，实际使用率为零。
4. 输出无检查。格式与事实问题反复出现。
5. 过早自动化。流程尚未稳定就搭工作流，维护成本高于收益。
6. 没有复盘。同样的问题反复发生，经验没有沉淀。

## 6.9 小结

- 个人 AI 操作系统由输入、处理、输出、自动化四个系统组成。
- 输入要求统一入口、统一命名、记录来源、定期清理。
- 处理要求固定模板、版本记录、来源标注和失败记录。
- 输出要求格式可交付、事实可核对、敏感信息已处理。
- 自动化处理提醒、归档、复盘和备份，前提是流程已经稳定。
- 起步只需统一入口、三类模板、检查清单和每周复盘，再逐步扩展。
