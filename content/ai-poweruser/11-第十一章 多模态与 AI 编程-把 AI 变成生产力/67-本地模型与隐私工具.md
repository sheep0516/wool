# 本地模型与隐私工具

本节说明哪些数据适合本地处理、本地模型的能力边界，以及混合方案的做法。

## 5.1 适合本地处理的数据

| 数据类型 | 原因 |
|---|---|
| 身份证、护照、银行卡 | 个人敏感信息，泄露后果严重 |
| 病历、体检、用药记录 | 健康信息，受法律保护 |
| 合同、报价、财务数据 | 商业机密 |
| 客户名单与联系方式 | 个人信息与商业价值 |
| 源代码与密钥 | 安全风险 |
| 内部制度、未发布方案 | 竞争与合规风险 |

判断标准不是文件是否标注"机密"，而是泄露后是否会造成实际损失。

## 5.2 本地工具形态

| 形态 | 特点 | 适合 |
|---|---|---|
| 桌面应用 | 安装简单，图形界面 | 个人日常使用 |
| 本地服务 | 提供兼容 API，便于集成 | 脚本与工具接入 |
| 本地知识库 | 文档不出本机，可离线检索 | 敏感资料问答 |
| 本地转写工具 | 音频不上传 | 会议与访谈 |

选择时先看是否需要集成，再看硬件是否足够。

## 5.3 能力边界

本地模型与云端旗舰通常存在差距，主要体现在：

1. 复杂推理。多步逻辑、数学、代码调试能力较弱。
2. 长上下文。可处理的文档长度有限。
3. 多模态。图片、语音、视频能力不均衡。
4. 工具调用。稳定性和复杂编排能力较弱。
5. 知识时效。模型版本固定，知识不会自动更新。

量化会降低硬件门槛，但也会损失精度。INT4 量化的模型在简单任务上可用，在复杂任务上错误率明显上升。

## 5.4 维护成本

本地部署不只是安装：

- 硬件投入。显存决定能运行多大模型。
- 环境配置。推理框架、驱动、依赖版本。
- 模型更新。新版本需要重新下载、测试、替换。
- 服务监控。崩溃、显存不足、响应变慢。
- 安全隔离。本地服务也可能被外部访问，需要限制端口与账号。

没有运维经验时，本地部署的时间成本常被低估。

## 5.5 混合方案

不必所有环节都本地，也不必所有环节都上云。常见组合：

```
本地：脱敏、检索、敏感数据处理
云端：复杂生成、多模态、长文档分析
```

流程示例：

1. 在本地提取字段并脱敏。
2. 只把脱敏后的内容发送到云端模型。
3. 云端返回结果后，在本地合并回原始数据。
4. 记录哪些数据出了本机、发给了谁。

这种方式兼顾能力与隐私，但需要明确脱敏规则，并验证脱敏是否彻底。

## 5.6 选择建议

| 情况 | 建议 |
|---|---|
| 数据敏感、任务简单 | 纯本地 |
| 数据敏感、任务复杂 | 本地脱敏 + 云端处理 |
| 数据公开、追求能力 | 云端 |
| 离线环境 | 本地 |
| 高频固定任务 | 本地可降低长期成本 |
| 低频使用 | 云端更划算 |

## 5.7 小结

- 身份证、病历、合同、客户数据、源代码和内部方案适合本地处理。
- 本地工具形态包括桌面应用、本地服务、本地知识库和本地转写。
- 本地模型在复杂推理、长上下文、多模态和工具调用上通常弱于云端旗舰。
- 维护成本包括硬件、环境、更新、监控和安全隔离。
- 混合方案是本地脱敏与检索、云端生成，需验证脱敏彻底并记录数据流向。
- 选择依据是数据敏感度、任务复杂度、使用频率和是否离线。
