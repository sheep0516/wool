# 隐私与数据安全

本节说明哪些信息不能上传、如何脱敏、权限如何设置，以及常见的泄露路径。

## 3.1 不应上传的信息

- 身份证、护照、银行卡、社保号码
- 病历、体检报告、用药与心理咨询记录
- 客户名单、联系方式、合同条款
- 未公开的财务数据、薪酬表、融资计划
- 内部战略、未发布产品方案
- 源代码、密钥、访问凭证
- 带个人信息的聊天截图、邮件、录音

判断标准是泄露后的实际后果，而不是文件是否标注"机密"。

## 3.2 脱敏方法

| 方法 | 做法 | 注意 |
|---|---|---|
| 删除 | 去掉与任务无关的个人信息 | 检查上下文与附件 |
| 替换 | 姓名、电话、地址换成占位符 | 保持格式，便于模型理解 |
| 泛化 | 精确数值改区间，具体日期改月份 | 不影响任务所需精度 |
| 分段 | 只上传相关章节 | 检查页眉页脚与批注 |
| 改写 | 用自己的话描述问题 | 避免直接粘贴原文 |

脱敏后仍需检查：文件名、表格批注、修订记录、截图边缘、文档属性中是否残留信息。

## 3.3 权限设置

1. 最小权限。只授予完成任务所需的范围。
2. 按项目隔离。不同项目的数据互不可见。
3. 按密级分库。机密资料单独存放。
4. 共享可控。链接设置有效期，可随时撤销。
5. 操作留痕。记录上传、下载、分享、删除。
6. 离职回收。人员变动时移除权限。
7. 定期审计。检查长期未使用的高权限账号。

## 3.4 本地化处理

适合本地的数据：证件、病历、合同、客户资料、源代码、内部文档。

可选方案：

- 本地模型处理简单任务。
- 本地知识库做检索，不上传原文。
- 本地转写工具处理录音。
- 混合方案：本地脱敏后再调用云端模型。

本地化不是绝对安全。本地服务也可能被外部访问，需要限制端口、账号与文件权限。

## 3.5 常见泄露路径

| 路径 | 说明 |
|---|---|
| 对话内容 | 直接粘贴敏感信息到公网模型 |
| 附件与文件名 | 文件名本身包含客户名、项目名 |
| 截图 | 边缘、通知栏、其他窗口内容未裁剪 |
| 知识库 | 上传时未检查是否含内部资料 |
| 日志 | 平台记录完整对话，保留时间过长 |
| 分享链接 | 权限设置为"任何人可查看" |
| 剪贴板与同步 | 多设备同步导致内容扩散 |
| 第三方插件 | 插件读取全部对话内容 |

## 3.6 事件应对

发现敏感信息已经上传或泄露时：

1. 立即删除相关内容，确认平台是否支持彻底删除。
2. 检查是否已用于训练、是否进入日志或备份。
3. 评估影响范围：涉及哪些人、哪些数据。
4. 按组织规定上报，不要自行隐瞒。
5. 修改相关密码与密钥。
6. 记录事件经过与处理结果，避免再次发生。

## 3.7 小结

- 证件、病历、客户资料、财务、源代码和内部方案不应上传公网模型。
- 脱敏方法包括删除、替换、泛化、分段和改写，并检查文件名与文档属性。
- 权限遵循最小权限、项目隔离、密级分库、共享可控、操作留痕和定期审计。
- 敏感数据优先本地处理，或采用本地脱敏加云端生成的混合方案。
- 泄露路径包括对话、文件名、截图、知识库、日志、分享链接和第三方插件。
- 发生泄露时立即删除、评估影响、按规定上报并更换凭证。
