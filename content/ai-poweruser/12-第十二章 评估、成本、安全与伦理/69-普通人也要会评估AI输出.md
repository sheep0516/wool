# 普通人也要会评估 AI 输出

本节说明评估 AI 输出的五个维度、测试题集的建立方法，以及对照表的使用。

## 1.1 为什么需要评估

AI 输出不稳定，同一问题多次执行结果可能不同；不同模型的能力与风格也有差异。凭一次使用体验判断"好不好用"，容易得出错误结论。

评估的目的不是给模型打分排名，而是回答三个问题：

1. 这个输出能不能直接用？
2. 它在什么情况下会失败？
3. 用它的成本是否值得？

## 1.2 五个维度

| 维度 | 检查内容 | 判断方式 |
|---|---|---|
| 准确性 | 事实、数字、引用是否正确 | 对照来源 |
| 完整性 | 是否覆盖必要信息 | 检查清单 |
| 可用性 | 格式、篇幅、语气是否可直接使用 | 实际使用或交付 |
| 安全性 | 是否含敏感信息、越权操作、有害内容 | 规则检查与人工复核 |
| 成本 | token、时间、人工复核成本 | 统计用量与耗时 |

五个维度不必等权。事实类任务以准确性为主，创意类任务以可用性为主，对外发布则安全性优先。

## 1.3 建立测试题集

准备 20 条真实问题，覆盖：

| 类型 | 数量 | 作用 |
|---|---|---|
| 常规 | 8 到 10 | 检验基本能力 |
| 边界 | 3 到 4 | 检验模糊与超范围输入 |
| 无答案 | 3 | 检验是否编造 |
| 对抗 | 2 到 3 | 检验注入、诱导、越权 |
| 格式 | 2 到 3 | 检验结构稳定性 |

题目来自自己的实际工作，不用网上通用题。每条记录预期结果与判断标准。

## 1.4 对照表

评估结果记录在对照表中：

| 字段 | 内容 |
|---|---|
| 日期 | 测试时间 |
| 模型与版本 | 名称、版本、参数 |
| 问题 | 输入原文 |
| 预期 | 期望结果或标准 |
| 实际 | 实际输出 |
| 准确性 | 通过/不通过，或 1 到 5 分 |
| 完整性 | 缺失项 |
| 可用性 | 是否需要二次加工 |
| 安全性 | 是否含敏感或越界内容 |
| 成本 | token 与耗时 |
| 结论 | 是否适合该场景 |

对照表积累后，换模型、改提示词、调整知识库时都能快速比较。

## 1.5 评估频率

以下情况需要重新评估：

1. 更换模型或版本。
2. 修改系统提示或模板。
3. 更新知识库。
4. 新增使用场景。
5. 平台调整价格或条款。
6. 发现新的失败类型。

不需要每天评估。固定测试集加季度复核即可。

## 1.6 常见错误

1. 凭一次体验下结论。
2. 只用简单问题测试，结果过于乐观。
3. 只看准确性，不看成本与人工复核时间。
4. 没有无答案问题，无法发现编造。
5. 评估后不记录，换模型时无法比较。
6. 把评估当成一次性工作，修改后不回归。

## 1.7 小结

- 评估的目的是判断能否直接用、何时会失败、成本是否值得。
- 五个维度是准确性、完整性、可用性、安全性、成本。
- 测试题集建议 20 条，覆盖常规、边界、无答案、对抗和格式。
- 对照表记录版本、输入、预期、实际、各维度结果和成本。
- 换模型、改提示词、更新知识库或新增场景时重新评估。
- 常见错误是凭感觉、题目过简、不看成本和不做记录。
