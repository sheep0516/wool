# 成本管理

本节说明三种付费方式的成本结构、任务与模型的匹配，以及成本控制方法。

## 2.1 三种付费方式

| 方式 | 计费 | 特点 | 适合 |
|---|---|---|---|
| 订阅 | 按月固定 | 额度不透明，超量限速 | 日常对话、写作 |
| API | 按 token | 可精确统计，随用量增长 | 批量、集成、自动化 |
| 平台积分 | 按点数 | 可切换多模型，倍率不一 | 试用、轻量 Agent |

三种方式的成本不能直接比标价。订阅看似固定，但额度用完后可能降级；API 单价低，但长上下文和高频调用会迅速放大总额；积分平台的兑换倍率常不透明。

## 2.2 成本由什么决定

1. 输入长度。系统提示、历史对话、附件、检索结果都会重复计入。
2. 输出长度。要求"详细展开"会显著增加费用。
3. 模型档位。旗舰模型单价通常是轻量模型的数倍到数十倍。
4. 调用次数。多轮对话、重试、多模型对照都会成倍增加。
5. 上下文累积。长对话每轮都重新发送全部历史。
6. 工具调用。搜索、代码执行、第三方 API 可能单独计费。

## 2.3 任务与模型的匹配

| 任务 | 建议档位 | 理由 |
|---|---|---|
| 分类、打标、路由 | 轻量模型 | 规则明确，输出短 |
| 字段抽取 | 轻量或中档 | 格式固定，可程序校验 |
| 短文本改写 | 轻量或中档 | 输入输出都短 |
| 长文总结 | 旗舰 | 需要长上下文与理解 |
| 复杂分析、代码 | 旗舰或推理模型 | 需要多步推理 |
| 高风险内容 | 旗舰 + 人工 | 错误代价高 |
| 批量低风险任务 | 轻量 + 校验 | 成本敏感 |

判断方法：先用轻量模型跑一批真实样本，统计失败率。可接受就用轻量；不可接受再升级。

## 2.4 成本估算

```
单次成本 = 输入 token × 输入单价 + 输出 token × 输出单价
月成本 = 单次成本 × 日均调用次数 × 30
```

估算时注意：

- 输出单价通常高于输入。
- 中文按字估算比按词更接近。
- 长对话的实际输入远大于单条消息。
- 重试与多模型对照要计入次数。
- 具体单价随厂商与版本变化，以官方价格页为准。

## 2.5 成本控制

1. 分层路由。默认用轻量模型，校验不通过再升级。
2. 压缩上下文。只传必要材料，长文档先检索或分段。
3. 限制输出。固定格式与长度，避免冗长解释。
4. 复用前缀。固定系统提示放在开头，利用缓存折扣。
5. 批量处理。非实时任务集中执行，使用批量接口。
6. 控制重试。设置上限，避免失败后反复调用。
7. 预算告警。按日或按月监控，异常时通知。
8. 记录单任务成本。把成本纳入评估，而不是只看效果。

## 2.6 常见错误

1. 用旗舰模型处理所有任务，成本随用量线性上升。
2. 长对话不重开，上下文越滚越大。
3. 每次调用都重发整份文档，而不是先检索相关段落。
4. 多模型对照无限循环，成本翻倍。
5. 只看单价，不看实际 token 消耗。
6. 没有预算告警，月底才发现超支。

## 2.7 小结

- 订阅、API、积分三种方式计费不同，成本不能只比标价。
- 成本由输入长度、输出长度、模型档位、调用次数、上下文累积和工具调用决定。
- 任务与模型要匹配：固定格式用轻量，复杂推理用旗舰或推理模型。
- 用公式估算单次与月成本，注意输出更贵、长对话更贵。
- 控制手段包括分层路由、压缩上下文、限制输出、缓存、批量、重试上限和预算告警。
- 常见错误是全程用旗舰、长对话不重开、重复发送全文和没有预算监控。
