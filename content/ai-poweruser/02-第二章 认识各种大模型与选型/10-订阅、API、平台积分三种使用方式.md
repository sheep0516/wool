# 订阅、API、平台积分三种使用方式

本节说明三种付费与接入方式的差别、适合人群，以及 token 成本的基本估算方法。

## 5.1 三种方式

### 订阅

按月付费，在厂商的网页或客户端中使用，通常包含固定额度或"合理使用"限制。优点是不用配置、开箱即用；缺点是额度不透明、难以集成到自己的流程、超额后可能降速或限制。

### API

按 token 计费，通过接口调用。优点是可以集成到脚本、工作流、自己的产品中，用量与成本可精确统计；缺点是需要技术配置，费用随调用量增长。

### 平台积分

在聚合平台或 Agent 平台上按点数消耗，点数可兑换不同模型。优点是可以在一个平台切换多个模型、门槛低于直接接 API；缺点是汇率不透明、不同模型消耗倍率不同、长期成本可能高于直接订阅或 API。

## 5.2 适合人群

| 方式 | 适合 | 不适合 |
|---|---|---|
| 订阅 | 普通用户、以对话和写作为主、不想配置 | 需要批量处理、需要集成到工作流 |
| API | 重度用户、搭建者、需要自动化和批量任务 | 只想日常聊天、没有技术基础 |
| 平台积分 | 想低成本试用多个模型、做轻量 Agent | 高频大量调用、对成本精度要求高 |

一个常见的过渡路径：先用订阅验证需求，确认高频场景后，把重复任务迁到 API 或工作流平台。

## 5.3 Token 成本的基本直觉

费用由输入 token 与输出 token 两部分组成，输出通常更贵。影响成本的因素：

1. 上下文长度。每次调用都会把系统提示、历史对话、附件内容重新计入输入，长对话成本增长很快。
2. 输出长度。让模型"详细展开"会显著增加费用。
3. 模型档位。旗舰模型单价通常是轻量模型的数倍到数十倍。
4. 重试与多次采样。同一任务跑三次取最佳，成本就是三倍。
5. 缓存。部分平台对重复前缀提供缓存折扣，固定系统提示可以降低成本。
6. 批量接口。非实时任务使用批量接口通常有折扣。

粗略估算公式：

```
单次成本 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
月成本 = 单次成本 × 日均调用次数 × 30
```

中文与英文的 token 换算不同，中文通常按字估算更接近。具体单价随厂商和版本变化，估算时应以官方价格页为准。

## 5.4 成本控制手段

1. 明确任务档位。简单任务用轻量模型，只有失败时才升级。
2. 压缩上下文。只传必要材料，长文档先分段或先检索。
3. 限制输出格式与长度。用结构化输出，避免冗长解释。
4. 复用系统提示。把固定指令放在前缀，利用缓存。
5. 批量处理。非实时任务集中执行，使用批量接口。
6. 设置预算告警。按日或按月监控用量，避免异常调用。
7. 记录单任务成本。把成本纳入模型对比的维度，而不是只看效果。

## 5.5 常见误区

一、订阅等于无限使用。
不成立。多数订阅有额度或使用限制，高峰期限速，条款也可能调整。

二、API 一定比订阅便宜。
不成立。低频使用时，订阅通常更划算；高频批量使用时，API 才体现优势。

三、积分平台最灵活，所以最省钱。
不成立。积分倍率与兑换规则会影响实际成本，长期高频使用往往不如直接订阅或 API 透明。

四、只看单价，不看总消耗。
不成立。长上下文、多轮对话、重试都会放大实际用量，单价低不代表总成本低。

## 5.6 小结

- 订阅适合日常对话与写作，API 适合集成、批量与自动化，积分平台适合低成本试用多模型。
- 成本由输入与输出 token 共同决定，输出更贵，上下文越长成本越高。
- 模型档位、重试次数、输出长度是成本的主要放大器。
- 控制成本的手段包括分层路由、压缩上下文、限制输出、缓存、批量和预算告警。
- 选择方式应基于使用频率与是否需要集成，而不是单纯比较标价。
