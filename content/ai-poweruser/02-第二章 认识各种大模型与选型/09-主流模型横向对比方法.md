# 主流模型横向对比方法

本节说明如何用自己的任务集对比模型，而不是依赖榜单或他人评价。

## 4.1 为什么要自己做同题测试

公开榜单的题目、评分方式和数据分布，与个人实际任务往往不一致。榜单靠前的模型，在自己的场景里未必最好。同题测试的目的，是在可控条件下比较模型对自己任务的表现。

基本做法：准备一组真实任务，固定输入与提示词，让多个模型分别执行，按统一标准评分。

## 4.2 测试集怎么准备

1. 从真实工作中抽取 10 到 20 条任务，覆盖高频场景，而不是只用几个简单示例。
2. 包含不同难度：常规样本、边界样本、容易出错的样本。
3. 固定输入。同一题给所有模型完全相同的文本、文件与提示词。
4. 记录标准答案或判断依据，便于评分。
5. 保留失败样本。失败样本比成功样本更能区分模型。

测试集不需要大，但要有代表性。十条覆盖真实分布的任务，比一百条网上找来的题目更有用。

## 4.3 比较维度

| 维度 | 说明 | 评分方式 |
|---|---|---|
| 准确性 | 事实、数字、结论是否正确 | 对照标准答案，统计正确率 |
| 完整性 | 是否覆盖必要信息 | 检查清单，统计遗漏项 |
| 稳定性 | 同一输入多次执行是否一致 | 重复 3 到 5 次，比较差异 |
| 格式遵循 | 是否按要求的 JSON、表格、字数输出 | 程序校验或人工检查 |
| 速度 | 首字延迟与总耗时 | 记录平均值与最大值 |
| 价格 | 单次任务的实际成本 | 按 token 用量估算 |
| 隐私 | 数据是否可用于训练、是否可关闭 | 查服务条款 |
| 拒答与安全 | 是否在应当拒绝时拒绝，是否过度拒绝 | 设计边界样本 |
| 上下文 | 长文档下是否保持稳定 | 逐步加长输入测试 |

不需要每个维度都打分。根据任务性质选 4 到 6 个关键维度，给出权重。

## 4.4 评分方法

常用三种：

1. 通过/不通过。适合格式转换、字段抽取这类有明确标准的任务。
2. 1 到 5 分。适合写作、总结这类质量有层次的任务，需要事先定义各分值标准。
3. 成对比较。把两个模型的输出放在一起，判断哪个更好，适合主观质量评估。

评分时建议隐藏模型名称，避免先入为主。多人评分时，先统一评分标准，再独立打分。

## 4.5 常见错误

1. 用单个问题下结论。一个题目表现好或坏，不能代表整体。
2. 忽略随机性。生成式输出本身有波动，只跑一次无法判断稳定性。
3. 提示词不统一。给不同模型不同的提示词，比较结果没有意义。
4. 忽略版本。模型会更新，几个月前的结论可能已经失效。
5. 只看能力，不看成本。最强模型在低成本任务上可能完全不划算。
6. 用公开题目代替真实任务。公开题目容易被模型"见过"，无法反映实际表现。

## 4.6 结果记录

建议每次测试记录以下信息：

| 字段 | 内容 |
|---|---|
| 日期 | 测试时间 |
| 模型与版本 | 具体名称、版本号、参数设置 |
| 任务 | 任务描述与输入摘要 |
| 提示词 | 完整提示词或模板编号 |
| 输出 | 保存原始输出 |
| 评分 | 各维度得分与总评 |
| 问题 | 失败原因、幻觉点、格式错误 |
| 结论 | 是否适合该场景 |

这些记录积累下来，就是自己的模型适用场景表，比任何榜单都更贴近实际。

## 4.7 小结

- 同题测试是在自己的任务上比较模型，不依赖公开榜单。
- 测试集应来自真实工作，覆盖常规、边界和易错样本，固定输入与提示词。
- 核心维度：准确性、完整性、稳定性、格式遵循、速度、价格、隐私。
- 评分可用通过/不通过、分级打分或成对比较，注意隐藏模型名称。
- 每次测试记录模型版本、提示词、输出和失败原因，形成可复用的场景表。
