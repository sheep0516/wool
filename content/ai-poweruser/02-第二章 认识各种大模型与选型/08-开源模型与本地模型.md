# 开源模型与本地模型

本节说明开源模型与本地部署能解决什么问题、代价是什么，以及普通人需要掌握的边界。

## 3.1 开源与闭源的区别

开源模型指权重可下载的模型，可以本地运行、私有部署、微调，也可以商用（具体取决于许可证）。闭源模型只提供网页或 API 服务，权重不可获取。

| 维度 | 开源模型 | 闭源模型 |
|---|---|---|
| 权重 | 可下载 | 不公开 |
| 部署位置 | 本地、私有服务器、云 | 厂商服务器 |
| 数据流向 | 可完全留在本地 | 数据发送给厂商 |
| 能力上限 | 通常低于同代旗舰 | 通常最强 |
| 可定制 | 可微调、可量化、可改推理参数 | 只能通过提示词与接口参数调整 |
| 维护 | 使用者自己负责 | 厂商负责 |
| 成本结构 | 硬件与运维为主 | 按订阅或 token 计费 |

## 3.2 本地部署解决的问题

1. 隐私。客户资料、病历、合同、未公开文档可以不出本机或内网。
2. 离线。无网络或网络受限环境下仍可使用。
3. 成本可控。长期高频使用时，一次性硬件投入可能低于持续的 API 费用。
4. 版本固定。不会因厂商升级导致行为突变，便于复现和回归测试。
5. 可定制。可以针对固定任务做微调，或接入内部工具与数据。

## 3.3 普通人需要知道的边界

### 硬件

本地运行需要显存。粗略估算：模型参数量乘以每个参数的字节数，再加上上下文缓存的开销。

- FP16 精度：每 10 亿参数约需 2GB 显存。
- INT8 量化：约需 1GB。
- INT4 量化：约需 0.5GB。

实际还要考虑上下文长度、批大小和推理框架开销，通常要留出额外余量。量化会损失部分精度，任务越复杂，损失越明显。

### 效果

同代开源模型与闭源旗舰通常存在能力差距，尤其在复杂推理、长上下文、多模态和工具调用上。开源模型的优势是可控与私有，不是绝对能力。

### 维护成本

本地部署不只是"下载后运行"，还包括：

- 推理框架的选择与配置
- 模型更新与版本管理
- 显存与并发调优
- 服务监控与故障处理
- 安全隔离与访问控制

这些工作对没有运维经验的人是不小的负担。

## 3.4 适合与不适合的场景

适合本地部署：

- 数据敏感，不能上传公网。
- 处于离线或内网环境。
- 有稳定、高频、格式固定的任务，例如内部文档问答、日志分类。
- 需要长期固定版本，或需要微调。
- 以学习和技术研究为目的。

不适合本地部署：

- 追求当前最强能力。
- 使用频率低，硬件投入不划算。
- 没有维护能力和时间。
- 需要多模态、长上下文、复杂工具调用等高级能力。

## 3.5 常见工具形态

本地部署通常分三类：

1. 桌面应用：安装简单，适合个人试用与日常对话，配置选项有限。
2. 本地服务框架：提供兼容 API 的接口，便于接入自己的脚本和工具。
3. 高性能推理服务：面向多人并发和生产环境，配置复杂，需要运维能力。

选择时先明确用途：个人试用选桌面应用，做集成选本地服务框架，团队生产再考虑高性能服务。

## 3.6 小结

- 开源模型的价值在于权重可控、可私有部署、可微调；闭源模型的价值在于能力与免维护。
- 本地部署主要解决隐私、离线、长期成本和版本固定问题。
- 硬件门槛由参数量、精度和上下文决定，量化可以降低门槛但会损失精度。
- 效果通常低于同代闭源旗舰，且维护成本常被低估。
- 是否本地部署，取决于数据敏感度、使用频率和维护能力，而不是"开源更自由"这一判断。
