# 模型选型决策树

本节把前面的模型分类、对比方法和成本因素整合成一套选型顺序，并给出场景表的建立方法。

## 6.1 选型的判断顺序

顺序固定为四步，前一步不通过就不进入下一步：

1. 任务风险。错误会造成什么后果，是否可逆，是否需要资质。
2. 能力需求。任务是否需要复杂推理、长上下文、多模态、工具调用。
3. 成本约束。调用频率、可接受的单次成本与月预算。
4. 隐私与合规。数据能否离开本机或内网，服务条款是否允许。

先看风险，是因为高风险任务即使能力足够，也不能只靠模型；先看隐私放在最后，是因为它通常决定"用哪一类"，而不是"用哪一个"。

## 6.2 决策树

```
任务是否高风险或不可逆？
├── 是 → 不用模型直接执行；模型只做草稿或建议，人工确认
└── 否
    └── 数据是否敏感、能否上传公网？
        ├── 不能 → 本地开源模型；能力不足则改为脱敏后调用闭源模型
        └── 能
            └── 任务是否需要多步推理、长文档或多模态？
                ├── 是 → 旗舰模型或推理模型
                └── 否
                    └── 是否是高频、格式固定的批量任务？
                        ├── 是 → 轻量模型 + 程序校验，失败再升级
                        └── 否 → 旗舰模型，按使用频率选择订阅或 API
```

决策树给出的是起点，不是终点。最终选择仍需用自己的测试集验证。

## 6.3 场景表示例

| 场景 | 风险 | 能力需求 | 建议档位 | 兜底方式 |
|---|---|---|---|---|
| 日常写作、改写 | 低 | 语言组织 | 旗舰或轻量 | 人工通读 |
| 长文总结 | 中 | 长上下文 | 旗舰 | 对照原文抽查 |
| 合同字段抽取 | 高 | 结构化输出 | 旗舰 + 程序校验 | 人工复核关键字段 |
| 客服自动回复 | 中 | 短文本、稳定格式 | 轻量 | 敏感问题转人工 |
| 代码生成与调试 | 中高 | 推理、工具调用 | 推理模型 | 运行测试 |
| 内部资料问答 | 高 | 知识库检索 | 本地模型或私有部署 | 引用原文、权限控制 |
| 会议转写与纪要 | 中 | 语音、长文本 | 专用转写 + 旗舰总结 | 人工校对专名与数字 |
| 批量评论分类 | 低 | 分类 | 轻量 | 抽样复核 |

这张表应随实际测试结果更新，而不是一次定死。

## 6.4 建立自己的模型适用场景表

维护一张表，至少包含以下字段：

| 字段 | 说明 |
|---|---|
| 任务 | 具体场景，不用"写作"这类模糊描述 |
| 频率 | 每天或每周调用次数 |
| 风险等级 | A 可直接用 / B 校验后用 / C 只能辅助 / D 不要用 |
| 能力需求 | 推理、长文、多模态、工具调用 |
| 数据敏感度 | 是否含个人信息、客户数据、未公开资料 |
| 选用模型 | 具体模型与版本 |
| 参数设置 | 温度、输出格式、上下文策略 |
| 兜底方式 | 校验、复核、人工确认 |
| 效果记录 | 通过率、主要失败原因 |
| 成本 | 单次成本与月成本 |

这张表积累三个月后，选型基本不再依赖他人推荐。

## 6.5 定期复核

模型和价格变化很快，建议每季度做一次复核：

1. 用固定测试集重跑当前模型，确认效果没有明显下降。
2. 检查价格与服务条款是否变化。
3. 评估是否有更便宜的模型可以承接部分任务。
4. 检查数据合规要求是否更新。
5. 更新场景表中的模型与成本字段。

复核的目的不是追新，而是确认现有选择仍然成立。

## 6.6 小结

- 选型顺序：任务风险 → 能力需求 → 成本约束 → 隐私合规。
- 高风险任务不用模型直接执行；敏感数据优先本地或脱敏。
- 复杂推理、长文档、多模态用旗舰或推理模型；高频固定任务用轻量模型加校验。
- 决策树只是起点，最终用自建测试集验证。
- 维护场景表并定期复核，比记住某个"最强模型"更有用。
