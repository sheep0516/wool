# 四个实战项目

本节给出四个项目的目标、组件配置、实施步骤和验收标准。

## 8.1 项目一：个人知识库问答助手

目标：基于自己的文档回答问题，并给出可核对来源。

组件：

- 指令：只根据知识库回答；无依据时明确说明；给出文件名与页码。
- 知识库：20 到 50 份核心文档，统一命名，清理旧版本。
- 工具：可选搜索，用于补充实时信息。
- 记忆：保存常用术语与已确认结论。

步骤：

1. 整理文档，统一命名与目录。
2. 上传并检查解析质量，尤其是表格与扫描件。
3. 编写指令，明确拒答规则。
4. 准备 20 条测试问题，含 3 条无答案问题。
5. 调整分块与检索，直到常规问题能命中正确文档。
6. 发布到网页或内部工具。

验收：常规问题命中率可接受；无答案问题不编造；引用能打开原文。

常见失败：文档版本混杂、分块切断条款、引用只给文件名不给页码。

## 8.2 项目二：会议纪要转待办与提醒

目标：把会议转写整理成结论、待办和提醒。

组件：

- 指令：按议题分段；抽取结论、待办、负责人、截止时间；缺失项标注"未指定"。
- 知识库：历史会议纪要、项目术语表。
- 工具：转写、任务系统写入、日历或消息提醒。
- 记忆：项目成员与常用术语。

步骤：

1. 准备转写文本，保留时间戳与说话人。
2. 按议题切分，逐段抽取。
3. 生成待办表，人工确认负责人与截止时间。
4. 写入任务系统，设置提醒。
5. 会议结束前由主持人复核。

验收：结论与原文一致；待办有负责人与时间；不重复创建任务。

常见失败：说话人识别错误、口语条件被简化、截止时间被自行填写。

## 8.3 项目三：内容研究、写作、审核 Agent

目标：从选题到可交付初稿，经过检索、写作、审核三个环节。

组件：

- 指令：分为检索、写作、审核三个角色，各自独立。
- 知识库：品牌规范、历史稿件、素材库。
- 工具：搜索、文档解析、图片生成。
- 记忆：常用风格、已用选题。

步骤：

1. 检索 Agent 收集资料，输出资料清单与原文片段。
2. 写作 Agent 基于资料成文，标注每个事实的来源。
3. 审核 Agent 检查事实、逻辑、风格、格式，只列问题不重写。
4. 人工裁决并定稿。
5. 发布前再次核对引用与敏感信息。

验收：事实有来源；结构与风格符合规范；审核问题清单完整；不直接发布。

常见失败：检索资料不足就开写、写作添加未提供的事实、审核与写作共享同一盲区。

## 8.4 项目四：跨应用自动化助手

目标：把重复的跨应用操作串成一条可监控的流程。

组件：

- 指令：定义触发条件、处理步骤、失败处理。
- 知识库：字段映射表、历史异常记录。
- 工具：表单、表格、邮件、消息、任务系统。
- 记忆：已处理记录，用于幂等判断。

步骤：

1. 画流程图，标出输入、输出、分支和人工确认点。
2. 先做只读流程，确认数据能正确获取与转换。
3. 加入写操作，设置幂等标记与确认环节。
4. 配置日志、重试与告警。
5. 小范围运行一周，再扩大范围。

验收：重复执行不产生重复数据；失败有告警；可从中断处重跑；高风险操作有确认。

常见失败：授权过期、字段变化、重试导致重复、失败无告警。

## 8.5 建议顺序

按以下顺序实施，难度递增：

1. 项目一。只涉及知识库与问答，风险低。
2. 项目二。加入转写与任务写入，需要人工确认。
3. 项目三。多 Agent 协作，需要状态传递与审核。
4. 项目四。跨应用写操作，风险最高，需要幂等与回滚。

每个项目完成后再进入下一个，不要在第一个项目还没稳定时就开始搭多 Agent。

## 8.6 小结

- 项目一是知识库问答，重点是文档整理、拒答规则和引用可核对。
- 项目二是会议待办，重点是议题分段、负责人确认和去重。
- 项目三是内容流水线，重点是检索、写作、审核分离，事实带来源。
- 项目四是跨应用自动化，重点是幂等、日志、告警和人工确认。
- 实施顺序由低风险到高风险，每个项目稳定后再进入下一个。
