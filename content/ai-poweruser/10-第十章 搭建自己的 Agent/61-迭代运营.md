# 迭代运营

本节说明 Agent 上线后的运营循环、失败案例归因和版本管理。

## 7.1 运营循环

```
收集问题 → 归因 → 修复 → 验证 → 记录
```

1. 收集。用户反馈、日志、定期测试。
2. 归因。判断问题出在知识库、指令、工具还是模型。
3. 修复。按优先级修改对应部分。
4. 验证。用测试集回归，确认问题解决且没有引入新问题。
5. 记录。写下改了什么、为什么改、效果如何。

这个循环应固定节奏，例如每周一次，而不是等到问题堆积。

## 7.2 问题来源

| 来源 | 能发现什么 |
|---|---|
| 用户反馈 | 实际使用中的困惑、错误、缺失功能 |
| 日志 | 失败率、超时、工具错误、异常调用 |
| 测试集 | 回归问题、边界行为变化 |
| 人工抽检 | 日志中未报告的隐性错误 |

只依赖用户反馈会漏掉"用户没有察觉的错误"。定期抽检输出，可以发现事实错误、格式漂移和引用错误。

## 7.3 归因方法

| 现象 | 可能原因 | 检查 |
|---|---|---|
| 答非所问 | 检索失败或指令不清 | 看检索片段与指令 |
| 编造事实 | 知识库缺失或未要求引用 | 查资料、查提示词 |
| 格式错误 | 输出约束不足 | 查格式定义与校验 |
| 工具失败 | 参数、权限、超时 | 查调用日志 |
| 行为突变 | 模型升级或提示词改动 | 对比版本记录 |
| 越权操作 | 权限过大或确认缺失 | 查工具权限配置 |

先定位环节，再改配置。不要一上来就换模型。

## 7.4 修复优先级

1. 安全与越权问题。最高优先级，立即处理。
2. 事实错误。影响可信度，优先修复。
3. 检索失败。影响可用性，调整知识库或分块。
4. 格式问题。影响下游使用，补充约束与校验。
5. 风格与体验。最后处理。

每次只改一处，改完立即回归测试。同时改多处，无法判断哪一处起作用。

## 7.5 知识库维护

1. 更新。新增资料及时入库，旧版本标注废止。
2. 清理。删除重复、过期、低质量文档。
3. 结构。保持标题层级与命名规范。
4. 索引。文件增删改名后同步更新。
5. 抽检。定期用测试问题检查检索是否仍命中正确文档。

知识库过期是 Agent 效果下降最常见的原因之一。

## 7.6 版本记录

每次修改记录以下内容：

| 字段 | 内容 |
|---|---|
| 版本号 | 递增编号 |
| 日期 | 修改时间 |
| 修改内容 | 指令、知识库、工具、模型 |
| 修改原因 | 对应的问题或需求 |
| 测试结果 | 回归通过率、成本变化 |
| 回滚方式 | 如何恢复上一版 |

版本记录的作用是：出问题时能定位是哪次修改导致的，必要时可以回滚。

## 7.7 指标监控

建议持续关注：

- 成功率与失败率
- 无答案问题的拒答率
- 引用可核对率
- 平均延迟与超时率
- 单次与月度成本
- 用户反馈中的高频问题

指标不必多，但要能反映"是否可用、是否可信、是否划算"。

## 7.8 小结

- 运营循环是收集、归因、修复、验证、记录，按固定节奏执行。
- 问题来源包括用户反馈、日志、测试集和人工抽检。
- 归因先定位环节：知识库、指令、工具、模型。
- 修复优先级是安全、事实、检索、格式、体验；每次只改一处并回归。
- 知识库要更新、清理、保持结构、同步索引和定期抽检。
- 版本记录包含修改内容、原因、测试结果和回滚方式。
