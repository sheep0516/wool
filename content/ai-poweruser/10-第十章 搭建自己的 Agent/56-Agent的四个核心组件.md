# Agent 的四个核心组件

本节说明指令、知识库、工具、记忆四个组件的作用，以及什么时候不需要 Agent。

## 2.1 四个组件

| 组件 | 作用 | 常见问题 |
|---|---|---|
| 指令 | 定义角色、任务、边界、输出格式 | 描述模糊、规则冲突、过长 |
| 知识库 | 提供外部资料，弥补模型知识不足 | 资料过期、分块不当、检索失败 |
| 工具 | 让 Agent 获取信息、执行动作 | 权限过大、参数错误、失败无兜底 |
| 记忆 | 保存会话状态与长期信息 | 记错、忘记、隐私泄露 |

四个组件不是必须全有。一个只做文本改写的 Agent 可能只需要指令；一个只查内部资料的 Agent 需要指令和知识库。

## 2.2 指令

指令决定 Agent 的行为方式，通常包含：

1. 角色与目标。
2. 输入要求：需要用户提供什么。
3. 处理规则：按什么顺序做，遇到什么情况如何处理。
4. 输出格式：结构、长度、字段。
5. 边界：不做什么，什么情况拒答。
6. 失败处理：工具失败、资料缺失时如何回应。

常见问题是把太多规则堆在一起，导致模型只遵守前面几条。规则应分组、编号，并控制总量。

## 2.3 知识库

知识库用于提供模型训练数据之外的信息。配置时要考虑：

- 资料范围：只放与任务相关的文档，清理旧版本。
- 文档结构：标题层级清晰，表格有表头，扫描件先做 OCR。
- 分块方式：按章节切分，保留标题；长条款不要切断。
- 更新机制：谁负责、多久检查一次。
- 引用要求：回答需给出文件名与页码。

知识库不是越大越好。覆盖度、结构和更新频率，比文档数量更重要。

## 2.4 工具

工具让 Agent 能获取实时信息或执行动作。配置原则：

1. 最小工具集。只保留当前任务需要的工具。
2. 读写分离。默认只读，写操作单独授权。
3. 参数约束。类型、范围、必填项写清楚。
4. 失败兜底。超时、权限、空结果时明确报告。
5. 人工确认。对外发送、付款、删除等操作必须确认。

工具越多，选择错误的概率越高。一个能完成任务的三个工具，胜过十个用不上的工具。

## 2.5 记忆

记忆分为两类：

- 会话记忆：当前对话的上下文，用于保持连续性。
- 长期记忆：跨会话保存的用户偏好、历史结论、常用资料。

长期记忆的配置要考虑：

| 问题 | 处理 |
|---|---|
| 存什么 | 只存稳定、可复用的信息，不存临时内容 |
| 存多久 | 设定保留期，过期清理 |
| 谁能看 | 按用户隔离，不跨账号共享 |
| 如何纠错 | 提供查看、修改、删除入口 |
| 隐私 | 不存敏感信息，或加密存储 |

记忆不是越多越好。错误的记忆会被反复引用，比没有记忆更难纠正。

## 2.6 什么时候不需要 Agent

| 情况 | 更合适的形式 |
|---|---|
| 单次生成、无外部资料 | 单提示词 |
| 固定格式转换 | 单提示词 + 结构化输出 |
| 步骤固定、无需判断 | 工作流 |
| 只查一份文档 | 文档问答 |
| 只需要一个固定助手 | 自定义助手 |

判断标准是：任务是否需要多步决策、调用工具、根据中间结果改变下一步。如果不需要，用更简单的形式，维护成本更低、失败更少。

## 2.7 小结

- Agent 的四个核心组件是指令、知识库、工具和记忆。
- 指令定义行为与边界，知识库提供外部资料，工具扩展能力，记忆保持连续性。
- 每个组件都有典型故障：指令模糊、资料过期、工具权限过大、记忆错误。
- 组件不必全有，按任务需要配置。
- 单提示词、工作流或文档问答能解决的任务，不必做成 Agent。
