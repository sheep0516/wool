# 让 AI 主动追问

本节说明如何让模型在执行前先澄清需求，以及如何设计一份有效的提问清单。

## 2.1 为什么需要主动追问

需求不完整时，模型不会停下来等，而是自行填补缺失信息。填补的依据是它的先验，而不是你的实际情况。结果是输出看起来完整，但方向、受众、篇幅都可能不对。

主动追问的作用，是把这些隐含假设提前暴露出来，把一次返工变成一次确认。

## 2.2 触发追问的写法

在任务提示中加入前置指令：

```
在开始执行前，请先列出完成该任务仍需确认的信息，最多 5 条，按重要性排序。
每条说明为什么需要，以及不同答案会怎样影响结果。
在我回答之前，不要开始写正文。
```

关键点：

- 限定条数，避免一次抛出十几个问题。
- 要求按优先级排序，便于快速回答。
- 要求说明影响，便于判断哪些可以默认。
- 明确"先不执行"，否则模型常常一边提问一边已经把正文写完。

## 2.3 提问清单模板

固定询问以下几类信息，可以减少来回：

| 类别 | 具体问题 |
|---|---|
| 目标 | 最终要产出什么，用来做什么 |
| 受众 | 给谁看，他们的背景和关注点 |
| 范围 | 覆盖哪些内容，明确排除哪些 |
| 材料 | 有哪些可用资料，是否有必须引用的来源 |
| 格式 | 篇幅、结构、语言、是否需要表格 |
| 标准 | 什么算合格，什么绝对不能出现 |
| 时间 | 截止时间、时效要求 |
| 权限 | 是否可以对外发布，是否涉及敏感信息 |

不必每次都问全，按任务复杂度选择。简单任务问两三项即可。

## 2.4 提高一次成功率的做法

1. 把答案直接写进提示词。与其让模型追问，不如一开始就把已知条件写清楚。
2. 给默认值。对不重要的项写明"若无说明，按 X 处理"，减少无效追问。
3. 用选项而非开放问题。"受众是管理层、执行层还是外部客户"比"受众是谁"更容易回答。
4. 分两轮。第一轮确认需求，第二轮执行，不要在一条消息里同时要求澄清和交付。
5. 记录常用答案。同一类任务反复出现的确认项，可以固化成模板。

## 2.5 追问质量不理想时

常见问题及处理：

| 问题 | 处理 |
|---|---|
| 问题太多、太泛 | 限定最多 5 条，要求按重要性排序 |
| 问的是已知信息 | 在提示中写明已知条件，要求只问缺失项 |
| 问题无法回答 | 要求给出 2 到 3 个可选答案及影响 |
| 只提问不说明原因 | 要求每条附上"为什么需要" |
| 一边提问一边执行 | 明确"未确认前不要输出正文" |

## 2.6 适用与不适用

适用：

- 任务目标模糊，例如"帮我做个方案"。
- 交付物用途不明确。
- 材料缺失，需要确认哪些可以补充。
- 高风险任务，错误代价高，值得多花一轮确认。

不适用：

- 需求已经明确，追问只是拖延。
- 只需要一个粗略初稿用于讨论方向。
- 时间紧迫，先出稿再调整更划算。

## 2.7 反向做法：先告诉模型需要什么

除了让模型追问，也可以由使用者先说明"你需要哪些信息我才能给你"。

```
为了完成这个任务，你需要我提供哪些材料？请列出清单，并说明每项的用途。
```

这种方式适合材料准备阶段。先拿到清单，再去收集资料，比反复补交更高效。

## 2.8 小结

- 需求不完整时，模型会用先验填补空白，主动追问可以把隐含假设提前暴露。
- 触发追问要限定条数、要求排序、说明影响，并明确"先不执行"。
- 提问清单覆盖目标、受众、范围、材料、格式、标准、时间、权限。
- 提高一次成功率的关键是把已知条件写进提示词，并给默认值和选项。
- 追问适合模糊、高风险任务，不适合已经明确或只需粗略初稿的场景。
