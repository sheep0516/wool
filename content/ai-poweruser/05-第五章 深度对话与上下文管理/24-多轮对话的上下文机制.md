# 多轮对话的上下文机制

本节说明多轮对话中模型如何"看到"历史、为什么聊久了会跑偏，以及什么时候应该开新对话。

## 1.1 上下文窗口与对话的存储方式

模型每次生成时，只能看到当前上下文窗口内的内容。这个窗口有 token 上限，系统提示、历史消息、上传的附件、工具返回结果，全部计入其中。

需要区分两个概念：

- 对话记录：平台保存的完整聊天历史。
- 模型实际看到的上下文：本次请求中真正送入模型的部分。

两者不一定相同。当历史超出窗口时，平台可能截断早期内容，或做摘要压缩，或只保留最近若干轮。模型本身没有跨对话的持久记忆，它不会"记得"上一次会话，除非那些内容被重新放入上下文。

## 1.2 上下文如何影响输出

1. 位置效应。放在开头和结尾的信息更容易被利用，夹在长上下文中间的内容容易被忽略，这一现象通常称为"中间遗忘"。
2. 近因偏好。模型更容易受最近几轮影响，早期设定的目标、约束和术语会逐渐被稀释。
3. 冲突累积。前后轮次出现矛盾时，模型未必会指出，可能直接采用后出现的内容。
4. 错误继承。早期的一个错误结论，会被后续轮次当作既定事实继续展开。
5. 成本上升。每一轮都会重新计入全部历史，对话越长，单次调用越贵、越慢。

## 1.3 为什么会跑偏

常见原因：

- 目标漂移。用户在中途插入新要求，旧目标没有被明确取消，模型在两套要求之间摇摆。
- 上下文过载。材料太多，关键约束被淹没。
- 话题分叉。从写作聊到工具，再聊到政策，模型把不同话题的信息混在一起。
- 隐含假设变化。用户以为某件事"上次说过了"，但那段内容已经被截断。
- 模型过度顺应。用户对某个错误结论表示认可后，模型倾向于继续沿着错误方向补充论据。

跑偏的典型信号：

- 重复已说过的内容
- 忘记早先设定的格式或篇幅
- 引用对话中不存在的信息
- 答非所问，只回应最后一句话
- 术语前后不一致
- 开始讨论与任务无关的话题

## 1.4 什么时候该开新对话

出现以下情况时，新开对话比继续往下聊更有效：

1. 任务已经切换。写作任务结束，开始做数据分析。
2. 目标发生实质变化。不是补充要求，而是换了交付物。
3. 历史中积累了错误结论，继续纠正的成本高于重来。
4. 上下文接近上限，模型开始遗忘早期约束。
5. 需要一份不受历史影响的干净输出，例如评审、对比、独立判断。
6. 对话中出现敏感信息，不希望它继续留在上下文中。

不建议频繁重开的情况：任务连续、需要保留已确认的事实和术语。这类任务应通过定期小结来维持上下文，而不是每次重来。

## 1.5 新对话的交接方法

开新对话前，写一份交接摘要，而不是把全部历史复制过去。摘要包含：

```
目标：这次要产出什么。
已确认事实：已经核实过的结论、数字、来源。
约束：篇幅、格式、语气、禁止内容。
术语：本项目使用的固定说法。
已完成：哪些部分已经定稿。
待办：还需要做什么。
未解决问题：哪些信息仍缺失。
```

把摘要放在新对话的开头，再附上必要的原始材料。这样既保留了关键信息，又去掉了历史中的噪音和错误。

## 1.6 长对话的管理策略

1. 固定系统提示。把角色、输出格式、禁止事项放在系统提示中，减少被后续内容冲淡。
2. 定期小结。每完成一个阶段，让模型输出"当前结论 + 未决问题"，作为下一阶段的开头。
3. 稳定信息外置。把术语表、资料、结论存到文档或知识库，需要时再引入，而不是一直挂在对话里。
4. 明确作废。旧要求不再适用时，明确写出"此前关于 X 的要求作废"。
5. 分段交付。长任务按阶段拆开，每段结束时确认，而不是一路聊到底。

## 1.7 小结

- 模型每次只能看到当前上下文窗口内的内容，没有跨对话的持久记忆。
- 对话记录与模型实际看到的上下文不是一回事，超限时会被截断或摘要。
- 跑偏的主要原因：目标漂移、上下文过载、话题分叉、错误继承和近因偏好。
- 任务切换、目标变更、错误积累、接近上限时，应开新对话。
- 新对话用交接摘要替代历史全文，保留目标、事实、约束、术语和待办。
- 长对话靠固定系统提示、定期小结和信息外置来维持稳定。
