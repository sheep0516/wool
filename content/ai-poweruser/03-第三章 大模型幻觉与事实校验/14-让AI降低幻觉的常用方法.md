# 让 AI 降低幻觉的常用方法

本节说明在输入、生成、输出三个环节可以采用的手段，以及每种手段的作用与局限。

## 3.1 三类手段

| 环节 | 手段 | 作用 |
|---|---|---|
| 输入侧 | 限定资料范围、提供原文、先检索 | 让模型基于给定材料回答，减少自由发挥 |
| 生成侧 | 要求引用、标注不确定、结构化输出、分步作答 | 让依据可见，降低自信编造 |
| 输出侧 | 程序校验、二次模型评审、人工复核 | 在交付前拦截错误 |

单一手段效果有限，通常需要组合使用。需要明确的是，这些方法降低幻觉概率，不能保证零幻觉。

## 3.2 限定资料范围

最有效的手段之一，是把回答限制在给定材料内，并明确材料之外的处理规则。

常用指令：

```
只根据以下材料回答。材料中没有的信息，直接写"材料未提及"，不要补充常识或推测。
回答时给出对应的原文片段。
```

作用：把开放域问答变成基于文本的抽取与归纳，减少模型调用参数中的模糊记忆。

局限：材料本身可能有错；长材料会超出上下文；分块不当会漏掉关键段落。

## 3.3 先检索再回答

先通过搜索或知识库获取资料，再让模型基于检索结果作答。这是 RAG 的基本思路，详见第6章。

需要区分两种情况：

- 真检索：确实调用了搜索或知识库，返回了可核对的内容。
- 伪检索：模型声称"已查阅资料"，但没有实际调用工具。后者仍是幻觉。

判断方法：看工具调用记录，或要求给出可点击链接、文件页码。

## 3.4 要求引用来源

要求模型对关键结论给出来源，可以让人快速核对，也能在一定程度上抑制编造。

有效写法：

```
每个关键结论后标注来源：文件名称 + 页码，或网页标题 + 链接。
无法给出来源的结论，标注为"无来源，需核实"。
```

局限：引用本身也可能是幻觉。模型可能编造看似合理的标题、作者和链接。因此引用必须可点击、可检索、可打开原文，不能只看格式是否完整。

## 3.5 标注不确定

要求模型区分把握程度，而不是统一用确定语气。

可采用四级标注：

| 等级 | 含义 | 处理 |
|---|---|---|
| 确定 | 材料中明确写到，或可直接计算 | 可使用，保留出处 |
| 较可能 | 多处材料一致，但未直接确认 | 抽检后使用 |
| 不确定 | 材料有冲突，或仅有间接依据 | 必须核实 |
| 未提及 | 材料中没有相关信息 | 不补写，或明确标注缺失 |

这种标注的价值在于把"隐性不确定"变成"显性待办"，便于分配核查精力。

## 3.6 结构化输出与程序校验

把输出限定为固定字段或 JSON，再用程序检查：

- 字段是否齐全
- 类型是否正确
- 数字是否在合理区间
- 枚举值是否在允许集合内
- 引用的文件是否存在

程序只能校验形式，不能校验事实。但形式校验可以过滤掉大量明显错误，减少人工负担。

## 3.7 降低随机性与多模型交叉

1. 降低温度。事实类任务使用低温度，减少采样带来的偶发错误。
2. 多次采样。同一问题跑多次，取一致答案；分歧本身是风险信号。
3. 双模型评审。一个模型生成，另一个模型对照材料检查，列出可疑点。
4. 分步执行。先抽取事实清单，再逐项核对，最后组织成文，避免一次性生成中错误被掩盖。

## 3.8 方法对比

| 方法 | 主要作用 | 局限 |
|---|---|---|
| 限定资料范围 | 减少自由发挥 | 材料错误、长文截断 |
| 先检索再回答 | 提供可核对依据 | 检索质量决定效果，存在伪检索 |
| 要求引用 | 让依据可见 | 引用可能被编造 |
| 标注不确定 | 暴露风险点 | 模型可能错误地标为"确定" |
| 结构化输出 | 便于程序校验 | 只校验形式，不校验内容 |
| 低温度与多次采样 | 提高稳定性 | 增加成本与延迟 |
| 双模型评审 | 发现遗漏与矛盾 | 评审模型也可能犯错 |

## 3.9 小结

- 降低幻觉需要输入、生成、输出三个环节配合，单一手段不够。
- 限定资料范围、先检索、要求引用，是三种最直接的手段。
- 引用必须可核对，格式完整不代表来源真实。
- 不确定标注把隐性风险变成显性待办事项。
- 结构化输出与程序校验能过滤形式错误，但事实仍需人工或外部来源核对。
- 所有方法都只能降低概率，不能消除幻觉。
