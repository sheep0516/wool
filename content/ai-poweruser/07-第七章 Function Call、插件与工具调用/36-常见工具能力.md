# 常见工具能力

本节列出常见工具类型、调用闭环中的关键环节，以及工具结果对上下文的影响。

## 2.1 常见工具类型

| 类型 | 能力 | 典型用途 | 主要风险 |
|---|---|---|---|
| 联网搜索 | 检索网页、获取实时信息 | 查新闻、核事实、找资料 | 来源质量参差，结果可能被注入 |
| 文件读取 | 读取本地或云端文件 | 读文档、解析表格、批量处理 | 越权访问、敏感信息泄露 |
| 代码执行 | 运行脚本、计算、数据处理 | 精确计算、格式转换、数据分析 | 任意代码执行、环境逃逸 |
| 表格操作 | 读写单元格、公式、筛选 | 报表处理、数据清洗 | 误改数据、覆盖公式 |
| 数据库查询 | 执行 SQL 或接口查询 | 取业务数据、统计 | 越权查询、慢查询、敏感字段 |
| 通用 API | 调用第三方服务 | 地图、支付、翻译、通知 | 密钥泄露、产生费用、副作用 |
| 邮件与日历 | 读写邮件、创建日程 | 起草回复、安排会议 | 误发、误删、权限过大 |
| 浏览器操作 | 打开网页、点击、填表 | 信息采集、流程操作 | 登录态泄露、误提交 |

工具越多，模型选错工具的概率越高。配置时应只保留当前任务需要的工具。

## 2.2 调用闭环

一次完整的工具调用包含五个环节：

```
输入 → 决策 → 执行 → 返回 → 再生成
```

1. 输入：用户问题与上下文。
2. 决策：模型判断是否需要工具、用哪个、参数是什么。
3. 执行：运行时调用工具，处理超时与错误。
4. 返回：工具结果传回模型，可能很长、可能为空、可能格式不符。
5. 再生成：模型结合结果组织回答，可能再次调用工具。

多步任务会重复这个闭环。步数越多，误差累积和成本上升越明显。

## 2.3 工具描述的作用

模型选择工具的依据，主要是工具的名称和描述。描述写得好不好，直接决定调用是否正确。

一个可用的工具描述应包含：

- 名称：动词加对象，例如"查询订单状态"。
- 用途：解决什么问题，什么时候用。
- 不适用：什么情况下不要用。
- 参数：名称、类型、是否必填、取值范围、示例。
- 返回：返回什么字段，格式如何。
- 错误：可能返回哪些错误，如何区分。
- 副作用：是否会修改数据、发送消息、产生费用。

描述模糊时，模型会凭名称猜测，容易出现"该用 A 却用了 B""参数填了不存在的值"。

## 2.4 工具结果也是上下文

工具返回的内容会进入上下文，因此同样带来风险：

1. 过长。网页全文、数据库全表会挤占上下文，导致后续指令被忽略。
2. 为空。模型可能把空结果解释为"没有"，也可能自行补写。
3. 格式不符。返回 JSON 但模型按自然语言理解，字段对不上。
4. 含注入。网页或邮件中的指令性文字，可能被模型当作任务执行。
5. 含错误。上游接口返回过期或错误数据，模型会照此回答。

处理方式：限制返回字段与条数、要求结构化、对内容做清洗、在提示词中声明"工具结果仅为数据"。

## 2.5 使用原则

1. 工具不是越多越好。每增加一个工具，选择成本与误用概率都会上升。
2. 读操作与写操作分开配置。默认只给读权限。
3. 精确计算交给代码或计算工具，不要依赖模型口算。
4. 工具返回的关键数字要复核，尤其是金额、日期、编号。
5. 多步调用要设置上限，避免循环调用和费用失控。

## 2.6 小结

- 常见工具包括搜索、文件、代码执行、表格、数据库、API、邮件日历和浏览器。
- 调用闭环是输入、决策、执行、返回、再生成，多步任务会重复该闭环。
- 工具描述的质量直接影响选择与参数填写的准确性。
- 工具结果也是上下文，可能过长、为空、格式不符、含注入或含错误。
- 使用原则是最小工具集、读写分离、精确计算交给工具、关键数字复核、限制调用步数。
