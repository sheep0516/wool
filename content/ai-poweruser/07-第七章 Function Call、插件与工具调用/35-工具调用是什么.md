# 工具调用是什么

本节说明模型的能力边界、工具调用的基本流程，以及 Function Call、插件、Agent 三者的关系。

## 1.1 模型本身能做什么

模型只能做一件事：根据上下文生成文本。它不能直接：

- 获取实时信息，例如天气、股价、新闻
- 读取本机文件或访问内部数据库
- 执行代码、修改表格、发送邮件
- 操作网页、提交表单、调用外部系统

它知道的是训练数据中的统计规律，能输出的是文字。凡涉及"获取新信息"或"改变外部状态"，都需要外部程序完成。

## 1.2 工具调用的流程

工具调用让模型可以"请求外部程序做事"，基本流程分四步：

```
1. 用户提问
2. 模型判断需要调用工具，输出结构化请求：工具名 + 参数
3. 外部运行时执行该工具，得到结果
4. 结果回传给模型，模型据此生成最终回答
```

示例：

```
用户：北京现在多少度？

模型输出：
{"tool": "get_weather", "arguments": {"city": "北京"}}

运行时调用天气接口，返回：
{"temperature": 25, "condition": "晴"}

模型回答：北京当前 25 摄氏度，晴。
```

模型不执行工具，只生成"调用意图"。真正执行的是外部程序，这一点决定了权限和安全必须由外部控制。

## 1.3 三个参与方

| 角色 | 负责 | 例子 |
|---|---|---|
| 模型 | 判断是否需要工具、选择工具、填写参数、解释结果 | 对话模型 |
| 运行时 | 执行调用、处理超时与错误、把结果回传 | Agent 平台、客户端 |
| 工具 | 提供具体能力 | 搜索接口、文件系统、数据库、API |

三者缺一不可。模型再强，没有运行时也无法执行；工具再多，模型不会选择也用不上。

## 1.4 Function Call、插件与 Agent 的关系

- Function Call 是机制。模型输出结构化调用请求，运行时执行。
- 插件是封装。把某个外部服务包装成模型可调用的工具，通常带有描述、参数定义和权限设置。
- Agent 是编排。在多步任务中反复调用工具、根据结果决定下一步，直到完成目标。

三者的关系可以理解为：Function Call 是底层能力，插件是接入方式，Agent 是使用方式。

## 1.5 工具调用改变了什么，没有改变什么

改变的部分：

- 模型可以获取实时信息，不再只依赖训练数据。
- 可以访问私有数据，例如内部文档、数据库。
- 可以执行动作，例如写文件、发消息。
- 可以通过计算工具完成精确运算。

没有改变的部分：

- 模型仍然可能选错工具、填错参数、误解返回结果。
- 工具返回的内容也可能是错误的、过期的、被注入的。
- 涉及外部状态改变的操作，仍然需要权限控制和人工确认。
- 工具调用不是"模型变万能"，它只是把能力边界向外扩展了一层。

## 1.6 小结

- 模型只能生成文本，获取信息与执行动作都需要外部工具。
- 工具调用是模型输出调用请求、运行时执行、结果回传、模型再生成的四步流程。
- 三个参与方是模型、运行时和工具，权限控制必须放在运行时。
- Function Call 是机制，插件是封装，Agent 是多步编排。
- 工具扩展了能力边界，但没有消除选错工具、参数错误和结果不可靠的问题。
