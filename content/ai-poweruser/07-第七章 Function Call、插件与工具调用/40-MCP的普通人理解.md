# MCP 的普通人理解

本节说明 MCP 是什么、解决什么问题，以及普通使用者需要知道的安全边界。

## 6.1 MCP 是什么

MCP（Model Context Protocol）是一套标准化协议，用于让模型客户端以统一方式连接外部工具和数据源。

在此之前，每个平台接入同一个工具，都要单独开发适配：A 平台一套接口，B 平台另一套接口，工具提供方要为每个平台重复实现。MCP 把这件事标准化：工具按协议实现一次，支持 MCP 的客户端都可以接入。

可以类比为 USB-C：设备与配件不必为每种组合单独设计接口，只要都遵循同一标准。

## 6.2 它解决什么问题

1. 降低接入成本。工具提供方不必为每个平台重复开发。
2. 统一发现方式。客户端可以列出可用工具及其描述。
3. 统一调用格式。参数、返回、错误有共同约定。
4. 便于组合。多个工具可以在同一客户端中被编排使用。
5. 支持本地与远程。工具可以运行在本机，也可以作为远程服务提供。

对普通使用者而言，直接收益是"可用的工具变多，配置步骤变简单"。

## 6.3 普通人需要知道的

不需要会开发 MCP 服务器，但需要知道三件事：

### 如何接入

通常是在客户端的设置中添加一个 MCP 服务器，填写启动命令或远程地址，完成授权。部分客户端提供图形界面，只需选择或填写配置。

### 权限范围

MCP 服务器可以访问它被授权的数据和系统。接入前应确认：

- 它能读取哪些文件或数据库
- 它是否能执行命令、写入数据
- 它连接的是本地还是远程服务
- 它的凭证从哪里来、存在哪里

### 安全边界

第三方 MCP 服务器是外部代码，可能读取数据、发起请求、执行操作。来源不明或缺少维护的服务器，存在数据泄露和恶意操作风险。

## 6.4 使用建议

1. 只接入可信来源的服务器。优先选择官方或开源社区维护良好的项目。
2. 最小权限。只授权完成任务所需的目录、表或接口。
3. 读写分离。默认使用只读服务器，需要写入时再单独配置。
4. 隔离环境。高风险工具在容器或独立账号中运行，避免影响主系统。
5. 审查工具列表。接入后先看它暴露了哪些工具，是否超出预期。
6. 关注更新。协议与实现仍在演进，版本不兼容会导致调用失败。
7. 保留日志。记录调用了哪些工具、访问了哪些数据。

## 6.5 局限

1. 支持范围有限。并非所有客户端和平台都支持 MCP，部分平台仍使用自有插件体系。
2. 质量参差。不同服务器的实现质量、错误处理和安全措施差异较大。
3. 安全责任在使用者。协议本身不提供权限模型，权限由客户端和服务器各自实现。
4. 调试成本。连接失败时，需要区分是客户端配置、服务器启动还是网络问题。

## 6.6 小结

- MCP 是连接模型客户端与外部工具的标准化协议。
- 它降低接入成本、统一发现与调用方式，便于工具组合。
- 普通使用者需要知道如何接入、授权范围和安全边界。
- 使用建议是最小权限、读写分离、可信来源、隔离环境和日志记录。
- 协议本身不解决权限与安全问题，责任仍在客户端配置和使用者选择。
