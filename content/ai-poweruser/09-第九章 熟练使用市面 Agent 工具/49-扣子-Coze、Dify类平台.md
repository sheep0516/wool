# 扣子-Coze、Dify 类平台

本节比较两类 Agent 平台的定位，并说明从模板复刻到改造的步骤。

## 3.1 共同能力

Coze 与 Dify 都属于"LLM 应用平台"，通常提供：

- 机器人或 Agent 创建
- 知识库上传与检索
- 插件与工具调用
- 工作流编排
- 多渠道发布：网页、API、社交平台、企业应用
- 日志与调试

它们的目标是让不会写代码的人也能搭出一个可用的 AI 应用。

## 3.2 定位差异

| 维度 | Coze/扣子 | Dify |
|---|---|---|
| 上手难度 | 低，模板多 | 中，配置项多 |
| 发布渠道 | 社交平台、聊天工具集成强 | 网页、API、可嵌入自有系统 |
| 知识库 | 平台内置，配置简单 | 可调分块与检索参数 |
| 工作流 | 可视化，适合中等复杂度 | 可视化，支持更复杂的编排 |
| 部署 | 以云端为主 | 支持自托管 |
| 适合 | 个人、轻量团队、对外 Bot | 企业内部应用、需要数据可控 |

选择时先看数据边界与发布渠道，再看复杂度。需要数据不出内网时，自托管能力是硬条件。

## 3.3 从模板复刻到改造

直接使用模板通常只能得到演示效果。有效做法是"先复刻，再改造"：

1. 选模板。选一个与目标场景接近的模板，不要选最复杂的。
2. 原样跑通。不改任何配置，先用示例数据跑一遍，确认能工作。
3. 记录结构。记录它用了哪些节点、知识库、插件、提示词。
4. 替换资料。把示例知识库换成自己的资料。
5. 改提示词。按自己的任务调整角色、约束、输出格式。
6. 改工具。替换不适用的插件，补充需要的接口。
7. 测试。用真实问题测试，包括没有答案的问题。
8. 发布。确认渠道、权限和日志后再上线。

每一步都应单独验证，不要一次性改完再测试。

## 3.4 改造时的注意点

1. 模板依赖。模板可能依赖特定插件或数据格式，替换后流程会断。
2. 知识库分块。默认分块未必适合你的文档，长条款、表格容易切碎。
3. 提示词继承。模板中的提示词可能带有演示性质的表述，需要清理。
4. 发布渠道权限。对外发布前确认可见范围，避免内部资料被公开。
5. 成本。插件调用、模型调用都计费，模板可能默认使用较贵的模型。
6. 日志。确认平台是否记录对话与调用，敏感内容是否会被留存。

## 3.5 常见失败

1. 只改知识库，不改提示词，输出仍是模板风格。
2. 一次性替换所有插件，出错后无法定位是哪一处。
3. 用演示问题测试通过，就认为可以上线。
4. 没有测试"知识库中没有答案"的问题，上线后频繁编造。
5. 发布到公开渠道，但知识库包含内部资料。
6. 没有版本记录，改坏后无法回退。

## 3.6 小结

- Coze 与 Dify 都提供机器人、知识库、插件、工作流和发布能力。
- Coze 上手快、渠道集成强；Dify 配置更细、支持自托管，适合企业内部。
- 复刻方法是选模板、原样跑通、记录结构、替换资料、改提示词、改工具、测试、发布。
- 改造要逐步验证，注意模板依赖、分块、提示词残留、渠道权限和成本。
- 常见失败是只换资料不换提示词、一次性全改、测试不覆盖无答案问题。
