# GPTs、Claude Projects、Gemini Gems 类工具

本节说明这类"自定义助手"的能力、适用场景与局限。

## 2.1 是什么

这类工具允许用户在对话模型上创建一个自定义助手，通常包含：

- 自定义指令：角色、任务、输出格式、禁止事项。
- 文件与知识库：上传资料，供助手检索。
- 工具：联网搜索、代码执行、图片生成等。
- 分享：生成链接，供他人使用。

它与普通对话的区别在于：配置一次，之后每次使用都带上同一套指令和资料，不需要重复粘贴。

## 2.2 适合的场景

| 场景 | 用法 |
|---|---|
| 个人写作助手 | 固定文风、篇幅、结构，每次只给主题 |
| 项目资料问答 | 上传项目文档，回答需求与决策问题 |
| 学习教练 | 固定讲解深度、提问方式、练习风格 |
| 团队规范助手 | 统一术语、格式、审核标准 |
| 领域问答 | 上传手册、制度、课程资料 |

共同点是：任务重复、资料固定、输出格式稳定。

## 2.3 搭建步骤

1. 定义用途。写清解决什么问题，不做什么。
2. 写指令。包含角色、任务、输入要求、输出格式、边界与不确定处理。
3. 上传资料。只放与任务相关的文档，清理旧版本。
4. 测试。用真实问题测试，包括知识库中没有答案的问题。
5. 调整。根据失败案例修改指令或资料。
6. 分享。确认分享范围与数据边界后再对外。

## 2.4 局限

1. 平台绑定。指令、资料、对话记录存在平台内，迁移困难。
2. 检索质量有限。知识库的分块与检索由平台控制，无法细调。
3. 权限较粗。分享通常只有"可用/不可用"，缺少细粒度权限。
4. 流程能力弱。适合单轮或少量多轮任务，不适合复杂多步编排。
5. 数据边界。上传的资料是否用于训练、存储多久，取决于平台条款。
6. 版本变化。模型升级后，同一指令的表现可能改变。

## 2.5 使用注意

1. 指令中不要放密钥、内部地址、个人信息。
2. 知识库定期更新，删除过期版本。
3. 分享前确认资料是否包含敏感内容。
4. 对外分享的助手，明确写出能力边界，避免使用者误以为它能做所有事。
5. 保留一份指令和资料清单，便于迁移。
6. 换模型后重新测试，不要假设行为不变。

## 2.6 与 Agent 平台的差别

| 维度 | 自定义助手 | Agent 平台 |
|---|---|---|
| 配置复杂度 | 低 | 中到高 |
| 多步流程 | 弱 | 强 |
| 工具集成 | 平台内置 | 可接插件、API、工作流 |
| 发布渠道 | 链接、应用商店 | 网页、API、社交平台、企业应用 |
| 适合 | 个人、轻量团队 | 需要流程与集成的场景 |

如果任务只是"固定指令加固定资料"，自定义助手足够。需要多步执行、跨系统操作时，再考虑 Agent 平台。

## 2.7 小结

- 这类工具的本质是"固定指令 + 文件知识库 + 内置工具 + 分享"。
- 适合重复、资料固定、格式稳定的个人与轻量团队场景。
- 搭建步骤是定义用途、写指令、上传资料、测试、调整、分享。
- 局限是平台绑定、检索不可细调、权限粗、流程能力弱和数据边界不清。
- 任务简单时用它足够，需要多步与集成时再上 Agent 平台。
