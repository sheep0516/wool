# 跟练复刻法

本节说明如何通过复刻模板、改造和失败复盘，真正掌握一个 Agent 工具。

## 7.1 方法

对每个主力工具，至少完成三轮练习：

1. 复刻 3 个模板。原样跑通，理解结构。
2. 每个模板做 1 次改造。换成自己的资料、任务或渠道。
3. 每个模板做 1 次失败复盘。记录哪里坏了、为什么、怎么修。

只看教程不会形成能力。复刻、改造、复盘三步，分别对应"看懂""会用""知道边界"。

## 7.2 复刻阶段

目标是把模板跑通，不改结构。

步骤：

1. 选 3 个与自己的任务接近的模板，覆盖不同能力：知识库问答、工具调用、工作流。
2. 原样导入，用模板自带的示例数据运行。
3. 记录结构：触发方式、节点、提示词、知识库、插件、输出。
4. 保存运行结果，作为对照基线。
5. 写下不理解的地方，后续查文档或测试。

复刻阶段的重点是理解"它由哪些部分组成"，而不是马上改成自己的场景。

## 7.3 改造阶段

每个模板至少做一次改造，任选一种：

| 改造类型 | 做法 | 检验什么 |
|---|---|---|
| 换资料 | 把示例知识库换成自己的文档 | 检索是否命中，分块是否合适 |
| 换任务 | 保持结构，改成自己的任务 | 提示词是否通用 |
| 换渠道 | 从网页发布改为聊天工具或 API | 渠道限制与权限 |
| 加约束 | 增加输出格式、禁止项、不确定规则 | 模型是否遵循 |
| 加确认 | 在写操作前加入人工确认 | 流程是否能暂停与恢复 |
| 换模型 | 同一流程换一个模型 | 稳定性与成本变化 |

改造时一次只改一处，改完立即测试。一次改多处，出错后无法定位。

## 7.4 失败复盘

每个模板至少制造或遇到一次失败，并完成复盘。复盘模板：

```
现象：什么情况下出错，输出是什么。
定位：失败发生在哪一步（知识库、分块、检索、提示词、工具、渠道）。
原因：为什么会这样，是配置问题、数据问题还是模型问题。
修复：改了什么，改后结果如何。
预防：以后如何避免，例如加校验、加测试用例、调整分块。
```

常见的失败来源：

- 知识库没有这份资料，模型编造
- 分块切断条款，检索到半句
- 工具参数格式错误
- 渠道权限不足，发布失败
- 输出格式不符合下游要求
- 模型升级后行为变化

## 7.5 记录方式

每个工具建一份笔记，包含：

| 内容 | 说明 |
|---|---|
| 工具与版本 | 名称、版本、使用的模型 |
| 复刻的模板 | 模板名、来源、结构摘要 |
| 改造记录 | 改了什么、结果如何 |
| 失败案例 | 现象、原因、修复、预防 |
| 能力边界 | 能做什么、不能做什么 |
| 成本 | 单次与月度支出 |
| 替代方案 | 失效时换什么 |

这份笔记比收藏夹更有用，因为它记录的是自己的验证结果。

## 7.6 时间安排

不需要集中学习。可以采用"每周一个工具"的节奏：

1. 第一周：复刻 3 个模板，跑通。
2. 第二周：完成 3 次改造。
3. 第三周：完成失败复盘，整理笔记。
4. 之后：每月用一次，保持熟悉度。

重点是完成闭环，而不是快速浏览很多工具。

## 7.7 常见问题

1. 只复刻不改造。模板能跑，但不会用到自己的场景。
2. 只改造不复盘。遇到失败就放弃，不知道边界在哪。
3. 一次改多处。出错后无法定位原因。
4. 不记录版本。模型或平台升级后，结果变化无法解释。
5. 追新工具。每个工具都只停留在复刻阶段，没有一个真正掌握。
6. 不做成本记录。上线后才发现费用超出预期。

## 7.8 小结

- 掌握工具的方法是复刻 3 个模板、每个改造 1 次、每个失败复盘 1 次。
- 复刻阶段理解结构，改造阶段换成自己的场景，复盘阶段明确边界。
- 改造一次只改一处，改完立即测试。
- 复盘记录现象、定位、原因、修复和预防。
- 每个工具维护一份笔记，记录模板、改造、失败、边界、成本和替代方案。
- 按周推进，完成闭环比浏览大量工具更有效。
