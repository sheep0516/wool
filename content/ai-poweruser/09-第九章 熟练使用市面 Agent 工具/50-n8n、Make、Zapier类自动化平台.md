# n8n、Make、Zapier 类自动化平台

本节说明这类平台的能力、与 Agent 平台的差别，以及使用时的注意事项。

## 4.1 能力范围

这类平台的核心是"连接应用、按规则自动执行"：

- 跨应用连接：表单、邮件、表格、日历、数据库、聊天工具。
- API 编排：调用没有现成连接器的服务。
- 定时触发：按小时、天、周执行。
- 条件分支与数据处理：过滤、格式转换、聚合。
- 人工确认：部分平台支持暂停等待审批。
- AI 节点：调用模型做分类、摘要、抽取。

它们解决的是"确定性流程自动化"，而不是"开放式任务执行"。

## 4.2 与 Agent 平台的差别

| 维度 | 自动化平台 | Agent 平台 |
|---|---|---|
| 流程 | 预先定义，路径固定 | 模型临场决定下一步 |
| 可预测性 | 高 | 低 |
| 调试 | 按节点排查 | 依赖对话记录 |
| 适合 | 重复、规则明确 | 开放、需要判断 |
| 风险 | 规则写错会稳定地错 | 可能误用工具或跑偏 |

两者可以组合：自动化平台负责触发、数据搬运和通知，Agent 平台负责其中的判断与生成环节。

## 4.3 典型用法

1. 表单提交后写入表格，并发送通知。
2. 收到邮件后分类，生成回复草稿，转人工审核。
3. 每周定时汇总多个表格，生成周报。
4. 监控网页或接口变化，有更新时推送。
5. 跨系统同步数据，例如 CRM 与表格之间。

这些任务的共同点是步骤固定、输入输出明确、可以重复执行。

## 4.4 选择要点

1. 应用覆盖。常用工具是否已有连接器，没有时是否支持自定义 API。
2. 流程复杂度。是否支持分支、循环、错误处理和人工确认。
3. 部署方式。是否支持自托管，数据能否留在内网。
4. 成本。按任务数还是按执行次数计费，高频场景下的实际支出。
5. 可观测性。是否提供执行历史、每步输入输出、失败重试。
6. 迁移成本。流程能否导出，是否被专有格式锁定。

## 4.5 使用注意

1. 凭证管理。API 密钥存在平台的安全配置中，不写入流程说明。
2. 幂等。写操作要能识别重复执行，避免重复发送或重复入库。
3. 限流。批量任务控制并发，避免触发上游限制。
4. 日志。记录每步输入输出，便于排查。
5. 人工确认。对外发送、提交、付款类操作保留确认环节。
6. 版本。流程修改后保留旧版本，出问题可回退。

## 4.6 常见失败

1. 连接器授权过期，流程静默失败。
2. 数据结构变化，字段对不上，写入空值。
3. 重试导致重复发送。
4. 批量任务触发限流，部分条目失败但未记录。
5. 流程过于复杂，一个平台承担了本应由代码处理的数据清洗。
6. 没有告警，失败数天后才发现。

## 4.7 小结

- 这类平台解决确定性流程自动化：跨应用连接、API 编排、定时触发。
- 与 Agent 平台的区别是路径固定、可预测性高、按节点调试。
- 典型用法是表单入库、邮件分类、定时汇总、变更监控和跨系统同步。
- 选型看应用覆盖、流程复杂度、部署方式、成本、可观测性和迁移成本。
- 使用注意凭证、幂等、限流、日志、人工确认和版本回退。
