# Agent 工具地图

本节按"解决什么问题"划分 Agent 工具，而不是按品牌或热度。

## 1.1 四类主要工具

| 类型 | 核心能力 | 典型任务 | 不适合 |
|---|---|---|---|
| 通用 Agent 平台 | 对话、工具调用、多步执行、知识库 | 研究、分析、资料整理、轻量自动化 | 需要严格流程控制的批量任务 |
| 工作流平台 | 固定步骤编排、跨应用连接、定时触发 | 表单处理、数据同步、定时汇总 | 开放式推理、需要临场判断 |
| 个人助手 | 自定义指令、文件、知识库、分享 | 写作规范、项目资料问答、学习教练 | 复杂多步任务、跨系统操作 |
| 编程 Agent | 读写代码、执行命令、调试 | 代码生成、重构、排错 | 非编程任务、高风险生产操作 |

除这四类，还有企业协作平台内嵌的助手、浏览器操作类 Agent、多 Agent 框架。它们大多可以归入上述类别，只是接入方式不同。

## 1.2 按问题分类，而不是按工具

选工具前先回答四个问题：

1. 任务是一次性的，还是每天重复？
2. 步骤是否固定，还是每次都要临场判断？
3. 结果是否需要对外发布或多人使用？
4. 数据是否敏感，能否离开本机或内网？

对应的判断：

| 情况 | 优先考虑 |
|---|---|
| 一次性、需要判断 | 通用对话或通用 Agent |
| 每天重复、步骤固定 | 工作流平台 |
| 个人长期使用、资料固定 | 个人助手 |
| 涉及代码 | 编程 Agent |
| 组织内使用、权限复杂 | 企业协作平台助手 |

## 1.3 追新的问题

Agent 工具更新很快，但同质化也明显。多数平台都提供对话、知识库、插件、工作流和发布渠道，差别在于集成范围、权限模型、成本和稳定性。

频繁更换工具的成本：

- 学习成本。每个平台的编排逻辑、调试方式不同。
- 迁移成本。知识库、提示词、流程难以完整导出。
- 维护成本。多平台并存时，排查问题需要跨系统。
- 经验失效。刚熟悉的技巧在新工具上不适用。

更有效的做法是：固定一两类主力工具，把精力放在任务设计和失败复盘上。

## 1.4 能力层与工具层

工具会变，能力层相对稳定：

| 能力层 | 需要的工具 |
|---|---|
| 语言处理 | 通用对话模型 |
| 信息检索 | 搜索型 AI、知识库 |
| 文档处理 | 文档问答、知识库平台 |
| 流程执行 | 工作流平台、Agent 平台 |
| 代码操作 | 编程 Agent |

选工具时先确认自己缺哪一层能力，再看具体产品。缺流程执行能力时，换多少个对话模型都不会解决问题。

## 1.5 小结

- Agent 工具分为通用 Agent 平台、工作流平台、个人助手和编程 Agent 四类。
- 分类依据是解决什么问题，而不是品牌或热度。
- 判断维度是频率、步骤是否固定、是否对外、数据是否敏感。
- 工具同质化明显，频繁更换带来学习、迁移、维护和经验四类成本。
- 先确认缺哪一层能力，再选具体工具。
