# RAG 链路拆解

本节按步骤拆解 RAG 的完整链路，说明每一步的作用和常见故障点。

## 2.1 链路步骤

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 摄入 | 读取文档，解析为文本 | 原始文本 |
| 清洗 | 去掉页眉页脚、乱码、重复内容 | 干净文本 |
| 分块 | 按语义或结构切成片段 | 文本块 |
| 向量化 | 把文本块转换为向量 | 向量与索引 |
| 检索 | 根据问题找出相关文本块 | 候选片段 |
| 重排 | 对候选片段重新排序 | 精选片段 |
| 生成 | 把片段与问题交给模型 | 带依据的回答 |

这条链路中任何一步出错，最终都会表现为"答得不对"，但原因可能完全不同。

## 2.2 每一步会怎么坏

### 摄入

扫描件识别错误、表格结构丢失、多栏排版顺序错乱、图片中的文字没有被提取。结果是原文信息在进入系统前就已经缺失。

### 清洗

页眉页脚被当作正文、章节编号混入内容、重复段落未去重、编码错误产生乱码。这些噪声会进入分块，干扰检索。

### 分块

- 块太大：一个片段包含多个主题，检索命中后模型拿到大量无关内容。
- 块太小：一句话被切断，缺少上下文，检索到也无法理解。
- 边界错误：把论证切成两半，每半都不完整。
- 丢失标题：片段脱离章节标题后，失去主题信息。

### 向量化

嵌入模型与文档语言、领域不匹配；专有名词、缩写无法表达；不同版本的模型混用，导致向量空间不一致。

### 检索

只做向量检索时，精确术语、编号、人名容易漏掉；top-k 太小会漏，太大则引入噪声；没有相似度阈值时，不相关内容也会被当作依据。

### 重排

未启用重排，或重排模型能力不足，导致真正相关的片段排在后面，被截断掉。

### 生成

模型忽略给定材料，凭记忆回答；材料之间冲突时随意选一个；引用位置标错；把片段中的否定或条件简化掉。

## 2.3 需要懂什么，不需要懂什么

普通人不需要自己训练嵌入模型、搭建向量数据库或调优索引参数。需要懂的是：

1. 每个环节的存在与作用，知道问题可能出在哪。
2. 如何查看中间结果，尤其是"检索到了哪些片段"。
3. 分块与文档结构的关系，知道为什么标题、目录、段落格式重要。
4. 检索失败与生成失败的区分方法。

这些知识足以判断一个知识库工具是否可用，以及在出问题时该改哪里。

## 2.4 排查的基本方法

不要只看最终答案，要看中间产物：

1. 知识库里有没有这份文档，版本是否最新。
2. 文档解析后，关键内容是否完整。
3. 分块后，相关片段是否完整，是否保留标题。
4. 检索时，实际召回了哪些片段，相似度是多少。
5. 重排后，顺序是否合理。
6. 提示词是否要求"只根据材料回答"并给出引用。

多数问题在前三步就能发现，不需要改模型。

## 2.5 小结

- RAG 链路包括摄入、清洗、分块、向量化、检索、重排、生成。
- 每一步都可能出错，最终都表现为"答得不对"，但原因不同。
- 摄入与解析决定信息是否完整，分块决定检索质量，检索与重排决定材料是否相关，生成决定是否遵循材料。
- 普通人不需要会训练，但要知道每步的作用和故障表现。
- 排查时先看中间产物，而不是直接换模型或重建知识库。
