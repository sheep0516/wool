# 知识库组织方法

本节说明按什么维度组织资料、目录与标签如何配合，以及元数据应包含哪些字段。

## 4.1 四种组织维度

| 维度 | 适合 | 例子 |
|---|---|---|
| 按项目 | 资料围绕具体目标，生命周期短 | 某产品需求、某次活动 |
| 按主题 | 长期积累，跨项目复用 | 提示词、行业研究、技术笔记 |
| 按时间 | 日志、会议、版本记录 | 周报、会议纪要、迭代记录 |
| 按权限 | 资料敏感度不同 | 公开、内部、机密 |

实际使用中通常组合：先按权限分库，再按项目或主题分目录，时间作为文件命名的一部分。

## 4.2 目录、标签与元数据

三者作用不同，不能互相替代：

- 目录：表达稳定的层级关系，适合浏览和权限隔离。
- 标签：表达交叉属性，适合检索和多维筛选。
- 元数据：表达结构化字段，适合过滤、排序和引用。

建议以目录为主干，标签为补充，元数据写在文件头部或表格中。只靠标签会导致结构混乱，只靠目录会导致跨类检索困难。

## 4.3 文件命名

命名要能看出"是什么、什么时候、哪一版"：

```
YYYY-MM-DD_类型_主题_v版本
```

例如：

```
2026-03-01_会议纪要_产品评审_v2
2026-02-20_制度_报销流程_v1
```

规则：

1. 日期用 ISO 格式，便于排序。
2. 类型用固定词表，例如会议、制度、报告、笔记、合同。
3. 主题简短，不使用空格和特殊符号。
4. 版本号明确，避免"最终版""最终版2"这类命名。
5. 不使用"新建文档""副本"作为正式名称。

## 4.4 元数据字段

| 字段 | 说明 |
|---|---|
| 标题 | 完整名称 |
| 来源 | 官方文件、内部撰写、外部转载 |
| 日期 | 创建或发布时间 |
| 版本 | 当前版本号 |
| 负责人 | 维护人 |
| 密级 | 公开、内部、机密 |
| 关键词 | 3 到 5 个检索词 |
| 适用范围 | 哪些项目或场景可用 |
| 状态 | 有效、草稿、已废止 |

元数据的作用是让检索可以按条件过滤，例如"只看有效版本""只看内部资料"。

## 4.5 结构与分块的关系

知识库的检索效果，很大程度取决于文档本身的结构：

1. 每份文档有明确的标题层级，不要用加粗代替标题。
2. 每个章节自成一段，不要把多个主题混在同一段。
3. 表格有表头，图有说明，避免只有图片没有文字。
4. 长文档提供目录，便于按章节切分。
5. 术语表单独成节，统一缩写与全称。

结构清晰的文档，分块后每个片段仍然带有主题信息；结构混乱的文档，切出来的片段往往无法独立理解。

## 4.6 权限设计

1. 按密级分库。机密资料单独建库，不与公开资料混放。
2. 按项目隔离。不同项目的资料默认互不可见。
3. 最小权限。只给需要的人访问权限，不按部门批量开放。
4. 共享链接可撤销。对外分享使用可设置有效期的链接。
5. 记录访问日志。至少能查到谁在什么时候访问了什么。
6. 人员变动时回收权限。

## 4.7 维护机制

1. 定期归档。过期项目整体移入归档区，不参与默认检索。
2. 去重。同一文档多个版本只保留当前有效版本，旧版标注"已废止"。
3. 更新责任人。每类资料有明确维护人，避免无人负责。
4. 季度检查。核对元数据、失效链接、过期制度。
5. 索引同步。新增、删除、改名后更新索引，避免检索到不存在的文件。

## 4.8 示例结构

```
知识库/
├── 公开/
│   ├── 行业研究/
│   └── 学习资料/
├── 内部/
│   ├── 项目A/
│   │   ├── 需求/
│   │   ├── 会议/
│   │   └── 决策记录/
│   └── 项目B/
├── 机密/
│   └── 合同与财务/
└── 归档/
    └── 已结束项目/
```

目录表达权限与项目关系，文件名表达时间与版本，元数据表达状态与适用范围。

## 4.9 小结

- 组织维度有项目、主题、时间、权限，实际使用中组合使用。
- 目录表达层级，标签表达交叉属性，元数据表达结构化字段，三者不能互相替代。
- 文件命名包含日期、类型、主题、版本，避免"最终版"式命名。
- 文档结构清晰，分块后片段才能独立可读。
- 权限按密级分库、按项目隔离、最小授权、可撤销、有日志。
- 维护包括归档、去重、责任人、季度检查和索引同步。
