# RAG 常见失效与排查

本节把 RAG 的失效分为三类，并给出从知识库到提示词的排查顺序。

## 5.1 三类失效

| 类型 | 表现 | 环节 |
|---|---|---|
| 没检索到 | 回答与资料无关，或说"没有相关信息" | 知识库、分块、检索 |
| 检索到了没用 | 引用了一堆不相关片段，答案仍不对 | 检索、重排 |
| 用了但答错 | 引用了正确片段，结论却错误 | 生成、提示词 |

三类失效的处理方式完全不同。先判断属于哪一类，再动手修改。

## 5.2 没检索到

常见原因：

1. 知识库里根本没有这份资料，或版本不是最新的。
2. 文档解析失败，关键内容没有被提取。
3. 分块切断了相关内容，检索只能命中半句。
4. 问题措辞与文档用词差异大，例如口语问法与书面术语不一致。
5. 专有名词、编号、缩写无法被向量检索表达。
6. 索引未更新，新增文档没有被收录。
7. top-k 设置过小，正确片段没有进入候选。

排查方法：

- 先确认文档是否存在、是否为当前版本。
- 直接搜索原文关键词，看能否命中。
- 查看解析后的文本，确认关键段落是否完整。
- 查看检索返回的片段，确认是否包含答案。
- 换一种问法，使用文档中的术语再试。

## 5.3 检索到了没用

常见原因：

1. top-k 过大，引入大量弱相关片段，模型被噪声干扰。
2. 没有重排，相关片段排在后面被截断。
3. 只做向量检索，精确关键词没有命中。
4. 相似度阈值过低，不相关内容也被当作依据。
5. 分块过大，一个片段里只有一小部分相关。
6. 缺少元数据过滤，检索范围包含了过期或无关资料。

排查方法：

- 查看实际召回的片段及其相似度。
- 缩小 top-k，观察答案是否改善。
- 启用混合检索，把关键词与向量结果合并。
- 加入元数据过滤，例如只检索有效版本。
- 调整分块大小，按章节而不是按固定字数切分。

## 5.4 用了但答错

常见原因：

1. 材料本身有错误，模型忠实复述了错误内容。
2. 多个片段相互冲突，模型随意选择或强行合并。
3. 提示词没有要求"只根据材料回答"，模型混入自身记忆。
4. 片段缺少上下文，模型误解了指代关系。
5. 模型在材料基础上做了未经验证的推理。
6. 引用位置标错，答案与来源对不上。
7. 条件、否定、例外在片段中被简化。

排查方法：

- 核对引用片段原文，确认答案是否真的来自材料。
- 检查材料是否有冲突，冲突时是否应该分别陈述。
- 检查提示词是否明确限定材料范围。
- 检查片段是否保留了标题与前后文。
- 对关键结论要求给出原文片段，而不只是文件名。

## 5.5 排查顺序

按以下顺序检查，避免一上来就换模型或重建知识库：

1. 知识库。资料是否存在、是否最新、解析是否完整。
2. 分块。片段是否完整，是否保留标题，是否切断了语义。
3. 检索。实际召回了什么，相似度如何，top-k 是否合理。
4. 重排。顺序是否正确，是否有过滤。
5. 提示词。是否限定材料范围，是否要求引用，是否允许"未提及"。
6. 模型。以上都正常仍出错，才考虑换模型或调整参数。

多数问题在前三步就能定位。

## 5.6 修复手段对照

| 问题 | 修复手段 |
|---|---|
| 问法不匹配 | 改写查询，加入文档术语与同义词 |
| 精确词漏检 | 混合检索，关键词与向量并用 |
| 片段不完整 | 调整分块，按章节切分，保留标题 |
| 噪声过多 | 降低 top-k，启用重排与阈值 |
| 过期资料干扰 | 元数据过滤，只检索有效版本 |
| 模型自由发挥 | 提示词限定材料范围，要求引用 |
| 材料冲突 | 要求分别列出不同说法及来源 |
| 引用错位 | 要求给出原文片段与页码 |

## 5.7 小结

- 失效分三类：没检索到、检索到了没用、用了但答错。
- 没检索到看知识库、解析、分块和查询措辞。
- 检索到了没用看 top-k、重排、混合检索和元数据过滤。
- 用了但答错看材料正确性、冲突处理、提示词约束和引用核对。
- 排查顺序是知识库、分块、检索、重排、提示词、模型，不要跳过前面的环节直接换模型。
