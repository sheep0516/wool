# RAG 的普通人直觉

本节说明 RAG 的基本思路、它能解决和不能解决的问题，以及与微调的差别。

## 1.1 RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）的流程可以概括为：先从资料库中检索与问题相关的内容，再把检索结果和问题一起交给模型，让模型基于这些内容作答。

用考试作类比：闭卷考试靠记忆，开卷考试可以翻书。RAG 相当于给模型配了一本书，并要求它按书上的内容回答。

```
用户问题 → 检索相关资料 → 资料 + 问题 → 模型生成 → 带依据的回答
```

## 1.2 它解决什么问题

1. 知识过期。模型训练有截止时间，RAG 可以接入最新文档。
2. 私有资料。内部制度、项目文档、个人笔记，模型训练时没有见过，可以通过知识库提供。
3. 可追溯。回答可以附带来源，便于核对。
4. 减少幻觉。把回答限制在给定材料内，比让模型自由回忆更可靠。

## 1.3 它不解决什么问题

需要明确边界，否则容易对 RAG 产生错误预期：

- 不提升模型能力。检索到的材料如果超出模型的理解范围，仍然答不好。
- 不保证材料正确。知识库里如果有错误文档，模型会照着错误回答。
- 不保证一定检索到。检索失败时，模型可能答非所问，或退回自由发挥。
- 不解决推理问题。多步推理、计算、比较，仍依赖模型自身能力或外部工具。
- 不自动理解结构。表格、扫描件、复杂版式在解析阶段就可能丢失信息。

一句话：RAG 让模型"有据可查"，不让模型"变聪明"。

## 1.4 与微调的差别

| 维度 | RAG | 微调 |
|---|---|---|
| 作用 | 提供外部资料 | 改变模型行为或风格 |
| 更新方式 | 更新文档即可 | 重新训练 |
| 成本 | 较低，主要是检索与调用 | 较高，需要数据与算力 |
| 可解释性 | 可给出处 | 难以说明依据 |
| 适合 | 知识频繁更新、需要引用 | 固定任务格式、特定风格、领域表达 |

多数个人场景优先用 RAG。只有当任务需要固定的输出格式、特定的表达风格，或需要模型学会某种领域语言时，才考虑微调。

## 1.5 日常使用中的直觉

1. 知识库的质量决定上限。文档缺失、过期、结构混乱，检索再好也答不对。
2. 检索不到时，模型不会承认"库里没有"，而是可能用常识补写。所以回答要带引用。
3. 问题写法影响检索。用文档中可能出现的词，比用口语化描述更容易命中。
4. 引用要能打开原文。只标注"根据资料"而没有具体位置，等于没有依据。
5. 知识库不是越大越好。覆盖面、结构、更新频率，比文档数量重要。

## 1.6 小结

- RAG 是先检索资料，再让模型基于资料回答。
- 它解决知识过期、私有资料和可追溯问题，不提升模型本身的能力。
- 知识库质量决定回答上限，检索失败时模型可能退回自由发挥。
- 与微调相比，RAG 更新成本低、可解释性强，适合知识型任务。
- 使用时要关注覆盖度、结构、更新频率和引用可核对。
