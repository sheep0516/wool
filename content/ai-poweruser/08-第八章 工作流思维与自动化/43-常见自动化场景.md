# 常见自动化场景

本节给出四类常见场景的流程、失败点和人工确认位置，用于选择第一个要搭建的工作流。

## 3.1 资料收集、总结、归档

流程：

```
触发器：定时或手动
1. 从指定来源收集链接或文件
2. 抓取正文，清洗
3. 调用模型生成摘要与标签
4. 按标签写入对应目录或表格
5. 归档原始文件，记录来源
```

失败点：

- 来源页面结构变化，抓取失败
- 正文含广告或无关内容，摘要失真
- 标签不稳定，同一主题分到不同类别
- 重复文件被多次归档

人工确认位置：首次运行时检查摘要质量与标签规则；后续按周抽查。

## 3.2 邮件或表单分类与回复草稿

流程：

```
触发器：收到新邮件或表单提交
1. 读取内容
2. 分类：咨询、投诉、合作、垃圾
3. 按类别生成回复草稿
4. 写入待审核队列
5. 人工确认后发送
```

失败点：

- 分类边界模糊，投诉被当作咨询
- 草稿承诺了未授权的条件
- 收件人、附件识别错误
- 重复邮件生成多份草稿

人工确认位置：所有对外发送前必须确认；分类规则变更后需重新抽检。

## 3.3 会议记录转待办与提醒

流程：

```
触发器：会议结束或转录完成
1. 读取转写文本
2. 按议题分段
3. 抽取结论、待办、负责人、截止时间
4. 写入任务系统
5. 到期前发送提醒
```

失败点：

- 说话人识别错误，待办分配错人
- 口语中的条件被简化，结论失真
- 截止时间缺失，被模型自行填写
- 重复会议生成重复任务

人工确认位置：待办写入前由会议主持人确认，尤其是负责人和截止时间。

## 3.4 内容选题、草稿、审核、发布

流程：

```
触发器：固定周期
1. 收集素材与热点
2. 生成选题清单
3. 人工选定题目
4. 生成草稿
5. 人工审核与修改
6. 发布或排期
```

失败点：

- 素材来源不可靠，事实错误
- 选题同质化
- 草稿违反平台规则
- 发布环节误操作

人工确认位置：选题、定稿、发布三个节点都需要人确认。发布环节不应全自动。

## 3.5 四类场景的共性

| 特征 | 说明 |
|---|---|
| 输入不稳定 | 来源格式、质量每次不同，需要清洗与校验 |
| 需要分类 | 不同类别走不同路径 |
| 需要人工审核 | 对外内容、任务分配、发布动作 |
| 失败可重试 | 单次失败不影响整体，可重新执行 |
| 需要留痕 | 要能查到处理过哪些内容、结果如何 |

这些共性决定了工作流必须包含清洗、分支、人工确认和日志。

## 3.6 先做哪一类

优先选择满足以下条件的场景：

1. 高频。每天或每周都会发生。
2. 规则清晰。分类和判断标准可以写成明确条件。
3. 错误可容忍。出错后可以修正，不会造成不可逆后果。
4. 步骤少。三到五步可以跑通完整闭环。
5. 有明确的人工确认点。出问题时人能及时介入。

不建议第一个工作流就做付款、对外发布、批量删除这类高风险流程。

## 3.7 小结

- 四类常见场景：资料归档、邮件分类回复、会议待办、内容发布。
- 每类都要考虑输入清洗、分类分支、人工确认和失败重试。
- 失败点集中在来源格式、分类边界、信息抽取和重复处理。
- 对外发送、任务分配、发布动作必须保留人工确认。
- 第一个工作流应选高频、规则清晰、步骤少、错误可容忍的场景。
