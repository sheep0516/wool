# 对话不是工作流

本节说明对话与工作流的差别，以及什么情况下应该从对话升级为工作流。

## 1.1 对话模式的特点

对话是"问一句、答一句"的交互方式：

- 由人发起，每一轮都需要人参与。
- 步骤不固定，根据上一轮结果临时决定下一步。
- 结果不要求一致，同一问题可以接受不同回答。
- 没有状态记录，换一次对话就重新开始。
- 无法自动运行，也无法监控执行情况。

对话适合探索、写作、分析、答疑这类需要人来判断方向的任务。

## 1.2 工作流的特点

工作流是把多步骤任务固定成一条可重复执行的流程：

- 由事件触发，不需要每次手动发起。
- 步骤固定，顺序和分支预先定义。
- 每一步有明确的输入和输出。
- 可以记录状态、日志和执行结果。
- 失败时可以重试、告警或转人工。

工作流适合高频、规则清晰、需要一致性和可追溯的任务。

## 1.3 对比

| 维度 | 对话 | 工作流 |
|---|---|---|
| 发起方式 | 人工 | 定时、事件、手动触发 |
| 步骤 | 不固定 | 预先定义 |
| 一致性 | 每次可能不同 | 同一输入得到相近结果 |
| 状态 | 无持久记录 | 有状态与日志 |
| 监控 | 难以量化 | 可统计成功率、耗时、失败原因 |
| 适用 | 探索、判断、创作 | 重复、批量、需审计 |
| 变更成本 | 低 | 较高，需修改流程 |

## 1.4 什么时候对话就够了

- 任务只做一次，或频率很低。
- 每次输入差异大，无法固定步骤。
- 需要人来判断方向和取舍。
- 结果只需自己使用，不需要审计。
- 流程还在探索阶段，尚未稳定。

在这些情况下，强行搭工作流会增加维护成本，收益有限。

## 1.5 什么时候需要工作流

满足以下多数条件时，适合改成工作流：

1. 高频重复。每天或每周固定发生。
2. 步骤稳定。输入到输出的路径基本不变。
3. 规则清晰。分类、抽取、格式转换有明确标准。
4. 需要一致性。同一类任务希望得到相近结果。
5. 需要追溯。要能查到每次执行的时间、输入、输出和失败原因。
6. 需要交接。任务由多人或多系统参与。
7. 错误可容忍或有兜底。失败可以重试或转人工。

## 1.6 工作流不是"更高级的对话"

一个常见误解是把多个 Prompt 串起来就叫工作流。区别在于：

- Prompt 链：仍然由人逐步触发，步骤之间靠人工传递结果。
- 工作流：由系统触发和推进，步骤之间自动传递状态，失败有处理机制。

如果每一步仍需人手动复制粘贴，那还是对话，只是拆成了几段。工作流的价值在于自动化推进和可监控，而不是把 Prompt 写得更长。

## 1.7 升级的判断方法

可以先记录一周内的高频任务，对每项回答四个问题：

1. 每周发生几次？
2. 步骤是否每次相同？
3. 错误是否会造成严重后果？
4. 是否需要留痕？

发生频率高、步骤稳定、错误可兜底、需要留痕的任务，优先改造成工作流。频率低、每次不同、需要判断的任务，继续用对话。

## 1.8 小结

- 对话由人发起、步骤不固定、无状态记录，适合探索与判断。
- 工作流由事件触发、步骤固定、有状态与日志，适合重复与批量任务。
- 高频、步骤稳定、规则清晰、需要一致性与追溯的任务，适合改造成工作流。
- Prompt 链不等于工作流，后者需要自动推进、状态传递和失败处理。
- 判断方法是统计频率、步骤稳定性、错误后果和留痕需求。
