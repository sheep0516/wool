# 错误处理、日志与重试

本节说明工作流失败时如何处理、记录什么、何时重试、何时转人工。

## 5.1 常见错误类型

| 类型 | 表现 | 处理方向 |
|---|---|---|
| 触发失败 | 定时未执行、事件未收到 | 检查触发器配置与权限 |
| 节点失败 | 接口报错、模型调用失败 | 重试或降级 |
| 数据格式错误 | 字段缺失、类型不符 | 校验并拒绝进入下游 |
| 超时 | 长时间无响应 | 重试或跳过 |
| 限流 | 返回频率限制错误 | 退避等待 |
| 部分成功 | 批量中部分条目失败 | 记录失败项，单独重跑 |
| 逻辑错误 | 流程跑通但结果不对 | 检查规则与提示词 |

最后一类最隐蔽：没有报错，但输出错误。仅靠运行状态无法发现，需要结果校验。

## 5.2 日志记录

每一步至少记录：

| 字段 | 内容 |
|---|---|
| 时间 | 开始与结束 |
| 流程与步骤 | 名称、版本 |
| 输入 | 关键字段，敏感信息脱敏 |
| 输出 | 结果摘要或完整结果 |
| 耗时 | 用于发现慢步骤 |
| 状态 | 成功、失败、跳过 |
| 错误 | 错误码与信息 |
| 重试 | 次数与原因 |
| 关联标识 | 同一次执行的所有步骤使用同一 trace id |

日志要能回答三个问题：这次执行做了什么、在哪一步失败、失败时的输入是什么。

## 5.3 重试策略

1. 只重试可恢复错误。超时、限流可以重试；参数错误、权限不足重试无意义。
2. 设置上限。同一节点最多重试 2 到 3 次。
3. 使用退避。间隔逐次增加，避免持续冲击上游。
4. 保证幂等。重试前检查是否已经执行成功，尤其是写操作。
5. 区分读写。读操作可自由重试，写操作必须先确认状态。
6. 记录失败项。批量任务中，只重跑失败条目，不要整批重来。

## 5.4 告警

1. 设置阈值。连续失败次数、失败率、超时次数超过阈值时告警。
2. 分级。单次失败记录即可，连续失败才通知。
3. 降噪。同一原因在短时间内合并为一条告警。
4. 明确责任。告警发给能处理的人，而不是全体成员。
5. 包含上下文。告警中附上流程名、步骤、错误、trace id 和重试记录。
6. 有恢复通知。问题解决后发送恢复消息，避免长期挂着未处理告警。

## 5.5 人工接管

以下情况应转人工：

- 连续重试仍失败。
- 写入或对外操作失败，状态不确定。
- 结果校验不通过，但流程显示成功。
- 涉及金额、权限、发布等高风险操作。
- 输入格式超出预设范围，无法自动处理。

接管方式：

- 暂停流程，保留当前状态。
- 提供失败项清单和已处理项清单。
- 支持从失败步骤重跑，而不是从头开始。
- 提供手动补偿操作，例如重新发送、撤销、修正数据。

## 5.6 常见错误

1. 没有日志，失败后无法定位。
2. 对所有错误统一重试，造成重复副作用。
3. 写操作超时后直接重试，导致重复提交。
4. 告警过多，最终无人查看。
5. 流程显示成功，但结果错误，没有结果校验。
6. 失败后只能从头重跑，浪费已完成的步骤。
7. 没有 trace id，无法把一次执行的多个步骤关联起来。

## 5.7 小结

- 错误分触发、节点、格式、超时、限流、部分成功和逻辑错误，逻辑错误最隐蔽。
- 日志要记录时间、输入、输出、耗时、状态、错误、重试和 trace id。
- 重试只针对可恢复错误，设上限、用退避、保证幂等、区分读写。
- 告警要设阈值、分级、降噪、明确责任、包含上下文并提供恢复通知。
- 连续失败、状态不确定、结果校验失败、高风险操作应转人工。
- 人工接管要能从中断处重跑，并提供失败项与已处理项清单。
