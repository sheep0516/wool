# 笔记目录与命名

结论：目录固定为「库 → 章 → 篇」三层，文件名用短词加数字前缀，一级标题负责表达完整主题。目录和文件名一旦被链接引用就成了接口，改动的代价由引用数量决定，所以命名要在落笔前想清楚，而不是事后整理。

## 一、三层结构够用

- 库：一个长期主题，如「Markdown 入门」「操作系统」。
- 章：库内的一组相关文章，控制在 5–8 篇。
- 篇：一个 `.md` 文件，一个主题。

超过三层，侧边栏要折叠两次才能看到文章，检索时还多一层猜测；少于三层，几十篇平铺在一层，排序和浏览都会失效。层级含义写进文件夹名，不靠记忆：`mdrumrn-Markdown/05-第五章 长期维护/21-笔记目录与命名.md` 已经是「库、章、篇」的完整表达。

## 二、数字前缀排序的利与弊

| 方面 | 利 | 弊 |
| --- | --- | --- |
| 顺序 | 按学习或阅读顺序排列 | 中间插入新篇要把后文全部重编号 |
| 浏览 | 一眼看出章节归属 | 数字占用前缀，检索时干扰关键词 |
| 链接 | 与路径一一对应，可预测 | 改名即改路径，旧链接全部失效 |
| 迁移 | 复制到任何工具都保持顺序 | 排序只反映写作顺序，不反映重要性 |

结论：章节目录用两位数字前缀，定下后尽量不动；文章文件名也带前缀，但接受跳号，例如 21 与 23 之间补 22。不要为了连号去重命名已发布文件，连号的审美价值远低于链接失效的代价。

## 三、文件名的规则

- 短：控制在 20 字以内，一眼看完。
- 能检索：用正文里会出现的词，如「表格」「锚点」，不用「杂记」「待整理」。
- 不用空格：空格在 URL 里会被编码成 `%20`，命令行里还要加引号。
- 不用特殊符号：`/ \ : * ? " < > |` 多数系统不允许，或需要转义。
- 大小写统一：全小写英文或纯中文，避免 `Note` 与 `note` 并存。
- 不加版本后缀：不写「最终版」「新版」「v2」，版本交给 Git 管理。

日期前缀只适合按时间累积的内容：日记、周报、会议记录、日志。知识型文章按主题组织，日期前缀只会让同主题的文章散落在各处。

文件名定下后，想补充含义就在正文里写，不要靠改名表达新理解。改名是最后手段。

## 四、标题与文件名分工

文件名是地址，标题是内容。

| 位置 | 职责 | 示例 |
| --- | --- | --- |
| 文件名 | 唯一、短、可检索、可排序 | `22-模板与片段.md` |
| 一级标题 | 完整表达主题，可带副标题 | `# 模板与片段：把重复排版变成一次配置` |

两者不要求逐字一致，但不能差异到无法对应。判断方式：去掉序号与标点后，文件名应当是标题的缩写。标题可以长，文件名必须短。

## 五、一个文件只讲一个主题

混合两个主题会带来三个后果：目录里无法判断该点哪篇；站内链接只能指向整篇，读者还得自己找段落；日后拆分时，链接和收藏一起失效。

判断标准很简单：标题里出现「与」「和」「及」，多半可以拆。真正该合并的只有总览页和索引页。拆分时保留原主题的核心内容，另立新篇承接独立部分，原篇只留一段指向说明。

## 六、索引页与改名的成本

索引页就是手写的目录，列出本章文章的顺序、一句话说明和状态，作用是给不熟悉结构的人一条阅读路径。维护方式有两种：

- 手动列表：每加一篇补一行，成本低，但容易漏。
- 自动生成：部分编辑器与静态站点支持按目录生成列表，省事，但顺序完全依赖文件名。

示例目录树：

```text
mdrumrn-Markdown/
├── _meta.md
├── 01-第一章 认识 Markdown/
│   ├── 01-Markdown是什么.md
│   └── 02-适用场景与局限.md
├── 05-第五章 长期维护/
│   ├── 21-笔记目录与命名.md
│   ├── 22-模板与片段.md
│   └── 23-常见问题排查.md
└── assets/
```

改名的成本来自引用：站内链接、浏览器收藏、外部引用、静态站点生成的 URL 都以文件名为准。一次改名要同步所有指向它的链接，漏一个就是 404。三条经验：

- 发布前随便改，越早越省事。
- 发布后只做必要改名，改完立即全文搜索旧文件名。
- 章节目录一旦稳定就别动，它的影响面比单篇文章大得多。

## 检查清单

- 目录不超过三层，库、章、篇职责清晰
- 章节目录带两位数字前缀，且不再随意调整
- 文件名 20 字以内，无空格与特殊符号
- 文件名使用的词能在正文里搜到
- 一级标题表达完整主题，可与文件名对应
- 一个文件只讲一个主题，标题无「与」「和」并列
- 索引页与实际文章一致
- 发布后没有非必要改名，改名已同步所有链接
