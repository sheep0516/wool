# 模板与片段：把重复排版变成一次配置

结论：只有当一类文档反复出现、且每次都要重新想结构时，才值得做模板。模板固定骨架，内容仍要逐项填写；片段负责小段重复，模板负责整篇结构，两者分开存放、分开维护。

## 一、四类文档值得做模板

| 文档 | 固定部分 | 每次要填 |
| --- | --- | --- |
| 读书笔记 | 书名、作者、结论、摘录区、判断区 | 具体观点、页码 |
| 会议记录 | 时间、参会人、议题、结论、待办 | 讨论内容、负责人 |
| 周报 | 本周完成、进行中、风险、下周计划 | 具体事项与数据 |
| 文章骨架 | 标题、结论段、分节、检查清单 | 论证与示例 |

判断标准三条：一年会写十次以上；结构比内容稳定；漏掉某一节会明显降低可用性。只写一次的东西做模板是负担，因为模板本身也要维护。

模板写得太细会变成填空题，写得太粗又等于没写。折中办法是只固定日后会被检索的栏目，例如结论、待办、日期，其余留给正文自由发挥。

## 二、固定部分与占位符

固定部分是每次都要出现的栏目名和提示语；占位符是只改一处就能替换的记号。

- 用 `〔日期〕`、`〔对象〕`、`〔负责人〕` 这类全角方括号包裹，正文里极少出现，替换时不会误伤。
- 不用 `TODO`、`xxx`、`<>`：第一个容易残留，后两个与 Markdown 语法冲突。
- 占位符只放真正会变的信息，栏目名直接写死。
- 全篇统一一种记法，不要混用 `{{}}` 与 `[]`。

占位符的价值在于可搜索：写完搜索 `〔`，就能确认有没有漏填。

## 三、编辑器里的两种实现

| 方式 | 作用范围 | 典型工具 | 限制 |
| --- | --- | --- | --- |
| 片段 | 插入一小段固定文本 | 部分编辑器支持，如 VS Code snippets | 只插入，不生成整篇结构 |
| 模板 | 新建文件时套用整篇骨架 | 部分编辑器支持，如 Typora 模板、Obsidian 模板插件 | 路径与语法各不相同 |

VS Code 的片段是 JSON 配置，放在用户目录或项目下的片段文件里；Typora 的模板是 `.md` 文件，新建时从模板目录复制；Obsidian 的模板功能通常由社区插件提供，需要指定模板文件夹。三者的配置互不通用，但模板文件本身是纯 Markdown，换工具时直接复制即可。

选择依据是重复的粒度：重复的是整篇结构就用模板，重复的只是几行固定文字就用片段。

一个最小片段示例：

```json
{
  "读书笔记": {
    "prefix": "book",
    "body": [
      "# 〔书名〕",
      "",
      "- 作者：〔作者〕",
      "- 读完日期：〔日期〕",
      "",
      "## 一句话结论",
      "",
      "## 关键摘录",
      "",
      "## 我的判断"
    ],
    "description": "读书笔记骨架"
  }
}
```

## 四、模板放哪、怎么命名

- 集中放在一个目录，例如 `_templates/`，不要散落在各章。
- 文件名加统一前缀，如 `tpl-读书笔记.md`、`tpl-会议记录.md`，按字母即可聚在一起。
- 模板开头写一行注释，说明用途与最近修改日期。
- 与正文分开存放，避免模板被索引页或静态站点当成文章发布。
- 模板目录一并纳入版本控制，改动可回溯，误删可恢复。

## 五、两个可直接复制的模板

读书笔记：

```markdown
# 〔书名〕

- 作者：〔作者〕
- 读完日期：〔日期〕
- 相关主题：〔主题〕

## 一句话结论

〔用一句话说明这本书解决了什么问题〕

## 关键摘录

> 〔原文摘录〕（第 〔页码〕 页）

## 我的判断

- 认同：
- 存疑：
- 可执行：
```

会议记录：

```markdown
# 〔会议主题〕会议记录

- 时间：〔日期〕 〔时间段〕
- 参会人：〔参会人〕
- 记录人：〔记录人〕

## 议题

1. 〔议题一〕
2. 〔议题二〕

## 结论

- 〔决定一〕

## 待办

- [ ] 〔事项〕 —— 〔负责人〕，〔截止日期〕
```

## 六、模板维护与使用后检查

模板越多越难记，最后真正用的往往只有两三个。维护规则：

- 只保留一年内真正用过的模板。
- 每季度看一次，合并重复的，删掉没用的。
- 改模板只改结构，不动已经写完的正文。
- 保证占位符可被搜索，这是检查是否漏填的唯一低成本手段。

套用模板后仍需检查：

- 所有 `〔〕` 都已替换，没有残留。
- 只有一级 H1，分节从 H2 开始。
- 列表、表格前后有空行。
- 日期格式统一，如 `2026-11-23`。
- 不适用的栏目整节删除，而不是留一个空标题。
- 任务列表的负责人与截止日期都填了。

## 检查清单

- 模板只覆盖一年十次以上、结构稳定的文档
- 占位符统一使用全角方括号
- 片段与模板分开存放，命名带统一前缀
- 模板目录不被当成正文发布
- 每季度清理一次，只留常用模板
- 套用后全文搜索占位符，确认无残留
- 不适用栏目已整节删除，未留空标题
- 日期、负责人、截止时间填写完整
