# 适用场景与局限

Markdown 适合以文字为主、需要版本管理和跨工具读取的文档，不适合需要精确版面控制、复杂表格或多人批注流转的正式文件。判断标准不是「好不好用」，而是文档要把重心放在内容还是版面上。

## 一、适合的场景

- 技术笔记：命令、配置、代码片段能直接写进文本，行内代码和代码块只加少量符号。
- 项目 README：GitHub 和 GitLab 默认渲染 `README.md`，仓库首页就是文档首页。
- 博客与静态站点：多数静态站点生成器以 `.md` 为源文件，写完由工具转成网页。
- 论文草稿与长文：结构清晰，可先用它写骨架，再用 Pandoc 一类的工具转成 LaTeX 或 Word 排版。
- 会议记录：标题加列表加待办，几分钟写完，改动可追溯。
- 个人知识库：文件即条目，靠目录和文件名组织，不依赖数据库。
- 变更记录与接口说明：`CHANGELOG.md` 按版本追加，diff 能看出每次改了什么。

一份可直接复用的正文模板，标题和各节标题按需补上：

```markdown
时间：2026-11-23　议题：需求评审

结论：方案 B 通过，方案 A 暂缓。

待办：

- [ ] 补充接口文档
- [ ] 确认排期
```

其中 `- [ ]` 是 GFM 扩展的任务列表，部分渲染器不认，会原样显示方括号。

## 二、不适合的场景

- 精细印刷排版：封面、页眉页脚、分栏、图文绕排、精确字号和行距，Markdown 一律做不到。
- 复杂表格：合并单元格、跨页表头、单元格内换行与富文本，原生语法都没有。
- 多人批注流转：批注、修订痕迹、按人追踪的修改记录，是 Word 的长项。
- 强样式要求的正式文档：合同、标书、对外报告通常要求固定模板和版式，交 Word 或 PDF 更稳妥。
- 图片为主的排版：画册、海报、宣传单不属于文本格式能处理的范围。

这些场景的共性是需要控制像素级的呈现，或者需要围绕版面做人工审阅，而 Markdown 只传递结构。还有一个隐性代价：同一份文件在不同平台观感不同，交付前无法保证对方看到的样子。

## 三、三种方案对比

| 维度 | Markdown | Word | 在线协作文档 |
| --- | --- | --- | --- |
| 文件形态 | 纯文本 `.md` | 二进制 `.docx` | 云端对象，通常可导出 |
| 排版能力 | 弱，靠渲染器 | 强，精确到毫米 | 中，受模板限制 |
| 版本管理 | Git 友好，按行 diff | 差 | 平台内历史，难脱离平台 |
| 多人协作 | 靠 Git 或评论工具 | 靠修订和批注 | 实时协同，最强 |
| 离线可用 | 完全可用 | 完全可用 | 依赖网络和账号 |
| 长期存档 | 最好，不依赖软件 | 中，依赖兼容软件 | 差，绑定服务商 |

在线协作文档指飞书文档、腾讯文档、Google Docs 一类，各家能力不同，表中只描述共性。

## 四、标准与方言

Markdown 最初由 John Gruber 提出，早期语法描述并不严格，导致各家实现有出入。目前要区分三层：

- CommonMark：把核心语法写成明确规范，标题、列表、引用、代码、链接等基础能力以它为准。
- GFM：GitHub 在 CommonMark 之上增加表格、任务列表、删除线、自动链接，是使用最广的方言。
- 工具私有语法：Obsidian 的双链 `[[笔记名]]` 和标注语法，Typora 的下标上标，各站点生成器的短代码，只在对应工具内有效。

写作原则：核心内容只用 CommonMark，扩展语法只用来增强，不把关键信息放进只有某个工具才认的语法里。即使同为 GFM，细节也有出入：表格对齐写法、列表缩进层级的容错程度，各工具并不完全一致。

## 五、跨平台的降级

换一个渲染器，扩展语法常常直接失效，表现为原始符号暴露在正文里：

- Obsidian 的 `[[双链]]` 在 GitHub 上显示为方括号原文，不生成跳转。
- 任务列表在部分老渲染器里显示成 `- [ ]` 原文。
- 脚注在不支持的平台会原样显示 `[^1]`。
- 数学公式 `$...$` 只有支持 MathJax 或 KaTeX 的渲染器才显示。
- 内嵌 HTML 可能被平台的安全策略过滤掉。
- 带中文或空格的链接不做编码，部分平台会截断地址。

降级不会丢字，但会破坏可读性。所以在多人、多工具使用的知识库里，宁可少用扩展。

## 六、怎么选

按三个问题依次判断：

1. 需要精确排版吗？需要就选 Word 或 LaTeX，Markdown 只做草稿。
2. 需要多人实时协作吗？需要就在线协作文档；开发者团队用 Git 加 Markdown 也能协作。
3. 需要长期存档、十年后还能打开吗？选纯文本，Markdown 优先。

三个问题都指向「文字为主、结构清晰、长期保存」时，Markdown 是默认选择；只要有一个强需求落在排版或流程上，就换专用工具。两者也能组合：Markdown 写内容，导出后进 Word 定稿。

团队使用时，把这几个判断写进仓库的贡献指南，比每次口头约定更稳定。

## 速查

- 适合：技术笔记、README、博客、草稿、会议记录、知识库。
- 不适合：精细印刷、复杂表格、批注流转、固定版式公文。
- CommonMark 是基础标准，GFM 是最常用的扩展。
- 私有语法换平台就失效，关键信息别放进去。
- 选择看三点：排版精度、协作方式、存档年限。
- 可以组合：Markdown 写，Word 定稿。
