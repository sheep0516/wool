# Markdown 是什么：给纯文本加排版约定

Markdown 是一种用少量符号标注文本结构的纯文本格式：`.md` 文件在记事本里就是普通文字，在支持它的编辑器里则显示成带标题、列表和表格的排版结果。它不保存样式，只保存结构意图。

## 一、定义：用少量符号标记结构

一份 Markdown 文档只有两种成分：普通文字，和夹在文字里的标记符号。`#` 开头的行是标题，`-` 开头的行是列表项，被 `**` 包住的文字是加粗。符号只声明「这段内容是什么」，不声明「它应该长什么样」。

文件本身是 UTF-8 编码的文本，任何文本编辑器都能打开。解析规则由标准定义，目前最通用的是 CommonMark；GitHub 在它之上增加了表格、任务列表、删除线等能力，称为 GitHub 风格 Markdown（GFM）。两者大部分重合，差异集中在扩展语法上。

渲染流程可以概括为三步：读取源文本，按规则解析出标题、列表等结构，再交给界面绘制样式。所以 Markdown 本身不定义字体和字号，只定义层级与从属关系。

## 二、源文件与渲染结果

同一份 `.md` 源文件，在 Typora、VS Code 预览和 GitHub 网页里显示出的字体、颜色、行距都不一样。变的只是渲染器，源文件一个字都没动。下面是一段完整示例：

```markdown
这是正文段落，包含 `行内代码` 和 **加粗文字**。

- 第一项
- 第二项

| 名称 | 用途 |
| --- | --- |
| 表格 | 对比数据 |

> 引用块用来放提示。
```

渲染后，第一行仍是普通段落，正文本来就不需要符号；`-` 开头的两行变成无序列表，竖线围成的部分变成两列表格，`>` 开头的行变成左侧带竖线的引用块。把第一行改成 `#` 开头的标题，它就会变成一级标题，机制完全相同：符号决定结构，结构决定显示。同一份文件，GitHub 用网页主题，Typora 用桌面主题，结构一致、风格不同。

## 三、最常用的符号

| 符号 | 作用 | 说明 |
| --- | --- | --- |
| `#` | 标题 | 一到六个 `#` 对应一到六级标题 |
| `**文字**` | 加粗 | 标准语法，星号前后不留空格 |
| `*文字*` | 斜体 | 标准语法 |
| `` `代码` `` | 行内代码 | 反引号包裹，用于命令和变量名 |
| `- ` | 无序列表 | 行首一个短横线加一个空格 |
| `1. ` | 有序列表 | 数字加点加空格 |
| `>` | 引用 | 行首一个尖括号 |
| `[文字](网址)` | 链接 | 方括号放文字，圆括号放地址 |
| `![说明](地址)` | 图片 | 比链接多一个感叹号 |
| 表格 | 竖线分隔 | GFM 扩展，不属于 CommonMark 核心 |

## 四、为什么纯文本能长期存活

- 可读：去掉渲染，符号也不妨碍阅读，最坏情况只是多看到几个井号和星号。
- 可版本管理：文本按行存储，Git 能给出精确到行的差异，冲突可以手动解决。
- 不绑定软件：不依赖某家公司的私有格式，十年后仍能用记事本打开。
- 易被工具处理：脚本、静态站点生成器、笔记软件都能直接读写。
- 体积小：同样一篇长文，`.md` 通常只有几十 KB，Word 文档往往大一个量级。
- 易于检索和批处理：`grep`、正则表达式和脚本都能直接对文本操作，不必先解析专有格式。

这几点共同决定了一件事：文档的价值可以放在文字本身，而不放在某个软件的渲染能力上。代价是它不保证精确的呈现，换一个渲染器就要接受外观变化。

## 五、与 Word 的核心区别

| 维度 | Markdown | Word（.docx） |
| --- | --- | --- |
| 存储形式 | 纯文本 | 压缩的二进制包 |
| 样式来源 | 渲染器决定 | 文件内嵌样式 |
| 版本对比 | 按行 diff，清晰 | 二进制，无法逐行对比 |
| 跨工具打开 | 任何文本编辑器 | 需要兼容的办公软件 |
| 精确排版 | 弱 | 强，可控制到毫米 |
| 内容与样式 | 分离 | 混在一起 |

Markdown 只描述「这是标题」，字号、字体、页边距交给渲染器；Word 把内容和样式一起存进文件，所以能精确控制版面，代价是文件不再是人类可读的文本。Word 也支持样式表和格式刷，理论上能分离内容与样式，但文件本身仍是二进制包，版本管理和跨工具打开依然困难。需要精确版式时，先写 Markdown，再导出到排版工具定稿，是常见的折中做法。

## 六、常见误解

- 不是编程语言。它没有变量、逻辑和运算，只是一套排版约定，写错了最多显示难看，不会报错。
- 不是 HTML 的替代品。Markdown 表达不了任意布局，需要精细控制时仍要写 HTML 或 CSS；渲染器最终也是把它转成 HTML 再显示。
- 不是「必须加符号才可读」。不加任何符号的纯文字也是合法 Markdown，符号只在需要区分结构时出现。
- 不是所有平台都认同一套语法。表格、脚注、任务列表在不同工具里写法可能不同，换平台前先确认渲染器支持什么。

## 速查

- Markdown 等于纯文本加少量结构符号，不含样式。
- `.md` 是 UTF-8 文本，任何编辑器可打开。
- `#` 标题，`-` 列表，`**` 加粗，反引号是行内代码。
- 同一份源文件在不同渲染器里外观不同。
- CommonMark 是通用标准，GFM 是 GitHub 的扩展。
- 纯文本的优势：可读、可 diff、不绑定软件。
- Word 存二进制加样式，Markdown 存文本加结构。
- 不加符号也能读，加了符号才便于机器解析。
