# HTML 混排与数学公式

Markdown 的排版能力有硬上限：居中、强制换行、折叠、合并单元格只能借助 HTML；数学公式则依赖 `$...$` 与 `$$...$$` 的数学扩展。两者都不是 CommonMark 核心语法，写之前要确认渲染器是否放行，发布后必须在目标平台实际看一遍效果。

## 一、什么时候需要 HTML

纯 Markdown 做不到、又确实需要的排版，才值得引入 HTML：

- 居中：封面标题、图片说明、结尾落款。
- 强制换行：段落内部的换行，两个空格加回车的写法常被编辑器自动清理。
- 折叠块：把长日志、附录收起来，正文保持干净。
- 表格合并：Markdown 表格不支持跨行跨列，复杂表格只能手写 `<table>`。
- 特殊样式：按键提示、上下标、高亮，Markdown 没有对应语法。

能用 Markdown 表达的，就不要写 HTML。HTML 片段在导出、复制到别的平台时最容易损坏。

## 二、常用标签与属性

| 标签 | 作用 | 典型写法 | 兼容性 |
| --- | --- | --- | --- |
| `<br>` | 强制换行 | 行尾写 `<br>` | 几乎所有渲染器 |
| `<center>` | 居中 | 包裹一段文字 | 多数可用，HTML5 已废弃 |
| `<div align="center">` | 居中 | 替代 `<center>` 的写法 | GitHub 与多数平台 |
| `<details>` | 折叠容器 | 配 `<summary>` 作标题 | GitHub、Obsidian、Typora |
| `<kbd>` | 按键样式 | `<kbd>Ctrl</kbd>` | GitHub、多数平台 |
| `<sup>`、`<sub>` | 上标、下标 | `<sup>2</sup>` | 多数平台 |
| `<mark>` | 高亮底色 | `<mark>重点</mark>` | 视平台而定 |

折叠块的完整写法如下，可以直接复制：

```html
<details>
<summary>点击展开：构建日志</summary>

- 第一步：安装依赖
- 第二步：执行编译

</details>
```

`<summary>` 与正文之间留一个空行，GitHub 才会继续把里面的内容按 Markdown 解析；不留空行时，里面的列表会原样显示成文本。`<br>` 写成 `<br/>` 或 `<br />` 也能被识别，严格 XHTML 环境要求后两种。

## 三、安全与兼容问题

托管平台会对 HTML 做清洗，下面这些基本一律无效：

- `<script>`、`<iframe>`、事件属性如 `onclick`，直接被删除，不会执行。
- `style="..."` 属性在 GitHub 被剔除，Typora 预览里可能生效，导出后往往丢失。
- 自定义 `<div class="...">` 缺少对应样式表，视觉上没有变化。
- 块的 HTML 前后要空行，否则它可能被并入上一段，当成行内内容处理。

另一个容易忽略的点是闭合标签后的空行：块级 HTML 结束时也要空一行，否则后续段落可能被吞进这个块。CommonMark 规定 HTML 块内部不再解析 Markdown，所以往 `<div>` 里塞列表、表格往往不会生效；GitHub 对 `<details>` 做了额外处理，其它平台不一定有这个例外。

安全规则决定了 HTML 只能用于结构，不能用于精细样式。需要稳定视觉效果时，用图片或目标平台的原生组件，而不是堆 CSS。引入 HTML 后源文件的可读性会下降，团队协作时要在提交说明里写清原因，避免后人误删。

## 四、公式写法与 LaTeX 常用符号

行内公式用单个美元符号包裹，独立公式用两个美元符号各占一行：

```markdown
质能方程是 $E = mc^2$，它在低速下退化为经典力学。

$$
\sum_{i=1}^{n} x_i = \frac{n(n+1)}{2}
$$
```

`$` 要紧贴公式，前后不留空格。写成 `$ x $` 时不少渲染器不认，会当成普通文本。独立公式的 `$$` 最好单独成行，公式内部换行用两个反斜杠。

| 需求 | 写法 | 说明 |
| --- | --- | --- |
| 上标 | `x^2`、`x^{10}` | 多字符要加花括号 |
| 下标 | `a_i`、`a_{ij}` | 同上 |
| 分数 | `\frac{a}{b}` | 大型分数用 `\dfrac` |
| 求和 | `\sum_{i=1}^{n}` | 上下限写在 `_` 与 `^` |
| 积分 | `\int_0^1` | 定积分上下限 |
| 根号 | `\sqrt{x}`、`\sqrt[3]{x}` | 方括号写次数 |
| 希腊字母 | `\alpha`、`\beta`、`\Omega` | 大写首字母变大写 |
| 矩阵 | `\begin{pmatrix} a & b \\ c & d \end{pmatrix}` | 行内换行用双反斜杠 |
| 自适应括号 | `\left( \frac{a}{b} \right)` | 括号随内容增高 |
| 文本 | `\text{其中 } x > 0` | 公式里插中文用 `\text` |

矩阵示例可以直接粘贴验证：

```markdown
$$
A = \begin{pmatrix}
1 & 2 \\
3 & 4
\end{pmatrix}
$$
```

## 五、各平台公式支持差异与降级

| 环境 | 行内公式 | 独立公式 | 说明 |
| --- | --- | --- | --- |
| Typora | 支持 | 支持 | 设置里需开启内联公式 |
| Obsidian | 支持 | 支持 | 内置 MathJax |
| GitHub | 支持 | 支持 | 无需设置，货币符号需转义 |
| VS Code 预览 | 需扩展 | 需扩展 | 内置预览不渲染 |
| Hugo、Jekyll | 取决于主题 | 同左 | 需引入 KaTeX 或 MathJax |
| 微信公众号 | 否 | 否 | 只能转成图片 |

不同引擎支持的命令集也有差别：KaTeX 追求渲染速度，宏包较少，个别冷门命令不支持；MathJax 更完整，但加载慢。某个公式在一个平台正常、换到另一个平台报红，先查引擎文档再换写法。公式里出现中文必须放进 `\text{}`，直接写汉字在多数引擎里会报错或显示异常，中文与符号之间也要留空格。

公式不渲染时的处理顺序：先看是不是 `$` 两侧多了空格；再看平台是否只认独立公式，把行内公式拆成块级；仍不行就渲染成图片嵌入。GitHub 上写金额时，`$5` 到 `$10` 这种成对美元符号可能被误判为公式，需要写成 `\$5` 到 `\$10`。跨平台时统一用 `$`，不要用 Pandoc 也支持的 `\(...\)`，后者在 GitHub 上不生效。

## 速查

- 居中用 `<div align="center">`，`<center>` 已废弃。
- 段内换行用 `<br>`，比「两个空格加回车」可靠。
- 折叠用 `<details>` 配 `<summary>`，内部 Markdown 前留空行。
- `<script>`、`style`、事件属性会被平台过滤。
- 行内公式 `$E=mc^2$`，美元符号要贴住公式。
- 独立公式用 `$$` 各自独占一行。
- 多字符上下标要加花括号，如 `x^{10}`。
- 公式不渲染就拆成块级或转成图片。
