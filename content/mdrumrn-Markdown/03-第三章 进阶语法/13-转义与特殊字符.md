# 转义与特殊字符：让符号保持原样

要显示一个会被 Markdown 解析的符号，在它前面加反斜杠 `\` 即可；而一旦把它放进行内代码或代码块，就不用再转义，反斜杠会原样出现。真正需要处理的，通常是行首的井号、减号、数字加点和正文里成对出现的星号、下划线。

## 一、会被当作标记的字符清单

CommonMark 规定，反斜杠可以转义所有 ASCII 标点符号。日常会撞上的只是其中一部分：

| 字符 | 默认被解析成什么 | 什么时候需要转义 |
| --- | --- | --- |
| 反斜杠 | 转义符本身 | 正文要显示一个反斜杠 |
| 反引号 | 行内代码的边界 | 正文要一个反引号 |
| 星号 | 强调、无序列表 | 算式、通配符、乘法 |
| 下划线 | 强调 | 变量名、文件名 |
| 花括号 | 部分扩展的占位符 | 模板语法、代码片段 |
| 方括号 | 链接、脚注、任务列表 | 数组下标、引用标记 |
| 圆括号 | 链接地址的一部分 | 函数调用、补充说明 |
| 井号 | 标题标记 | 行首的编号或话题标签 |
| 加号、减号 | 无序列表 | 行首的正负号、增减号 |
| 点 | 有序列表 | 行首的「1.」这类编号 |
| 感叹号 | 图片标记的前缀 | 与方括号连用的情况 |
| 竖线 | 表格的列分隔 | 单元格内要一条竖线 |
| 大于号 | 引用块 | 行首的比较或箭头 |

名单之外的非 ASCII 字符没有转义语义。`\中` 不会变成「中」的特殊形式，反斜杠会原样输出，所以别对汉字加反斜杠。

## 二、用反斜杠转义

反斜杠只对紧邻的下一个字符生效，两个反斜杠 `\\` 表示一个真正的反斜杠。下面是可直接复制的写法：

````markdown
\*这不是斜体\*
价格是 3 \* 4 = 12 元
行首的 \# 号、\- 减号、2024\. 这样的编号都能还原
路径写作 C:\\Users\\me
````

渲染效果：星号、井号、减号、点号全部按原样显示；最后一行显示为 `C:\Users\me`。注意反斜杠只写在需要保留的符号前，多写会多出一个反斜杠。

## 三、行内代码与代码块天然免疫

代码环境里没有 Markdown 语法，所有符号都是字面量，包括反斜杠本身。要在正文里展示 `a * b`、`snake_case`、`# 注释`，最省事的办法是包成行内代码，而不是逐个加反斜杠：

````markdown
`a * b * c` 会原样显示，`snake_case` 也一样。

```python
print("# 这行不会被当成标题")
x = a * b  # 星号也不会变成斜体
```
````

渲染效果：第一行两个片段都是等宽字体；代码块里井号和星号都保持原样。代码块内的内容连 HTML 实体也不会被解码，所见即所得。

## 四、HTML 实体：另一种写法

实体来自 HTML，也被 CommonMark 收进规范：渲染时解码成对应字符。GitHub、Typora 与浏览器预览都会解码；反过来，把文件当纯文本查看时，看到的是 `&lt;` 这几个字符。所以实体适合两种情况：符号本身是 HTML 标签的开头，直接写会被吞掉；或某些表格、HTML 片段里反斜杠不生效。

## 五、中文全角标点不需要转义

`，。！？：；、（）【】「」——` 这些全角符号不在 ASCII 标点范围内，Markdown 不会把它们当成标记，加反斜杠反而会多打印一个反斜杠。中文写作里唯一要留意的是全角标点紧贴强调标记时的边界判定，稳妥做法是把标点放到 `**` 外面，而不是给它加转义。

## 六、高频踩坑与写法对照

- 下划线在英文变量名里：`user_name_list` 这类词内下划线多数渲染器不触发强调，但 `_a_`、`_b_` 这种以下划线开头结尾的写法很容易翻车。变量名、文件名统一用反引号包住最稳。
- 星号在算式里：`2*3*4` 会把中间的 3 渲染成斜体，两个星号一起消失。写成 `2 \* 3 \* 4`，或直接换成乘号 `×`。
- 行首井号：正文以井号开头就是标题，想显示井号必须写 `\#`。
- 行首数字加点：`1. ` 开头会自动变成有序列表，`2024. 年度总结` 尤其容易中招，写成 `2024\.` 即可。
- 表格里的竖线：单元格内容含竖线时，即使包在行内代码里也可能被切断，需要写成反斜杠加竖线。

把最容易出错的情况整理成一张对照表：

| 你想显示的内容 | 直接写会怎样 | 正确写法 | 渲染结果 |
| --- | --- | --- | --- |
| 带星号的文字 | 变成斜体 | `\*重点\*` | 星号保留 |
| 变量名 | 可能被当成斜体 | 包成行内代码 | 等宽显示 |
| 行首井号 | 整行变成标题 | `\# 结论` | 井号加文字 |
| 行首编号 | 变成有序列表 | `2024\. 总结` | 编号加文字 |
| 一对圆括号 | 一般无碍 | 保持原样或加反斜杠 | 原样显示 |
| 路径反斜杠 | 被当作转义符 | 写成两个反斜杠 | 一个反斜杠 |
| 小于号 | 可能被当 HTML 开头 | 用 `&lt;` | 小于号 |

对照表的用法是：先判断符号会不会被解析，再看它是否在行首或成对出现，最后决定加反斜杠、包行内代码还是换 HTML 实体。三者的优先级是行内代码、反斜杠、实体。

## 速查

- 反斜杠只转义紧邻的下一个 ASCII 标点。
- 代码块和行内代码里不用转义，符号全是字面量。
- 行首井号、减号、数字加点是最常见的误判来源。
- 算式里的星号要转义，或改用乘号。
- 词内下划线不保险，变量名用反引号包住。
- 小于号、与号可用 `&lt;`、`&amp;` 表示。
- 全角中文标点不需要转义。
- 优先级：行内代码高于反斜杠，反斜杠高于 HTML 实体。
