# 表格：对齐、转义与复杂内容

Markdown 表格由表头行、分隔行、数据行三部分组成，缺一不可。分隔行决定对齐方式，每行列数必须严格一致，单元格里的竖线必须转义成 `\|`。表格只适合放短内容，长段落和嵌套列表应当拆出去。

## 一、基本语法与分隔行

````markdown
| 语法 | 用途 |
| --- | --- |
| `#` | 一级标题 |
| `>` | 引用块 |
| `-` | 无序列表 |
````

第二行是分隔行，每个单元格至少三个连字符。CommonMark 规范只要求一个 `-`，但多数编辑器与渲染器要求三个，写三个最保险。首尾竖线可以省略，但省略后不同渲染器对边界空白的处理不一致，建议保留。

表格前后必须各留一个空行。不留空行时，部分解析器会把上一段文字吞进表格，或者干脆不识别表格，直接把竖线当普通字符输出。

表格也不能随意缩进。放在列表项里时，整张表要跟着列表内容缩进，否则会被解析成列表外的块；放在引用块里，每一行都要以 `>` 开头，漏一行就会把表格截断。

## 二、三种对齐

| 写法 | 效果 |
| --- | --- |
| `:---` | 左对齐 |
| `:---:` | 居中 |
| `---:` | 右对齐 |

对齐写在分隔行里，作用于整列。不写冒号时默认左对齐。阿拉伯数字列用右对齐便于比较位数，短标签列可以居中，长文本列左对齐。对齐属于 GFM 扩展，严格的 CommonMark 渲染器会忽略冒号，只保证表格结构。对齐只影响显示，不改变数据类型；数字仍按文本处理，需要计算就得换成真正的表格工具。

## 三、竖线转义与单元格内容

单元格里想显示竖线字符，必须写成 `\|`，否则会被当成分列符，把后续内容挤到下一列。

| 需求 | 写法 |
| --- | --- |
| 显示竖线字符 | 竖线前加一个反斜杠 |
| 单元格内换行 | 写 `<br>` |
| 单元格内代码 | 用反引号包住 |
| 单元格内强调 | 用 `**加粗**` |

`<br>` 是 HTML 标签，依赖渲染器放行内联 HTML。GitHub、Typora、VS Code 预览都支持；关掉 HTML 渲染的静态站点会把它当纯文本显示，所以不要把关键信息藏在换行里。单元格默认不换行，超长内容会把整列撑开，出现横向滚动。表格宽度由渲染器按内容分配，Markdown 没有列宽语法，想在 GitHub 上控制列宽只能靠缩短文字，或换用 HTML 表格的 `width` 属性。

````markdown
| 命令 | 说明 |
| --- | --- |
| `git status` | 查看工作区状态 |
| `a\|b` | 含竖线的写法 |
````

## 四、列数与表头

数据行的单元格数量必须与表头一致。少写或多写一个竖线，多数渲染器会补齐或截断而不报错，结果是内容整体错位，比直接报错更难排查。表头单元格不能留空，空表头在部分工具里会让整张表不渲染。从 Excel 或表格软件粘贴时，先确认分隔符是竖线而不是制表符；直接粘贴常会得到一列用制表符隔开的文本，需要借助编辑器插件或手工替换才能转成 Markdown 表格。

## 五、不适用场景与替代方案

表格适合放键值对、对照关系、参数说明这类短内容。不适合放长段落、嵌套列表、多行代码，因为单元格宽度会被内容撑爆，标准语法也不支持块级元素。

替代方案按优先级排序：

- 内容有层级关系时，拆成小标题加列表。
- 每项需要一段解释时，用定义列表式的「加粗标签 + 段落」。
- 确实需要合并单元格或嵌代码块时，才用 HTML `<table>`，代价是可读性下降且必须保证标签闭合。

拆成列表后每项还能各自加链接、加代码块，维护成本比 HTML 表格低得多。

````markdown
- 参数 `timeout`
  - 类型：整数
  - 默认值：30
  - 说明：请求超时时间，单位为秒
````

## 六、常见错误

| 错误 | 后果 |
| --- | --- |
| 漏写分隔行 | 整张表按普通段落输出 |
| 数据行比表头多一列 | 多出的内容被丢弃或推到表外 |
| 表头为空 | 部分渲染器不生成表格 |
| 单元格内竖线未转义 | 列被意外拆分 |
| 表格前无空行 | 与上文粘连，可能不识别 |
| 单元格里塞长段落 | 列宽失控，阅读困难 |

## 速查

- 结构：表头行 + 分隔行 + 数据行。
- 分隔行每格至少三个连字符。
- 对齐：`:---` 左、`:---:` 中、`---:` 右。
- 竖线写 `\|`，换行写 `<br>`。
- 列数必须与表头一致，表头不能空。
- 表格前后各留一个空行。
- 长段落和嵌套列表不要放进表格。
- 复杂表格改用列表或 HTML 表格。
