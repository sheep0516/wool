# 列表：无序、有序与嵌套

无序列表用 `-`、`*`、`+` 开头，有序列表用 `1.` 开头，两者都能嵌套。决定嵌套成败的是行首缩进：同一篇里统一用 2 个或 4 个空格，不要混用。

## 一、无序列表的三种符号

`-`、`*`、`+` 等价，都能生成圆点列表。混用不会报错，但同一层级来回换符号毫无意义，建议全篇只用 `-`。符号后面必须有一个空格。

```markdown
- 采集需求
- 设计接口
- 联调测试
```

渲染效果：三行显示为同一组项目符号列表。写成 `-采集需求`（符号后无空格）会被当成普通段落，短横线原样显示。

## 二、有序列表与起始编号

有序列表写成 `1.` 加空格。起始编号有意义：从 `3.` 开始，第一条就显示 3。后续条目的编号多数渲染器会自动递增，实际写几并不影响结果。

```markdown
1. 准备环境
1. 安装依赖
1. 运行测试
```

渲染效果：显示为 1、2、3。这种"全写 1."的写法在 CommonMark 系渲染器里合法且实用，插入或删除条目时不必重排。但旧式解析器可能按字面显示成 1、1、1，跨平台文档还是顺序编号更保险。

## 三、嵌套的缩进规则

子列表要缩进到父项正文的起始列。父项是 `- ` 两个字符，子项缩进 2 个空格即可；父项写 `1. ` 三个字符，子项至少缩进 3 个空格，习惯上统一取 4。关键是同级对齐、逐层递增。

```markdown
- 前端
  - 组件库
  - 状态管理
- 后端
  - 接口层
```

渲染效果：`组件库`、`状态管理` 缩进到 `前端` 之下，`接口层` 同理。若某行缩进 3 个空格、下一行缩进 2 个，就会出现断列，后面的条目被顶回上一级。

| 写法 | 结果 |
| --- | --- |
| 子项缩进 2 空格（父项 `- `） | 正确嵌套 |
| 子项缩进 4 空格 | 正确嵌套，同样可用 |
| 同级缩进不一致 | 断列，层级错乱 |
| 子项缩进 1 空格 | 不构成嵌套 |

## 四、列表项里放多段文字、代码与图片

列表项内要放第二个段落，需要空一行，并把续写内容缩进到与该列表项正文对齐。放代码块时，围栏也要缩进到对齐位置，否则会跳出列表。放图片写成 `- ![替代文字](图片路径)`，图片会作为该列表项的内容缩进显示。

````markdown
- 部署步骤

  先确认配置，再执行脚本。

  ```bash
  ./deploy.sh
  ```
- 回滚方案：见 `rollback.md`
````

渲染效果：第一项包含独立的一段说明和一个代码块，都归属于该列表项；第二项是普通条目。代码围栏若不缩进，就会脱出列表成为独立代码块。

## 五、列表与段落、标题的搭配

列表前要空一行。紧贴上一段文字时，部分解析器会把列表吞进段落，圆点不渲染。列表也不宜代替章节标题：小节用 `##`，条目才用列表。嵌套超过三层，读者就难以追踪层级，该拆成小节。任务列表写成 `- [ ]` 与 `- [x]`，属于 GFM 扩展，只适合勾选清单，不适合承载正文。

## 六、常见错误

- 缩进不一致：同一层有的 2 空格、有的 4 空格，直接断列。
- 列表紧贴段落：前面没空行，圆点不渲染。
- `*` 与 `-` 混用：风格混乱，导出主题可能对不上。
- 用列表代替标题：大纲缺失，无法跳转。
- 嵌套四五层：层级过深，应改成分节。

## 速查

- 无序列表用 `-`，全篇统一。
- 符号后必须有一个空格。
- 有序列表从几开始就显示几。
- 后续编号可全写 `1.`，部分平台不认。
- 子项缩进 2 或 4 个空格，同级对齐。
- 列表项内的续段、代码块要缩进对齐。
- 列表前留一个空行。
- 任务列表 `- [ ]` 是 GFM 扩展。
