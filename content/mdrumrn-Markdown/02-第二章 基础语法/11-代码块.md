# 代码块：围栏、语言标注与行内代码

围栏代码块用三个反引号开始、三个反引号结束，起始行紧跟语言名。围栏长度必须大于内容里出现的连续反引号，否则代码会被提前截断。行内代码只适合单行短片段，多行一律用围栏。

## 一、围栏与语言标注

````markdown
```python
def parse(text):
    return text.strip()
```
````

语言名写在起始围栏之后。语言标注有两个作用：一是语法高亮，渲染器按语言着色；二是部分工具据此提供复制按钮、行号或文件名。写错语言名不会报错，只是失去高亮，看起来像普通文本块。

语言名用小写最稳。`javascript` 与 `js`、`shell` 与 `bash` 在主流渲染器里都能识别；`c++` 和 `cpp` 一般也通用，但写成 `C++` 这类带大写的形式，个别渲染器匹配不上。GitHub 走 linguist 词法库，识别的别名最多；Typora 与 VS Code 依赖各自的语法表，冷门语言容易认不出。起始围栏后面除了语言名还可以写额外信息，例如 `title="app.py"`，这是部分渲染器的扩展能力，标准没有定义，换工具会被忽略或原样显示。

## 二、围栏长度与嵌套

如果代码内容本身包含三个连续反引号（比如在写 Markdown 教程），外层围栏必须用四个反引号：

`````markdown
````markdown
```python
print("hi")
```
````
`````

规则是：结束围栏的反引号数量不能少于开始围栏，且内容中任何连续反引号串都不能达到开始围栏的长度。四个包三个是最常用的组合，内容含四个反引号时就用五个，以此类推。换成波浪号 `~~~` 也能做围栏，效果相同，在需要展示大量反引号时更省心。

## 三、行内代码与代码块的边界

| 场景 | 选择 |
| --- | --- |
| 单个命令、变量名、函数名 | 行内代码 |
| 多行脚本、配置片段 | 围栏代码块 |
| 需要语法高亮 | 围栏代码块 |
| 展示 Markdown 源码 | 四个反引号围栏 |
| 内容含四个反引号 | 五个反引号围栏 |

行内代码用单个反引号，例如 `git status`、`npm run build`。它只保护单行，不做高亮，也不能保留换行。需要在行内代码里显示反引号字符时，用两个反引号包裹，并在内容首尾各留一个空格，渲染结果才会正确。

## 四、闭合与缩进

围栏必须成对出现。少写结束围栏，后面所有内容直到文末都会被当成代码，这是最常见的整篇排版事故。

在列表里写代码块，围栏要跟着列表内容缩进：

````markdown
- 第一步：

  ```bash
  npm install
  ```

- 第二步：

  ```bash
  npm run dev
  ```
````

缩进不足时，代码块会跳出列表，变成与列表平级的块，破坏层级。缩进量要与列表项内容对齐，通常是两个或四个空格；渲染器对「刚好够」的缩进比较宽容，但少一格就可能失效。

在引用块里嵌代码块同理，围栏要跟在 `>` 之后并与引用内容对齐，`>` 只写在围栏行的开头。混用 Tab 和空格缩进时，不同编辑器按不同宽度展开 Tab，最容易出现「本地正常、推送后错位」。

## 五、代码块内不解析 Markdown

围栏内的 `#`、`*`、`[链接](url)`、HTML 标签都按原样输出，不会被解析。这是写教程、贴日志、展示 Markdown 源码的唯一可靠方式。行内代码同样不解析内部语法，但它只覆盖单行，且不会参与语法高亮。

代码块首尾的空行会被保留，贴日志时注意不要带入多余空行；行尾空格在部分编辑器保存时被自动清除，如果内容依赖行尾空格（例如 Markdown 的硬换行示例），展示结果会悄悄变化。

## 六、缩进式代码块

用四个空格或一个 Tab 开头的老写法仍被 CommonMark 支持，但缺陷明显：无法标注语言、没有高亮、与列表缩进容易冲突、复制出来的空白字符可能被编辑器改写。新写内容一律用围栏代码块，缩进式只在对齐旧文档时才需要认识。

## 速查

- 围栏用三个反引号，起始行写语言名。
- 语言名小写最稳，写错只会失去高亮。
- 内容含三个反引号时外层用四个，含四个就用五个。
- 行内代码用于单行短片段，多行用围栏。
- 围栏必须闭合，漏写会让后续全文变成代码。
- 列表中的代码块要缩进到列表内容层级。
- 围栏内不解析 Markdown，适合展示源码。
- 缩进式代码块已被围栏取代，不要再用。
