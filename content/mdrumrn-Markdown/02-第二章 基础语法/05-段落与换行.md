# 段落与换行：空行才是分段

Markdown 分段只认空行：两个文字块之间留一个空行，就是两段；不留空行，敲再多次回车也还是同一段，换行会被合并并补成一个空格。确实需要段内强制换行时，在行尾敲两个空格，或者在行尾加一个反斜杠。

## 一、空行分段是核心规则

分段这件事在 Markdown 里只由空行决定，缩进、回车次数、行尾符号的优先级都不如它。

```markdown
第一段的第一行
第一段的第二行

第二段
```

渲染效果：前两行合并成一段，断行处变成一个空格；空行之后另起一段，两段之间出现由样式表控制的段间距。

## 二、单个回车会被合并成同一段

遵循 CommonMark 的渲染器把段内换行当作软换行，处理方式是把换行替换成一个空格。中文段落这样处理，断行处会多出一个显眼的间隙，看起来像误打的空格。聊天软件和部分博客里"按回车就换行"是平台自己改的行为，许多编辑器还能单独开关（Typora 有"保留单行换行"，Obsidian 有严格换行选项），这些都不是 Markdown 标准。

## 三、强制换行的两种写法

行尾两个空格后回车，或行尾一个反斜杠后回车，都会产生硬换行，输出一个 `<br>`。

```markdown
第一行（行尾两个空格）  
第二行
第三行（行尾一个反斜杠）\
第四行
```

渲染效果：四行各自独立成行，行间没有段间距。第一行末尾那两个空格肉眼不可见，编辑器通常有"显示空白字符"的开关可以核对。

| 写法 | 结果 | 说明 |
| --- | --- | --- |
| 单回车 | 合并为一段 | 断行处补一个空格 |
| 行尾两个空格 | 硬换行 | 最通用 |
| 行尾反斜杠 | 硬换行 | CommonMark 支持，更直观 |
| 行尾一个空格 | 无效 | 不足以触发换行 |
| 段落间一个空行 | 分段 | 标准做法 |

两种硬换行写法并非所有工具都完整支持，行尾空格又常被编辑器自动清除，相比之下反斜杠更稳。

## 四、硬换行该用和不该用

适合用的地方：地址、诗句、歌词，以及必须逐行对齐的清单。不该用的地方：正文断句。用硬换行去控制排版，换个窗口宽度就错位，段落语义也被拆碎，屏幕阅读器可能把每一行当成独立片段。正文交给渲染器自动折行即可。

## 五、缩进与空行数量

首行缩进不要手动打空格。Markdown 不认段首缩进，行首四个空格反倒会被解析成缩进式代码块，文字变成等宽字体。段间距由渲染器的样式表决定，连续敲三个空行和一个空行效果相同，都只分出一段。想调间距只能改主题样式，在文档里堆空行没有用。

## 六、常见错误

- 用空格缩进想分段：变成代码块或直接失效。
- 连续多个空行想拉大间距：没有任何额外效果。
- 依赖单回车换行：被合并，还多吞一个空格。
- 行尾留空格实现换行：被编辑器清理后失效。
- 正文到处硬换行：换个宽度就错位。

## 速查

- 分段靠空行，不靠回车。
- 单回车是软换行，合并并补空格。
- 硬换行：行尾两个空格，或行尾反斜杠。
- 行尾一个空格不生效。
- 段首不要手动缩进。
- 行首四空格会变成代码块。
- 多个空行不增加段间距。
- 段间距由样式表控制。
