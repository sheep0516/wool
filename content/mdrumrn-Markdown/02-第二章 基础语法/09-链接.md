# 链接：行内、引用式与锚点

Markdown 链接只有一种核心形式：`[显示文字](目标地址)`。行内写法覆盖九成场景；同一地址反复出现时才改用引用式；页内跳转依赖标题自动生成的锚点，而锚点规则各家渲染器并不一致，必须实测确认。

## 一、行内链接与 title

方括号写显示文字，圆括号写地址，两者之间不留空格。地址后可以再跟一个用引号包住的 title，鼠标悬停时显示。

````markdown
[示例站点](https://example.com)
[示例站点](https://example.com "鼠标悬停时显示的说明")
````

title 在移动端基本没有展示机会，触屏没有悬停状态，不要用它承载必要信息。地址里如果含空格，要么写成 `%20`，要么整体用尖括号包住，即 `[文档](<我的 笔记.md>)`；尖括号写法属于 CommonMark 规范，但部分老旧渲染器不认。

| 写法 | 实际效果 |
| --- | --- |
| `[文字](地址)` | 正常链接 |
| `[文字](地址 "说明")` | 链接，悬停出现说明 |
| `[文字] (地址)` | 不是链接，原样输出 |
| `[文字]（地址）` | 全角括号不识别，原样输出 |

## 二、引用式链接

结构是正文写 `[文字][id]`，文末任意位置写 `[id]: 地址`。定义不会渲染成可见内容，只用于查找。

````markdown
参考 [CommonMark 规范][spec] 与 [GitHub 文档][gh]。

[spec]: https://commonmark.org
[gh]: https://docs.github.com
````

适用场景很明确：同一个长地址在文中出现三次以上，或者正文里塞满长 URL 影响阅读。只出现一次时用引用式反而多一步跳转，得不偿失。id 不区分大小写；`[文字][]` 表示 id 与文字相同，`[文字]` 是简写形式，靠文字本身去匹配定义，容易误伤，不建议在长文里用。

## 三、自动链接与裸网址

标准写法是尖括号包住完整地址，例如 `<https://example.com>`，渲染成可点击链接，显示文字就是地址本身。

裸网址不加尖括号能否自动变成链接，属于扩展而非标准。GitHub、GitLab、Typora、Obsidian 默认开启 GFM 的 autolink 扩展，裸网址会被识别；严格的 CommonMark 渲染器不会。更麻烦的是网址后面紧跟中文标点，识别边界容易出错，比如 `https://example.com。` 可能把句号吃进地址。需要确定性时一律加尖括号。

## 四、页内锚点

跳转到本文某个标题，写 `[跳到引用式](#二引用式链接)`。锚点由标题文本生成，通用规则是：英文转小写、空格替换为 `-`、去掉大部分标点。

各平台在细节上差异明显：

- GitHub：中文原样保留，标点去掉，空格变 `-`；同名标题第二次出现时追加 `-1`。
- Typora、VS Code 预览：直接按标题文本生成，中文一般可直接用。
- VuePress、GitBook 一类静态站点：走 slugify，中文可能被转成拼音或被直接丢弃。

结论是不要手写推测。在目标平台的预览里点一次标题旁的链接图标，复制真实地址最稳。标题里带英文括号、斜杠、冒号时最容易失败。

## 五、相对路径与中文文件名

相对路径以当前 Markdown 文件所在目录为基准，不是仓库根目录。

| 目标位置 | 写法 |
| --- | --- |
| 同目录文件 | `文件.md` |
| 上级目录文件 | `../文件.md` |
| 子目录文件 | `子目录/文件.md` |
| 仓库根目录文件 | 按层级写多个 `../` |

链接到仓库内另一个 Markdown 文件，GitHub 上写 `.md` 或省略扩展名都能跳到渲染后的页面；本地编辑器则要求写全扩展名，否则找不到文件。

中文文件名在语法上完全合法，但 URL 中空格必须编码为 `%20`。中文本身在 GitHub、Typora 里通常可以直接写，浏览器会自动编码；跨平台分发时更稳妥的做法是文件名只用英文、数字和连字符。

## 六、常见错误

| 错误写法 | 问题 |
| --- | --- |
| `[文字](地址` | 右括号缺失，整段不渲染成链接 |
| `[文字](我的 笔记.md)` | 地址含空格未编码，链接在空格处截断 |
| `[文字]（地址）` | 用了全角括号，不被识别 |
| `![文字](地址)` | 多了感叹号，变成图片而非链接 |
| `[文字](C:\notes\a.md)` | 本机绝对路径，换机即失效 |

## 速查

- 行内链接：`[文字](地址)`，可选 title 写在地址后。
- 引用式：正文 `[文字][id]`，文末 `[id]: 地址`。
- 同一地址复用三次以上再考虑引用式。
- 自动链接用 `<https://example.com>`，裸网址依赖平台扩展。
- 页内锚点 `#标题`，规则各平台不同，以预览结果为准。
- 相对路径相对当前文件，不是仓库根目录。
- 空格编码为 `%20`，中文文件名尽量改成英文。
- 多一个 `!` 就从链接变成图片。
