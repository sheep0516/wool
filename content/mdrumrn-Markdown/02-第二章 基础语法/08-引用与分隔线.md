# 引用与分隔线：旁注与停顿

`>` 是引用，每一行行首都得写；`---` 单独成行、前后留空行时才是分隔线。`---` 紧跟在一行文字下面时，会被解析成二级标题的下划线，这是最常见的误用。

## 一、`>` 的基本写法

引用以 `>` 开头，后面跟一个空格更整齐。每续一行都要写 `>`，否则第二行会掉回正文。

```markdown
> 引用要标明出处。
> 这是同一段引用的第二行。
```

渲染效果：两行合为一个引用块，左侧出现竖线，文字通常带灰色或斜体。写成 `>` 后不加空格也能识别，但加空格读源码时更清楚。

## 二、多行、空行与嵌套引用

跨段引用时，用单独一行 `>` 表示引用内部的空行；一旦出现完全空白的行，引用块就结束。嵌套引用叠加符号，每多一层多一个 `>`。

```markdown
> 第一段。
>
> 第二段，仍在同一个引用块内。
>> 这是嵌套一层。
```

渲染效果：前后两段同属一个引用块，`>>` 那一行缩进更深，形成二级引用。引用块里还能继续放列表和代码，前提是每行都带 `>`。

## 三、引用块里放列表、代码与标题

引用块内部可以容纳其他块级元素，规则是让每一行都保留 `>` 前缀，缩进按嵌套后的位置重新计算。

````markdown
> ### 注意事项
>
> - 先备份
> - 再执行
>
> ```text
> 示例输出
> ```
````

渲染效果：引用块内出现一个三级标题和一个两项列表，代码块同样带着竖线。外侧的 `>` 要一直保留，漏一行就会把内容甩出引用。

## 四、引用块的典型用途

引用适合三种场景：摘录他人原文并注明出处；给正文加一段旁注，不打断主线；放提示或警告。GitHub 的 `> [!NOTE]` 之类告警语法是平台扩展，换到别的工具就退化成普通引用，重要提示最好同时写成文字，别只靠图标。

## 五、`---` 分隔线与标题下划线歧义

`---` 独占一行就是分隔线。它还有一种用法：紧跟在文字行下方且中间没有空行时，会被当作 Setext 标题的下划线，把上面那行变成二级标题。

```markdown
上一段文字
---

上一段文字

---
```

渲染效果：第一种写法把"上一段文字"渲染成二级标题，分隔线消失；第二种写法因为加了空行，文字仍是普通段落，下面才是分隔线。规避方法很简单：`---` 前后各留一个空行。

`***` 与 `___` 也能作分隔线，且不会触发这个歧义。另外，文档开头连续的 `---` 还可能被当成 YAML 前言的分隔符，把它写在前言区之外更安全。

| 写法 | 结果 |
| --- | --- |
| 文字行紧接 `---` | 文字变成二级标题 |
| 空行 + `---` + 空行 | 正常分隔线 |
| `***` 单独成行 | 分隔线，无歧义 |
| `---` 出现在文首 | 可能被当作前言分隔符 |

## 六、分隔线的节制与错误对照

分隔线是视觉停顿，用来切换话题或分隔附录。一章里出现三五条，读者的节奏就被打断。真正需要切分时，标题比横线更有效，因为标题能进大纲、能跳转。

| 错误写法 | 问题 | 正确做法 |
| --- | --- | --- |
| 文字下紧贴 `---` | 变成二级标题 | 前后加空行 |
| 每个小节后都加 `---` | 滥用，节奏破碎 | 用标题分节 |
| 引用续行漏写 `>` | 脱离引用块 | 每行都写 `>` |
| 用引用代替警告框 | 换个工具即失效 | 同时写明文字 |
| 用 `---` 代替标题 | 大纲缺失 | 用 `##` 分节 |

## 速查

- 引用用 `>`，每行都要写。
- 引用内空行写 `>`，完全空行则结束。
- 嵌套引用叠加 `>>`。
- 引用块内可放列表、代码、标题。
- 分隔线 `---` 必须单独成行。
- `---` 前后留空行，避免变标题。
- `***` 作分隔线没有歧义。
- 分隔线是停顿，别当分节用。
