# 标题：用 # 建立文档骨架

Markdown 的标题只由两样东西决定：行首的 `#` 个数，以及 `#` 后面那一个空格。`#` 的数量等于标题级别，一个 `#` 是一级，六个 `#` 是六级。一篇文章只用一个一级标题，其余层级逐级递进，渲染器才能据此生成稳定的大纲与页内锚点。

## 一、六级标题的写法

`#` 到 `######` 对应一级到六级标题，级别越高字号越大、字重越重。多数主题里一级标题约为正文的两倍，五、六级在实践中几乎没有存在感。日常笔记用二级、三级两层通常就够。

| 写法 | 级别 | 常见用途 |
| --- | --- | --- |
| `# 标题` | 一级 | 全篇标题，一篇只出现一次 |
| `## 标题` | 二级 | 大章节 |
| `### 标题` | 三级 | 章节下的小节 |
| `#### 标题` | 四级 | 长文档的细则分组 |
| `##### 标题` | 五级 | 极少用到 |
| `###### 标题` | 六级 | 基本没有使用场景 |

超过六个 `#` 不再继续升格，多数解析器会把整行当作普通文本，或者只按六级处理。

## 二、`#` 后面必须有一个空格

`#` 与标题文字之间要留一个半角空格，这是最常被漏掉的一步。少了空格，遵循 CommonMark 的解析器会把整行当成普通段落，`#` 原样显示。

```markdown
# 项目说明
## 一、安装
### 1. 环境要求
```

渲染效果：三行依次成为一级、二级、三级标题，字号逐级递减，大纲里呈现三层结构。

```markdown
#项目说明
##安装步骤

# 项目说明 #
```

渲染效果：前两行是普通段落，`#` 直接显示；第三行末尾的 `#` 是可选闭合写法，会被忽略，该行仍是一级标题。可以记住一句话：开头必须有空格，结尾的 `#` 可有可无。

## 三、一个一级标题，层级不跳级

一级标题是文档的根，全篇只应出现一次。正文的章节从二级开始，向下逐层嵌套。跳级不会报错，但大纲会出现断层，自动目录和阅读器导航都会显得错乱。

```markdown
# 部署手册
## 一、准备环境
### 1. 依赖清单
#### 版本约束
```

渲染效果：四层结构完整，大纲可以逐层折叠；如果把 `#### 版本约束` 直接挂在二级下面、跳过三级，导航里就会留下一个明显的空档。

## 四、标题是大纲与锚点的来源

渲染器会把每个标题收进文档大纲，并据标题文字生成页内锚点。GitHub、Typora、Obsidian、VS Code 预览都支持点击大纲跳转，很多静态站点生成器还会据此生成侧边目录。标题文字会进入 URL 片段，改动标题往往等于改动锚点，外部指向该位置的旧链接随之失效。所以标题要当作对外接口来取，别随手改。

## 五、标题与加粗不是一回事

加粗只是视觉上更重，语义上仍是正文；标题是结构，会进入大纲、参与锚点生成。用加粗冒充标题，在编辑器里看着相似，导出的目录却是空的，屏幕阅读器也无法识别层级。

| 目的 | 正确做法 | 错误做法 |
| --- | --- | --- |
| 表示一个章节 | `## 安装步骤` | `**安装步骤**` |
| 强调某个词 | `**注意**` | `## 注意` |
| 出现在自动目录里 | 使用标题 | 加粗或放大字号 |

## 六、标题怎么写，常见错误有哪些

标题宜短、能扫描，尽量写成名词短语。整句式的标题在目录里会被截断，也不利于快速定位。标题只负责指路，解释放到正文第一段。

- `#标题`：漏了空格，不渲染。
- `**标题**`：只有视觉加粗，没有结构。
- 通篇都是 `##`：大纲扁平，看不出从属关系。
- 标题写成完整句子：目录冗长，扫描成本高。
- 二级直接跳到四级：大纲断层，导航错乱。

## 速查

- 行首 1 到 6 个 `#`，数量即级别。
- `#` 与文字之间必须有一个空格。
- 一篇文章只用一个一级标题。
- 层级从二级开始，不跳级。
- 标题自动成为大纲与页内锚点的来源。
- 标题要短、可扫描，优先名词短语。
- 加粗是视觉，标题是结构。
- 改标题可能让旧锚点链接失效。
