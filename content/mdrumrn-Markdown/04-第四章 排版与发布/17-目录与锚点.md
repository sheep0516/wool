# 目录与锚点：给长文档装导航

Markdown 没有单独的目录语法。目录和页内跳转都建立在标题上：渲染器先为每个标题生成一个 id，再用 `[文字](#id)` 指过去。标题文字、层级和稳定性决定导航是否可用；改标题常常等于改锚点，旧链接会静默失效。

## 一、锚点从哪里来

渲染器读到 `## 安装步骤` 时，会把标题文字转成一个 id 挂在对应的 HTML 标题标签上，浏览器据此定位。常见转换规则是：转小写、连续空白变一个连字符、去掉大部分标点、保留字母、数字、下划线、连字符和中文。

| 标题写法 | 常见生成的 id | 说明 |
| --- | --- | --- |
| `## 安装步骤` | `安装步骤` | 中文原样保留 |
| `## 一、安装步骤` | `一安装步骤` | 顿号被去掉 |
| `## Install on Windows` | `install-on-windows` | 空格变连字符，转小写 |
| `## API v2.0` | `api-v20` | 小数点被去掉 |
| `## C++ 与 C#` | `c-与-c` | 加号、井号被去掉 |

不同渲染器的细节不完全一致，比如 GitHub、Typora、VS Code 预览对重复标题的编号方式可能不同，但对“小写、空格转连字符、去标点、保留中文”这套主干规则基本一致。重复标题通常会追加 `-1`、`-2` 区分，第一处不加后缀。

## 二、中文标题的锚点长什么样

中文不需要音译，也不转拼音，标题里的汉字会直接进入 id。`## 安装步骤` 的锚点就是 `安装步骤`，链接写成 `[安装步骤](#安装步骤)`。在编辑器和本地预览里点击即可跳转。

放进浏览器地址栏后，中文会被百分号编码，形如 `#%E5%AE%89%E8%A3%85%E6%AD%A5%E9%AA%A4`。这是浏览器的正常行为，编码前后指向同一个位置。真正的坑是二次编码：把已经编码的 `%E5` 再交给编码器，会变成 `%25E5`，链接就失效。复制地址时直接复制浏览器给出的结果，不要手写编码。

另一个坑是大小写和标点。id 已经转成小写，`#Install` 匹配不到 `install`；标题里的顿号、冒号、括号都被删掉，手写锚点时要按“删掉标点后的文字”来写，而不是照抄标题。最稳妥的做法是先在预览里点一次，确认能跳，再贴进目录。

## 三、手写目录

手写目录就是一组指向页内 id 的链接，通常放在正文开头或单独的“目录”小节。链接文字可以自由改写，括号里的目标必须是 `#` 加 id。

```markdown
## 目录

- [一、安装](#一安装)
- [二、配置](#二配置)
- [三、排错](#三排错)

## 一、安装
```

渲染效果：三条链接分别跳到后面的三个二级标题。锚点只写 `#` 和 id，不加文件路径；链接文字与标题不一致也能跳，但建议保持一致，方便维护。

手写目录的代价是同步：增删一节就要改一次目录。文档超过十节、又经常改动时，优先用自动方式。

## 四、让编辑器生成目录

多数 Markdown 编辑器都有大纲面板，按标题层级列出一棵树，点击即跳转。它不写进正文，只在侧边栏显示，适合写作时定位。

需要把目录写进正文时，有三类做法：

- Typora 支持用 `[TOC]` 占位，导出或预览时按标题生成目录。
- VS Code 需要安装插件，例如 Markdown All in One 提供生成目录的命令；也可以用通用工具 markdown-toc 按标题批量生成。
- Obsidian 主要依赖大纲面板，正文目录可通过插件生成。

自动生成的目录按当前标题文字生成锚点，标题一改，重新生成即可。不要在同一篇里混用手写目录和自动目录，否则会出现两套入口、两套锚点。部分平台不识别 `[TOC]`，会把它当普通文字显示，发布前要在目标平台确认。

## 五、链接到另一篇文档的某个标题

跨文档跳转由“路径 + `#锚点`”组成，锚点规则与页内相同。写法有两种：源文件相对路径，或站点路由。

```markdown
[配置说明](05-配置文件.md#二配置)
[配置说明](/kb/mdrumrn-Markdown/05-配置文件/#二配置)
```

渲染效果：前者按源文件相对位置寻找目标，后者直接指向站内文章地址。相对路径便于文件搬家，但依赖生成器把 `.md` 改写成页面地址；本仓库这类自建脚本不会自动改写正文里的 `.md` 链接，线上应使用站点路由。`#` 后只写 id，不写标题原文；路径用 `/`，不要用 Windows 的反斜杠。

目标标题改名、改级别、改标点，都会让 `#` 后面那段失效。页面不会报错，只会停在文首，所以跨文档链接要和服务端路由一样，按“对外接口”维护。

## 六、长文档的结构建议

- 层级不超过三级：一级是篇名，二级是大节，三级是最细的切分。需要四级时，说明该拆文件了。
- 每节可独立阅读：小节开头先给结论，不依赖上一节的代词和省略。
- 二级标题控制在 5 到 8 个：太少说明没切开，太多说明该拆篇。
- 标题短而具体：目录里能一眼扫完，不写成整句。
- 标题定稿后再广泛引用：发布过的标题当接口看待，必须改时同步更新所有指向它的链接。
- 需要永久锚点时，可在标题前插入 `<a id="install"></a>`，链接指向 `#install`；代价是多一行需要维护的 HTML。

## 检查清单

- [ ] 全篇只有一个一级标题，正文从二级开始
- [ ] 标题层级不超过三级，没有跳级
- [ ] 手写目录的每个锚点都在预览中点击验证过
- [ ] 中文锚点没有二次编码，`%25` 开头的链接已排除
- [ ] 重复标题已确认后缀编号，链接指向正确的那一处
- [ ] 跨文档链接使用 `/` 和正确路径，并带对 `#锚点`
- [ ] 自动目录与手写目录没有混用
- [ ] 标题定稿后，已检查所有指向旧标题的链接
